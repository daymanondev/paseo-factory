# paseo-factory

A verification line for coding agents: the work is judged against criteria fixed before
it starts, by running checks rather than trusting the agent's word, and every step is
recorded so it can be read back later.

## Language

### People and parties

**Agent** (or **Peer**):
The working agent (`factory-peer` provider in Paseo's `config.json`, tab titled `Peer · <Task>`, ADR 0017, ADR 0053, ADR 0054) doing the work on a Task inside its isolated Task worktree, equipped with the `agent` role slice of the Role-scoped MCP bridge (`agent_claim`, `agent_escalate_blocker`) and the `factory-claim` CLI (ADR 0016, ADR 0053). A `Peer` operates under one of four task-level **Peer dispositions** (`disposition?: "engineer" | "architect" | "reviewer" | "scout"`, defaulting to `"engineer"`, ADR 0053, ADR 0054) on the Project's single Owner-configured `worker` lane: `engineer` owns writable implementation and test changes; `scout`, `architect`, and `reviewer` are fenced read-only (`read-only-disposition-fence`), never run `git commit`, and complete `agent_claim` without `commit` (`--sha`) using disposition-specific evidence in their mandatory **6-Field Handoff** (`Outcome`, `Snapshot`, `Scope`, `Verification`, `Unknown / risk`, `Ownership`). It may make Claims; it never sets or changes a Contract. Under ADR 0029, ADR 0032, and ADR 0053 (`Contract Before Test`), it treats the Brief as a provisional map, verifies premises against the repository before writing tests or code across a boundary, challenges `Lead` immediately via `agent_escalate_blocker` (`REOPEN_REQUEST` on `foundation | dependency | lifecycle | API | ownership | verification`, `DEPENDENCY_REQUEST`, or `BLOCKED`, routed strictly to the `Lead mailbox` while keeping the `Peer` session alive for in-place reconciliation via `lead_set_contract` + `lead_repoke_agent`), implements only its bounded outcome, records decisions and assumptions in its owned `.scratch/<initiativeId>/decisions/<task>.jsonl` rather than stopping for interactive prompts, and respects Excluded / Deferred to Later Waves.
_Avoid_: worker as a name for the agent itself (the `worker` lane key in `lanes.json` and the "Worker" model picker label name the Peer's model lane only — the lane keeps its legacy name, ADR 0056), bot, separate model lanes per SLP disposition

**Owner**:
Whoever sets or ratifies the work's outcome and final acceptance — the human, or a seat the human has delegated authority to (the Supervisor as conversational delegate; the Lead for intermediate Task contracts and clean green-task acceptance under ADR 0010, with Human override always retained). Never the Agent working that Task.
_Avoid_: reviewer, user

**Supervisor**:
The Owner's conversational delegate seat for a Project (`labels: { seat: "supervisor", project: <slug> }`, tab titled `Supervisor`), rooted at the Project's directory (`cwd = <project-root>`, bound to the Project's active main Paseo `workspaceId` via a 2-step seat launch and initialized on Turn 1 with a deterministic Seat kickoff packet, ADR 0010, ADR 0015, ADR 0016, ADR 0017) rather than an external `<home>-supervisor` folder, with compaction-proof role instructions written from a single shared role-contract module (`src/roles-contract.ts`) to both `config.systemPrompt` and `<stateDir>/pi-agent/supervisor/APPEND_SYSTEM.md`, equipped with the `supervisor` slice of the Role-scoped MCP bridge (`supervisor_dispatch_lead`, `supervisor_accept_task`, `factory_status`, ADR 0016) alongside the `factory` CLI, and 100% of the Owner's slash commands and skills preserved via symlinked `~/.pi/agent/{prompts,skills}` (ADR 0013, ADR 0015) while `<project-root>/AGENTS.md` is never overwritten. It clarifies intent (`grilling`), diagnoses reported repository states via read-only inspection (`ls`, `cat package.json`, `git status`, `git log`) before immediately dispatching any required fix, dependency installation, or verification wave to the Project's Lead via `supervisor_dispatch_lead` / `factory lead dispatch` (immediately ending its turn to wait for the Lead's report, ADR 0019), receives completion summaries and escalations through the bidirectional `mailbox.jsonl` (`to: "supervisor"`, ADR 0015), relays status, verdicts and needs-human items to the Owner, accepts on the Owner's word (`accepted_by: "supervisor"`), and curates project-level rules in `AGENTS.md` / `CONTEXT.md`. Enforced by the Spool and the 3-layer `Seat write fence` (ADR 0015, ADR 0016, ADR 0019), the Supervisor never decomposes Tasks, never calls `factory contract` or `factory run`, never edits product source files or runs package-mutating or git-committing commands on `<project-root>`, never calls Paseo's native agent-management tools directly, never pushes externally, and never accepts without the Owner's word. Added in v0.0.9 (ADR 0006); scoped per Project at `cwd` in ADR 0010; made compaction-proof in ADR 0013; fenced and wired bidirectionally in ADR 0015; equipped with the Role-scoped MCP bridge, Seat kickoff packet, and 3-layer execution fence in ADR 0016; unified with Lead in the Project's main Workspace with orphan workspace sweeping in ADR 0017; equipped with the Diagnostics & Run-Verification Law and Layer-3 package-manager shims in ADR 0019. Under ADR 0029, it transmits Owner outcomes, boundaries, and verification criteria faithfully, preserving architecture freedom unless the Owner explicitly requests file-packaging constraints, and challenges architectural traps or packaging anti-patterns (such as forcing a multi-subsystem application into a single file) via `grilling` with a recommended modular alternative before dispatching unless the Owner explicitly confirms running as-is. The plugin may create a `Supervisor` seat in exactly two places — the onboarding wizard's Start and a vacant Supervisor row on the Project panel (`factory.onboarding.commit`, `factory.supervisor.start`) — through the same role-provider path as Paseo's native `Supervisor (Factory)` picker, so the seat is recognised, fenced and bound to the workspace identically; the directive, if given, is the seat's first message (ADR 0017 amended by ADR 0056). It never creates a `Lead`.
_Avoid_: manager, orchestrator, assistant (and Driver — a mechanism, not a seat)

**Lead**:
The presiding technical seat over Agents for a Project (`labels: { seat: "lead", project: <slug> }`, tab titled `Lead`, `cwd = <project-root>`, co-located inside the active `Supervisor`'s Paseo `workspaceId` but — since v0.6.1 (ADR 0057 §4) — created WITHOUT a Paseo `parent` link so archiving any Supervisor can never cascade onto the Lead (a pre-v0.6.1 still-parented Lead makes its outgoing Supervisor `released` — held un-archived until that Lead's own handoff archives it), via a 2-step seat launch and initialized on Turn 1 with a deterministic Seat kickoff packet, ADR 0010, ADR 0015, ADR 0016, ADR 0017): a standing model-backed Paseo agent on the `lead` lane (`lanes.json`, anchored by the unified role contract in `config.systemPrompt` and `<stateDir>/pi-agent/lead/APPEND_SYSTEM.md`, equipped with the `lead` slice of the Role-scoped MCP bridge — `lead_set_contract`, `lead_spawn_agent`, `lead_accept_task`, `lead_repoke_agent`, `lead_needs_human`, `lead_report_to_supervisor`, `factory_status` — alongside the `factory` CLI, receiving work through the Project's Lead mailbox, and rotatable manually or automatically via Lead handoff at the `128,000` token mark, ADR 0013, ADR 0015, ADR 0016, ADR 0047) paired with the Driver's deterministic watch/respawn/ceiling rider underneath. Since v0.6.1 (ADR 0057 §4) a Lead archived from outside the plugin is caught through the daemon's `agent.archive.after`: the binding clears, delivered-but-unacknowledged Lead mail requeues (`lead_lost`), and the next mailbox pump recreates the Lead from the on-disk handover — which carries a staleness line whenever the file predates the lost Lead's last activity, telling the successor to re-read the Ledger and repository instead of trusting old notes. The Lead reads the Seat kickoff packet and repository, splits a Supervisor directive into one or more Tasks (delivering vertical user-facing journey slices after at most 1–2 foundational setup waves rather than horizontal chains of backend-only micro-waves, writing concise `<= 2,500`-char 4-Part Briefs that state outcome, boundary contracts, exclusions, and Gate command without pre-solving internal helper signatures or mandating N unit-test files per task, and never reading implementation or framework `SKILL.md` files into its own context window, ADR 0044, ADR 0047), sets each Task's Contract around desired outcomes, regression invariants, and a Gate command that runs both the new verification and the repository's existing test/build suite (without pre-declaring file-scope handcuffs for the Peer, ADR 0028), spawns working Agents in isolated Task worktrees, judges hand-backs strictly against mechanical Gate evidence and its own direct inspection of the attested commit diff (`git show --stat "<sha>"` and bounded per-file `git diff "<sha>^" "<sha>"` without JSON-stringifying multi-file outputs inside a single REPL call, plus the proof falsification check, without running ad-hoc out-of-band shell/node scripts to invent uncontracted edge cases after a GREEN Gate, ADR 0029, ADR 0030, ADR 0044, ADR 0047), accepts clean green Tasks in every wave (`accepted_by: "lead"`, when Verdict is green and the Task is not in Needs-human, ADR 0030, ADR 0044), re-briefs or escalates stuck work (`needs_human`), and reports final landed completion or human questions back to the Supervisor via `lead_report_to_supervisor` / `factory supervisor report` (`to: "supervisor"` in `mailbox.jsonl`, ADR 0015, ADR 0016). The Lead is dispatched only by the `Supervisor`: no surface offers a Start Lead action, and a vacant Lead row only tells the Owner to ask the Supervisor (ADR 0017, ADR 0056).
_Avoid_: manager, foreman, orchestrator, "the loop" (that names the mechanism), Driver (a mechanism, not a seat), creating the Lead as a Paseo child of the Supervisor (Paseo's archive cascade then kills it), routing mail to an archived Lead

### Work and criteria

**Project**:
One Git repository supervised by the factory, identified canonically via `git rev-parse --show-toplevel --git-common-dir` as `<project-slug> = <basename>-<sha1(gitRoot).slice(0,6)>` (ADR 0010). Starting a `Supervisor` or `Lead` seat registers the Project and, on a non-Git directory, initializes a Git repository with an initial empty commit so per-Task worktrees work immediately (ADR 0024); onboarding (`factory.onboarding.inspect` / `factory.onboarding.commit`) turns a Paseo workspace folder into a Project the same way and offers `git init` only when the Owner asks (ADR 0056). Owns its isolated state directory (`<stateDir>/projects/<project-slug>/`) and its own `Factory` instance in the plugin server's per-Project registry (`factoryForProject(slug)`, ADR 0045), containing its registration (`project.json`), per-Project `Ledger` (`ledger.jsonl`), `Reports` (`report-<task>-<attempt>.md`), `Gate` logs (`gate-<task>-<attempt>.log`), per-Project settings (`project-settings.json` — the Open Design link and skill packs, ADR 0056), and `Task worktrees`, plus its standing `Supervisor` and `Lead` seats — giving each Project an independent `Task` ID namespace (`T-01`, `T-02`, ...) and isolated `seq` stream (`1..N`), with one-time automatic startup migration (`migrateRootLedgerToProjects`) splitting and compacting any legacy root `<stateDir>/ledger.jsonl` into per-Project directories and archiving the legacy root files to `<stateDir>/archive/legacy-root-<timestamp>/` (ADR 0045). If the Project's directory is later deleted on disk, the registered Project keeps its persisted identity (`missingRoot`) so it can still be purged via `Project delete` (ADR 0024).
_Avoid_: workspace (that is the working copy a Task runs in), folder, team, shared root `ledger.jsonl` across multiple Projects

**Task**:
One unit of work within a Project, identified by a filename-safe id, judged against exactly one Contract.
_Avoid_: job, ticket, lane

**Contract**:
The done-criteria for a Task, fixed before the Agent starts: one `Gate` command (mandatory for `disposition: "engineer"`, optional and defaulting to `""` for read-only dispositions `scout | architect | reviewer`, ADR 0054), optional SLP `disposition?: "engineer" | "architect" | "reviewer" | "scout"` (default `"engineer"`, ADR 0053), optional Artifact path (omitted when the Gate command and commit diff suffice and refused on read-only dispositions, ADR 0028, ADR 0054), optional `scope` (used only as an explicit opt-in when a Task is contracted to edit a root memory file `AGENTS.md`/`CLAUDE.md`/`CONTEXT.md` and forced to `[]` on read-only dispositions, never as a Station 4 red Verdict handcuff on code files, ADR 0028, ADR 0054), and optional required `skills`, rooted at a Project workspace. Setting a new Contract (`contract_set`) on an unaccepted Task opens a fresh Contract epoch, resetting the Task's Attempt counter and clearing prior `Needs-human` status, while **preserving any live bound `Peer` session in place by default (`resetPeer: false`)** so `Lead` and `Peer` can reconcile premises mid-flight via `lead_set_contract` + `lead_repoke_agent` (canceling and archiving the live `Peer` only when `resetPeer: true` is explicitly passed or when the Task is accepted/closed, ADR 0053). Lead-authored Contracts are mechanically validated at `lead_set_contract` (accepting either structured `outcome`, `invariants`, `exclusions`, `verification` fields or a `description` containing all four canonical sections: `1. Bounded Outcome`, `2. Contract Boundary & Regression Invariants`, `3. Excluded / Deferred`, and `4. Verification`; missing sections are refused with `invalid-contract`, ADR 0054), anchored just-in-time to the current Stable Checkpoint and capped at `<= 2,500` chars without pre-solving internal function/prop names from deep implementation files (ADR 0029, ADR 0032, ADR 0047, ADR 0053, ADR 0054).
_Avoid_: spec, acceptance criteria, hợp đồng (outside research notes), bare `gate`-only Contracts with empty `description` bypassed via `lead_repoke_agent`

**Workspace**:
The git working copy a Task's work lives in; the Gate runs there and the Artifact is resolved inside it. Under ADR 0010, each spawned Task runs inside its own isolated Task worktree so the Project's root checkout stays clean.
_Avoid_: repo, project dir, cwd

**Serial Wave**:
A bounded stage of a directive, normally one cohesive vertical-slice Task owning a single new interactive workflow or subsystem (real screen/UI + state/data wiring + journey test, after at most 1–2 foundational setup waves for app shell and core schema/repository seam, ADR 0044, ADR 0052). Initial roadmaps are rolling-wave outlines rather than fixed commitments: after each wave lands at a Stable Checkpoint, Lead re-evaluates actual repository complexity and splits any downstream wave that spans multiple user journeys before contracting it, without decomposing work into horizontal chains of backend-only micro-waves (`T-04c1..c6`) or standalone test-only negative-matrix sub-wave chains (`T-04d1..d6` with `src/` frozen, ADR 0044, ADR 0052). When a vertical slice hits `BLOCKED (context-ceiling)` and must split across seams (`Wave A` data/SDK seam → `Wave B` provider/UI wiring), its verification tail (`Wave C`) is capped at **at most 1 combined journey wave** covering both happy path and failure/retry recovery in one concise suite (ADR 0052). Multiple Tasks share a wave only when the existing foundation is stable and their module/file surfaces are genuinely disjoint. Each wave is accepted before the next is contracted (ADR 0029, ADR 0034, ADR 0044, ADR 0052).
_Avoid_: all-at-once decomposition, locked upfront multi-wave roadmaps, multi-subsystem mega-tasks, horizontal backend-only micro-wave chains, test-only negative-matrix sub-wave spirals

**Project ingress lock**:
The per-Project serial lock (`withProjectIngressLock`, ADR 0056) under which directive and Contract admission for one Project run strictly one after another, in submission order; a job that re-enters its own Project's lock runs inline. It replaces the retired Execution-mode lane and carries no mode.
_Avoid_: execution lane, execution mode

**Stable Checkpoint**:
The landed Project HEAD established by Acceptance of a GREEN wave; the foundation for the next wave's Contracts, Task worktrees, and in-flight `Wave Hardening` (ADR 0029, ADR 0030, ADR 0048).
_Avoid_: unaccepted green commit

**Wave Hardening**:
The Lead's in-flight workflow self-correction at a `Stable Checkpoint` boundary whenever a costly failure mechanism (RED `Gate`, `re-contract`, `Choke` denial, or recurred `context-ceiling` on a `> 1,500`-line monolith/fixture file) triggers the `Recurrence Guard` (`observed → recurred`, ADR 0048, ADR 0052). Rather than deferring workflow potholes to a passive backlog or waiting for an end-of-project ceremony, the Lead applies at most one highest-leverage fix before contracting the next `Serial Wave`, following the 3-tier hardening hierarchy: (1) mechanical `Gate` check, shared module/fixture extraction wave (when `context-ceiling` recurs `>= 2` times on a `> 1,500`-line file, ADR 0052), script, or `.worktreeinclude` update applied immediately in-flight; (2) a concise 1-line navigation pointer quoted into downstream `Contract`s for **at most 2–3 waves** before being encoded into Tier-1 structure (ADR 0052) and proposed at directive completion in the 4-line Owner ratification format for `<project-root>/AGENTS.md` or `CONTEXT.md`; (3) deprecation and mechanical replacement of any existing `AGENTS.md` prose rule that a `Peer` still violated (`no-op` pruning).
_Avoid_: backlog deferral, waiting for a manual retrospective ceremony while downstream `Peer`s repeat the same failure, adding multi-paragraph prose warnings to `AGENTS.md`, quoting the same Tier-2 prose rule across more than 3 waves without encoding it into structure

**Recurrence Guard**:
The two-strike causal filter (`observed → recurred → hardened → verified`, tracked in `<projectStateDir>/notebook.md` and capped at `<= 12` active rows via `seatworks` 3-rule graduation, ADR 0048, ADR 0052) governing when a workflow failure earns a structural change. A first occurrence is recorded as `observed` with its causal mechanism (`Cause → Effect`) and evidence (`Task` + `seq`) without adding repo-wide rules; a second occurrence of the same mechanism moves the row to `recurred` and triggers `Wave Hardening` (whose `Proposal` cites at least two distinct `seq`s); once the fix holds across subsequent waves, the row is marked `verified` and graduated via: (1) **Fold** rows sharing the same `Cause → Effect` mechanism, (2) **Verified Retirement** after `3` waves, and (3) **Stale `1x` Expiry** after `5` waves without recurrence (ADR 0052).
_Avoid_: "seen twice" (informal), one-off rule bloat from a single surprise, unverified slogan rules, unbounded append-only `Recurrence Guard` tables exceeding 12 rows

**Project notebook**:
The Lead's bounded (`<= 80` lines / `<= 4 KB` / `<= 12` `Recurrence Guard` rows) per-Project operational memory file at `<projectStateDir>/notebook.md` (`~/.paseo/plugin-state/paseo-factory/projects/<slug>/notebook.md`, ADR 0048, ADR 0049, ADR 0052), persisted in-process by the plugin single writer via the `lead_update_notebook` MCP tool and `factory notebook` CLI (so OS-sandboxed seats such as `codex` Seatbelt update it without writing `<project-root>/.scratch/notebook.md`, while `syncLegacyScratchNotebook` automatically promotes and unlinks any legacy untracked `<project-root>/.scratch/notebook.md` before `landTaskWorktree`, ADR 0052) and stored outside `<project-root>` so it never dirties the Git working tree or pollutes `Peer` (`Agent`) context windows. Contains two fixed sections — `## 1. Verification & Run Recipe` (`Worktree & Env Setup`, `Fast Slice Check`, `Full Cumulative Gate`, `Process & Port Cleanup`) and `## 2. Recurrence Guard` — and is automatically embedded into `Lead` and `Supervisor` kickoff packets (`buildSeatKickoffPacket`) so institutional run knowledge survives `128,000`-token `Lead handoff` rotations and is wiped cleanly on `Project reset`.
_Avoid_: dumping Lead orchestration rules into `<project-root>/AGENTS.md` or Peer briefs where every `Peer` pays context pressure to read them, writing `<project-root>/.scratch/notebook.md` in the Git working tree, silent bottom truncation of over-limit notebooks

**Contract epoch**:
One version of a Task's Contract and the Attempts judged against it. Re-contracting begins a new epoch; an Attempt number identifies work within that epoch.
_Avoid_: retry cycle, Task version

**Task worktree**:
The linked `git worktree` automatically allocated for a Task at Spawn under `<projectStateDir>/worktrees/<task>` on branch `factory/<task>` (rooted at the Contract's `base` commit, copying `.worktreeinclude` entries and symlinking `<project-root>/node_modules` when present, and registered in Paseo under the Project's own `projectId` with the human-readable Workspace title `Peer · <Task> — <short summary>` rather than an internal `<slug> <task>` hash, ADR 0010, ADR 0015, ADR 0017, ADR 0019). Preserved across in-place `contract_set` re-contracting of an unaccepted Task (`worktreeFor` and `liveContractFor` retain the latest unaccepted `spawn_dispatched.worktree` while it exists on disk, ADR 0019), isolates the working Agent (created with `parent: leadAgentId` and tab title `Peer · <Task>`) and Gate execution from `<project-root>`, hydrates `<project-root>/node_modules` from `<worktree>/node_modules` when `<project-root>` lacks installed dependencies, lands its `claimedCommit` back into `<project-root>`'s local branch upon Acceptance, automatically reaps any leaked test or dev-server child processes (`@embedded-postgres`, Playwright/Chromium, etc.) whose command line references `<worktree>` before removing or resetting the worktree directory (`reapWorktreeProcesses`, ADR 0044), and automatically archives both the working Agent and the temporary Paseo worktree workspace before removing the directory (ADR 0015, ADR 0019, ADR 0044). For a pre-contracted Task with no Claims in its current Contract epoch, an Acceptance recorded after that Contract advances initial allocation to current project HEAD instead of its stale base; retries with current-epoch Claims retain the contracted base (ADR 0029).
_Avoid_: clone, sandbox, shadow copy

**Workspace conflict**:
Two live Contracts whose execution Workspaces nest inside one another (`inside` / `contains`), or two live Contracts on the same Project that both explicitly declare overlapping `scope` globs. Because every Task executes in its own isolated `Task worktree` and merges through `landTaskWorktree` at Acceptance, unscoped Contracts on the same Project root never conflict at contract or spawn time (ADR 0028). Added in v0.0.5; updated in ADR 0010 and ADR 0028.
_Avoid_: scope conflict (the charted name — the real key is workspace overlap, not scope intersection), merge conflict

**Gate**:
The command named in a Contract whose exit status is the factual check of the work, executed in its own detached OS process group (`detached: true`, ADR 0016) so that when the command exits or times out, any leftover descendant child processes are reaped (`SIGTERM` → `SIGKILL` on `-pgid`) before stream closure is awaited. Mandatory for `disposition: "engineer"`; optional (defaulting to `""`) for read-only dispositions (`scout | architect | reviewer`, ADR 0054), where an empty `gate` verifies the `Task worktree` sits clean at `HEAD` and records a synthetic `green` Verdict without spawning a shell subprocess.
_Avoid_: test step, check, cổng (outside research notes), requiring dummy `echo ok` shell gates on read-only dispositions

**Artifact**:
An optional workspace-relative path inside the Workspace that, when specified on a Contract, must exist for a Verdict to be green (ADR 0028) and is refused on read-only Peer dispositions (`scout | architect | reviewer`, ADR 0054). It can never point outside the Workspace.
_Avoid_: deliverable, output file

### Judging

**Claim**:
The Agent's statement that a Task is finished (`agent_claim` / `factory-claim`), carrying a mandatory **6-Field Handoff** (`outcome: "complete" | "partial" | "blocked" | "reopen"`, `scope`, `verification`, `unknowns`, plus synthesized `ownership` and `snapshot`, ADR 0053, ADR 0054) and a commit `sha` (`commit` required for `engineer`, optional/omitted for read-only dispositions `scout | architect | reviewer`, ADR 0053, ADR 0054). A Claim is evidence of intent, never of completion. Within the current `Contract epoch`, if a completed `GREEN` `Attempt` already exists for the exact same commit `sha`, a duplicate `Claim` on that `sha` returns the existing `GREEN` `Attempt` idempotently without opening a redundant `Attempt`, re-running the `Gate`, or re-emitting duplicate `Meter` / `Lead mailbox` verdict hooks (`outcome.gate.seq <= admitted.priorSeq` in `plugin/server/spool.ts`), whereas a retry on a `sha` whose prior `Attempt` was `RED` opens a new `Attempt` below the `Attempt ceiling` (ADR 0031).
_Avoid_: "done" (for the Agent's side), report, submission, mute `{ task, commit }`-only claims without the 6-Field Handoff, duplicate `mail_queued` verdict notifications on idempotent `Claim` retries

**Attempt**:
One Claim and the Gate run it triggers. A Task may have up to three Attempts (the Attempt ceiling, ADR 0008); they are numbered and never overlap.
_Avoid_: retry, run, iteration

**Verdict**:
The factory's red/green judgment of one Attempt. Green means the Workspace sat clean at the claimed commit (or at `HEAD` on a read-only disposition without a new commit, ADR 0053, ADR 0054) both before and after the Gate, the Gate exited 0 (or was skipped on a clean read-only disposition with an empty `gate`, ADR 0054), any Contract-specified Artifact exists, and no root memory file (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`) was modified without an explicit Contract opt-in (ADR 0028). Green is evidence, not acceptance.
_Avoid_: result, status, pass/fail

**Accepted**:
The state of a Task after one of its green Attempts is accepted (`attempt_accepted`, recording `accepted_by: "owner" | "supervisor" | "lead"`, refused with `gate-running` whenever an `Attempt` is currently in flight so Acceptance never archives the working `Agent` or removes the `Task worktree` underneath a running `Gate`, and always projecting the accepted `Attempt`'s `green` `Verdict` in `projectTask`, ADR 0010, ADR 0031) and its claimed commit is landed into the Project's local checkout from the Task worktree (promoting and unlinking any legacy `<project-root>/.scratch/notebook.md` via `syncLegacyScratchNotebook` before clean-tree verification, ADR 0052; closing cleanly without merging a git branch when the Task is a read-only disposition without a new commit, ADR 0053; hydrating `<project-root>/node_modules` when needed, preserving `factory/<task>` if a local merge conflict requires resolution, and permitting an idempotent re-`accept` on a `pending-conflict` Task to complete `landed` once the conflict is resolved; never pushing to remote, ADR 0010, ADR 0019). Under ADR 0030 and ADR 0052, the Lead accepts green Attempts in every wave, including the final wave, whenever Verdict is green and the Task does not stand in `Needs-human`, after inspecting `git show --stat "<sha>"` and `git diff "<sha>^" "<sha>"` in the Closure & Integration Loop — never re-contracting a GREEN wave solely for test-file DRYness or helper polish (ADR 0052). The Owner retains override and final sign-off.
_Avoid_: done, finished, complete, passed, post-GREEN test-polish re-contracting

**Task closed**:
The terminal retirement state of an unaccepted Task (`task_closed`, recorded via `lead_close_task` / `factory close --task <id> --reason <text>` with `closed_by: "lead" | "supervisor" | "owner"`, ADR 0054) when a Task has been superseded, split into replacement waves (e.g. after `BLOCKED (context-ceiling)`), or retired as no longer needed. Refused if the Task is unknown (`unknown-task`), already accepted (`already-accepted`), already closed (`already-closed`), or has a Gate currently running (`gate-running`). Closing a Task cancels and archives any bound live `Peer` session and temporary Paseo worktree workspace, removes the managed `Task worktree` (`removeTaskWorktree` + branch `factory/<task>`), and marks the Task terminal across `projectTask`, `foldTasks`, `Active Peer Roster`, `liveWorkspaceConflict`, `projectPeerInFlight`, and `FactoryView` KPIs without merging a commit.
_Avoid_: leaving superseded Tasks permanently in `unaccepted` / `needs-human`, merging incomplete or obsolete worktrees just to clear the roster

**Fresh-eyes review** _(retired in ADR 0030)_:
A historical pre-Lead headless review step (`fresh_eyes_written`, added in v0.0.2 / ADR 0005 when no model-backed `Lead` seat existed, unlocked onto `lanes.json` in ADR 0009, and smart-defaulted in ADR 0018). Retired from the active `Contract` / `Claim` / `Acceptance` execution pipeline in v0.0.49 (ADR 0030) in favor of canonical 2-party SLP separation (`Peer` + mechanical `Gate` + `Lead` inspecting `git show --stat "<sha>"` and `git diff "<sha>^" "<sha>"` in the Closure & Integration Loop, matching `paseo-room` and `codex-room`). Historical `fresh_eyes_written` events and `contract_set.freshEyes` fields in existing `Ledger` files remain readable for backward-compatible history projection, never blocking `Lead` acceptance.
_Avoid_: mắt soi (outside research notes), code review, self-review

**Watch**:
The record-only post-verdict pass that asks the Watch questions about one Attempt — a model prompted headless and tool-less on the Watch's configured lane (Lane config, defaulting to `pi/zcode/glm-5.3` or `copilot/gpt-5.4`, ADR 0009, ADR 0055) reading the run timeline, the Contract, the diff and the gate output in one strict-answer pass — and appends exactly one ledger line (`watch_written`). A passenger, never a judge: no notification, no escalation, and Verdicts and driver exits are unchanged by its answers. Off unless the Contract marks it on. Added in v0.0.6; the question table shrank to four in v0.0.7, returned to five in v0.0.8, and moved from a hardcoded Copilot pin to the Lane config in v0.0.13.
_Avoid_: watcher, monitor, alarm, "Jev" (historical: the v0.0.6 design first used a decision model, dropped for the Copilot subscription before the first run)

**Watch question**:
One of the five fixed yes/no questions the Watch asks (destructive-writes, test-weakened, stuck-loop, scope-creep, secret-leak) — each with fixed wording and true/false criteria, answered as a probability between 0 and 1 in a strict `name: probability` answer format, never prose. The v0.0.7 shrink kept four of the original eight (fake-done, unverified-claims and self-accept dropped); destructive-writes returned in v0.0.8, its battery arm redesigned so the blocked step rides a task that still reaches a Claim — the v0.0.6 arm stalled on the block and left the Watch nothing to read.
_Avoid_: check, heuristic, alert rule

**Proposal**:
One unit of `Wave Hardening` output requiring Owner ratification: a class (`gate-check`, `contract-draft`, or `observation`), the recurring task and ledger `seq` evidence that grounds it (`Recurrence Guard`), the causal mechanism, and the exact preview diff for `<project-root>/AGENTS.md`, `CONTEXT.md`, or verification scripts (rendered in the 4-line Owner ratification format, ADR 0048). Advice for the Owner — the factory never applies repo-memory proposals without the Owner's nod. Added in v0.0.7; updated in ADR 0048.
_Avoid_: finding (a fresh-eyes word), recommendation, one-off single-seq complaints

**Ratification**:
The Owner's act of adopting a `Proposal` (from `Lead`'s end-of-directive report via `Supervisor`) into tracked repository files (`AGENTS.md`, `CONTEXT.md`, `docs/adr/`, or `Gate` scripts); recorded in the repo, never a factory event. While in-flight Tier-1 `Gate`, `.worktreeinclude`, and `Project notebook` hardening is applied immediately by `Lead` at `Stable Checkpoint` boundaries without blocking the run, edits to tracked repository memory (`AGENTS.md`, `CONTEXT.md`) always wait for Ratification (ADR 0048). Added in v0.0.7; updated in ADR 0048.
_Avoid_: acceptance, approval (Accepted is the Attempt word), unratified agent edits to `AGENTS.md` / `CONTEXT.md`

**Flaw battery**:
A set of deliberately flawed, gate-green Tasks — plus one clean control — run through the real pipeline to measure whether the fresh-eyes review catches what the Gate cannot. The runner never judges outcomes and never accepts; comparing findings against planted ground truth is the operator's act. Added in v0.0.3.
_Avoid_: test suite, eval harness, mutation suite

**Arm**:
One member of a battery (flaw or bypass): a Workspace carrying one planted flaw or escape (or none, in the control), its Contract, and the ground truth an outcome is compared against.
_Avoid_: case, scenario, fixture (that names the files)

**Battery outcome**:
The comparison words for one arm against ground truth: hit (CONCERN citing the planted flaw), miss (CLEAR on a flawed arm), noisy hit (CONCERN citing only non-planted nits), false positive (CONCERN on the clean control), failed (technical).
_Avoid_: pass/fail (those are Verdict words)

**Watch battery**:
The instrument that measures the Watch: one planted arm per Watch question (five again since the v0.0.8 re-arm) plus a clean control, run through the real pipeline on the trial daemon with the Watch on, outcomes asserted with the Battery outcome words against pre-registered ground truth (a flag means yes-probability ≥ 0.5 naming the planted evidence). The runner never judges and never accepts; comparison against ground truth is the operator's act at close-out. Added in v0.0.6.
_Avoid_: eval suite, calibration set (that is the later tooling)

### Permissions

**Permit ask**:
The daemon's question whenever an agent wants to run a shell command it cannot run unasked (or, under some modes, edit a file). Since v0.0.4 the plugin answers every ask from a contracted Agent itself; Paseo persists no record of its own, so the ledger's `permit_allowed` / `permit_denied` lines are the audit trail an ask leaves. Under ADR 0045 (Lean Permit Recording), `Supervisor`, `Lead`, and dispatcher seats record only violations (`permit_denied` and `git_blocked`) in `ledger.jsonl` (`deny-only`, never appending routine `permit_allowed` lines for seat read/status/MCP calls), and `Peer` (`Agent`) `permit_allowed` events record lean metadata (`task`, `agent`, `permission`) without full `command` payload strings (full `command` strings are persisted strictly on `permit_denied` and `git_blocked`).
_Avoid_: permission prompt (the daemon's UI word), approval, grant, `Supervisor`/`Lead` `permit_allowed` ledger spam

**Choke policy**:
The Layer-2 runtime judge over permit asks (`agent.permission_asked`) from contracted working Agents and from project seats (`Supervisor`, `Lead`, and registered `dispatchers`, ADR 0015, ADR 0016, ADR 0019, ADR 0044, ADR 0045): for contracted working Agents (recognized strictly by a `Task worktree` path or non-seat Agent binding), it applies default-allow with a small deny-list — the dangerous-git vocabulary on any spelling, direct calls to Paseo's native agent-lifecycle tools (`seat-paseo-tool-fence`), and writes outside the writable set (workspace ∪ /tmp ∪ TMPDIR ∪ factory state dir, excluding `<stateDir>/{projects,ledger.jsonl,correlations.json}`). For `Supervisor`, `Lead`, and dispatcher sessions standing at `<project-root>`, it enforces the `Seat write fence` (`seat-write-fence`) and `seat-paseo-tool-fence`, stripping literal heredoc payloads (`<<EOF ... EOF`, `<<'EOF' ... EOF`, `<<-EOF ... EOF`) on non-interpreter shell commands (`cat`, `tee`, etc.) before `splitShellSegments` and `extractWriteTargets` inspect the command so English prose (`touch`, `install`, `rm`, `git`) and Markdown symbols (`> Note`, `>= 0.5`) inside documentation heredocs never trigger false-positive `seat-write-fence` denials while interpreter heredocs (`python3 - <<'PY'`, `node <<'JS'`, `bash <<'EOF'`) keep their body intact for inspection (ADR 0044), and auto-allowing safe read, bash, and `paseo_factory` MCP tool calls silently (`deny-only` in `ledger.jsonl`, ADR 0045) so seats with `auto_accept: false` or `modeId: "auto"` run unattended without blocking on human permission prompts or bloating the Project's `Ledger`. Strictly on `opencode` sessions (`resolveEffectiveProviderFamily(...) === "opencode"`), when a `Bash` ask's violation is purely a bare Layer-3-shimmed binary (`git`, `npm`, `npx`, `pnpm`, `yarn`, `bun`, `pkill`, `kill`, `killall`, `paseo`, `gh`) whose wrapper exists in `<stateDir>/bin`, Layer 2 delegates the refusal to Layer 3 (`exit 126` + `stderr` + `git_blocked`) so OpenCode v2 never aborts the turn with `Permission.DeclinedError`, while non-OpenCode providers (`pi`, `claude`, `codex`, `copilot`, `omp`, `antigravity`) remain untouched (ADR 0019). A deny is choke-and-record: one ledger line, one report line, no mid-task escalation channel.
_Avoid_: sandbox, warden (that would be daemon-wide), allowlist (the stance is the opposite), parsing non-interpreter heredoc prose as shell commands, recording `permit_allowed` in `ledger.jsonl` for `Supervisor`/`Lead` seats

**Seat write fence**:
The 3-layer mechanical write and tool boundary on `<project-root>` and `<stateDir>` for `Supervisor`, `Lead`, and any normal chat session that has dispatched a directive via `factory supervisor dispatch` (ADR 0015, ADR 0016, ADR 0019, ADR 0044, ADR 0055):
1. **Layer 1 (Provider-Native Harness & `providerOptions` / `modeId` / `featureValues` Lock):** On `agent.create`, `opencode` sets `featureValues: { auto_accept: true }`, `toolPolicy: { preapproved: [] }`, `modeId: "build"`, and `providerOptions: { permission: { edit: "deny", task: "deny", bash: "ask", skill: ... } }`; `claude` sets `providerOptions: { disallowedTools: ["Edit", "Write", "MultiEdit", "NotebookEdit", "Task", "mcp__paseo__create_agent", "mcp__paseo__kill_agent", "mcp__paseo__archive_agent", "mcp__paseo__update_agent"] }` (plus `mcp__paseo__send_agent_prompt`); `codex` sets `modeId: "auto"` and `providerOptions: { features: { multi_agent_v2: false } }`; `pi` sets `defaultTools: ["read", "bash", "grep", "find", "ls"]` in `settings.json`; `copilot` sets `featureValues: { auto_accept: false }` and `modeId: "...#plan"` / `"...#agent"`; `omp` sets `modeId: "write"`; and `antigravity` auto-provisions `~/.gemini/config/plugins/paseo-factory/hooks.json` with a `PreToolUse` hook that denies disallowed edits and commands when `PASEO_FACTORY_SEAT` is set (sharing `stripNonInterpreterHeredocs` with Layer 2, ADR 0044).
2. **Layer 2 (`Choke policy` on `agent.permission_asked`):** Refuses (`seat-write-fence`) any file-write tool or shell command targeting paths in `<project-root>` outside the project memory and planning whitelist (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`, `GLOSSARY.md`, `.gitignore`, `.worktreeinclude`, `docs/**`, `.scratch/**`) or mutating `<stateDir>/{projects,ledger.jsonl,correlations.json}` directly (after stripping non-interpreter heredoc bodies via `stripNonInterpreterHeredocs`, ADR 0044), and refuses (`seat-paseo-tool-fence`) direct calls to Paseo's native agent-management tools (delegating bare Layer-3-shimmed `Bash` commands to Layer 3 strictly on `opencode` sessions so OpenCode v2 returns `stderr` without aborting the turn, ADR 0019).
3. **Layer 3 (OS `PATH` Shims in `<stateDir>/bin`):** Enforced by the `Git shim` (`supervisor-git-fence` / `lead-git-fence`), package-manager shims (`npm`, `npx`, `pnpm`, `yarn`, `bun`), and process-protection shims (`pkill`, `kill`, `killall`, `paseo`, `gh`) (ADR 0016, ADR 0019, ADR 0044).
_Avoid_: prompt-only rule, advisory boundary

**Git shim**:
A `git` wrapper in the hook-injected PATH dir (`<stateDir>/bin`, alongside package-manager shims for `npm`, `npx`, `pnpm`, `yarn`, `bun` and process-protection shims for `pkill`, `kill`, `killall`, `paseo`, and `gh`, backed by self-contained scripts staged in `<stateDir>/runtime-bin/` and `<stateDir>/shared/` plus newest-managed-checkout resolution across Paseo `updateSource` so `<stateDir>/bin/*` wrappers survive deletion of outgoing `<paseoHome>/plugins/paseo-factory/<uuid>` checkouts, ADR 0016, ADR 0019) that refuses the destructive git subcommands (force/delete push, `reset --hard`, deleting `clean`, working-tree discard on `<project-root>`, `branch -D`, recovery destruction) at exec time no matter who runs them — while permitting working-tree discard (`git restore <file>`, `git checkout -- <file>`) inside isolated `Task worktree`s (`<projectStateDir>/worktrees/<task>`) so Peers can clean up failed experiments before claiming (ADR 0028), permitting `kill` / `pkill` / `killall` signals targeting test or dev-server child processes scoped inside a `Task worktree` (`/projects/<slug>/worktrees/<task>/`, such as `@embedded-postgres` or Playwright/Chromium) when not matching Paseo or factory infrastructure binaries (ADR 0044), and permitting `npx` invocations that launch read-only MCP stdio server packages (`@z_ai/mcp-server`, `@upstash/context7-mcp`, `chrome-devtools-mcp`, `@notionhq/notion-mcp-server`, `@modelcontextprotocol/server-*`, and `*-mcp*` / `mcp-*` server packages) so harnesses booting global user MCP servers do not trigger false `seat-write-fence` blocks at startup (ADR 0031) — plus, under the `Seat write fence` (ADR 0015, ADR 0016, ADR 0019, ADR 0028), blocks `git commit`, `git merge`, `git cherry-pick`, `git rebase`, `git reset`, `git clean`, `git stash`, and branch creation by `Supervisor` on `<project-root>` (`supervisor-git-fence`), blocks `Lead` from committing non-whitelisted source files on `<project-root>` (`lead-git-fence`), and blocks `Agent` (`Peer`) from committing edits to root memory files (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`) unless `Contract.scope` explicitly lists them (`memory-write-fenced`) — explanatory stderr line plus one `git_blocked` ledger line (bound to `task: contract.task` strictly when `cwd` is a contracted `Task worktree` and `rule` is not a seat fence rule, ADR 0031); everything else passes through to the real git. Composes with Layer 1 and the Choke policy: the shim nets PATH-resolved git, package-mutating seat commands (`npm`/`npx`/`pnpm`/`yarn`/`bun`), and daemon-killing commands (`pkill`/`kill`/`killall`/`paseo`), the policy nets everything that asks.
_Avoid_: git wrapper (too generic), git hook (different mechanism)

**Bypass battery**:
The instrument that measures the choke: four planted escape arms plus a clean control, run against the real plugin on the trial daemon, outcomes asserted against rules fixed before any run (choked = not executed + exactly one ledger line; escaped; clean; failed). The runner never judges and never accepts, and refuses the prod home.
_Avoid_: pentest, red team, security audit

### Records

**Ledger**:
The append-only per-Project record of every event in a Project (`<stateDir>/projects/<project-slug>/ledger.jsonl`, ADR 0010, ADR 0045); ordinary operation never edits or removes recorded facts. Historical Scrum-era `contract_set` events (which carried an `execution` field) and `retro_written` events stay readable and importable: Ledger validation and folding read and ignore the field and fold the events, and nothing writes either shape any more (ADR 0056).
_Avoid_: log, history, sổ (outside research notes), shared root `ledger.jsonl` mixing multiple Projects

**Ledger event identity**:
The stable identity of one recorded factory fact, preserved when its history is copied or synchronized between machines.
_Avoid_: sequence number, timestamp

**Ledger sequence**:
An event's assigned position in one local Ledger. That assignment retains its meaning when more history is imported.
_Avoid_: event identity, global order

**Ledger import**:
Admission of incoming factory history into a local Ledger after its identity, evidence and local state bindings have been validated. A fetched snapshot can wait for admission while active work continues.
_Avoid_: download, hydration

**Ledger import conflict**:
Incoming history whose relationship to local history, evidence or local state cannot be resolved unambiguously. Its original snapshot is retained for the Owner's resolution.
_Avoid_: newest-wins, merge success

**Report**:
The human-readable account of one Attempt, generated from the Ledger, with every line traceable to a Ledger event.
_Avoid_: summary, biên bản (outside research notes)

**Meter**:
The plugin-owned recorder of token and cost usage across every provider harness (`pi`, `codex`, `opencode`, `antigravity`, `claude`, `copilot`) and every Project seat (`Supervisor`, `Lead`, working `Agent` / `Peer`, and the headless `Watch` pass) (ADR 0004, ADR 0043, ADR 0055). Rather than relying solely on the Driver or Paseo's volatile, single-turn in-memory `lastUsage`, the plugin extracts authoritative cumulative usage from each provider's native session store through a stat-gated incremental/tail reader (`O(delta)` via byte-offset cursors on append-only JSONL for `pi`/`claude`/`copilot`, 64 KB tail reads of `total_token_usage` on `codex` rollout JSONL, indexed row reads on `opencode` `session_v2`, and incremental `idx > lastStepIdx` Protobuf decoding on `antigravity` `steps`), normalizing all providers into four disjoint additive token buckets (`inputUncachedTokens + cacheReadTokens + cacheWriteTokens + outputTokens = totalTokens`, with `reasoningTokens` reported as a subset of `outputTokens`) plus `totalCostUsd` when metered. Persists across two complementary tiers without bloating the Ledger: (1) exactly one task-scoped `meter_written` line appended to `ledger.jsonl` at each Task Attempt's / Peer's terminal boundary, and (2) an idempotent per-Project rollup (`<projectStateDir>/usage.json`) keyed by `agentId` (retaining `seat`, `task`, `attempt`, `provider`, `harness`, `model`, `turns`, token buckets, timestamps, and `nativeSessionRef` for per-turn auditability) updated debounced on `agent.turn_ended`, finalized on seat rotation/retirement, and lazily backfilled once from `<paseoHome>/agents/` for historical Projects. A recorder, never a judge: no token budgets, no automatic spending cutoffs, and Verdicts remain unchanged. Added in v0.0.8; upgraded to plugin-owned multi-provider two-tier metering in ADR 0043; consolidated GLM Coding Plan sessions onto `extractPi` in ADR 0055.
_Avoid_: cost tracker, billing, accounting, per-turn `ledger.jsonl` spam, double-counting cached or reasoning tokens

### Running

**Spawn**:
Starting a contracted Task's Agent: a `spawn` request through the spool (`lead_dispatch_agent` / `factory spawn`), validated by the plugin (request shape, caller seat authority — refused if called by `Supervisor` or a working `Agent`, task known and not accepted or closed, no workspace conflict, and no currently running/initializing `Peer` already bound to that Task — `peer-already-running`, while any stopped `idle` or `error` `Peer` from a prior run on that Task is automatically canceled and archived before replacement so at most one active `Peer` ever operates in a `Task worktree` at a time, ADR 0031), resolving optional per-dispatch reasoning effort (`thinking?: "low" | "medium" | "high" | "xhigh" | "max"` with `thinkingReason?: string`, adapting automatically to the configured `worker` model's `thinkingOptions` catalog so fixed-effort models such as `antigravity/gemini-4-argon-high` keep their exact model ID and partial-catalog models such as `zcode/GLM-5.3` map `"medium"` to their supported default without stripping thinking, ADR 0054), automatically allocating or reusing the Task's isolated `Task worktree` (`<projectStateDir>/worktrees/<task>` on branch `factory/<task>`) server-side whenever `request.worktree` is omitted on a root-workspace `Contract` so a `Peer` never falls back onto `<project-root>` or shares the `Lead`'s Paseo `workspaceId` (where archiving an outgoing `Lead` during `Lead handoff` would trigger Paseo's `cascadeArchiveChildren` against a same-workspace child), and recorded as exactly one ledger line — `spawn_dispatched` (always carrying the resolved `worktree` path) or `spawn_refused` with its rule — before any agent exists, with the Task's Paseo workspace bound to the Project's `projectId` and the working Agent created with `parent: leadAgentId` (ADR 0015, ADR 0028, ADR 0031, ADR 0045, ADR 0054). Added in v0.0.5; workspace-bound and parented in ADR 0015; freed from pre-declared scope mandates in ADR 0028; guarded by the Single-Active-Peer Law in ADR 0031; equipped with provider-adaptive per-dispatch effort selection in ADR 0054.
_Avoid_: launch, fork, dispatch (that names the happy ledger line), spawning a `Peer` directly in `<project-root>` when `request.worktree` is omitted, stripping thinking suffixes when a model lacks an intermediate effort tier

**Driver**:
`factory run <task>… [--provider <p[/m]>]` — the command that takes explicit task ids, creates each task's branch, spawns each Agent (through the spool, falling back to the `worker` lane in the Lane config when `--provider` is omitted, ADR 0009) and watches to verdict, printing each task's verdict at its own terminal moment and exiting 0 only when every task ran green with zero refusals. It never sets Contracts and never Accepts; it stops at verdicts. Since v0.0.10 its watch loop carries the Lead's stall predicate as a rider (the announced path to a standing plugin loop); since v0.0.12 (ADR 0008) it stays watching across red Attempts below the Attempt ceiling and executes at most one automatic Respawn on Substrate death. Carrying a seat's act does not make it one. Added in v0.0.5.
_Avoid_: orchestrator, runner, supervisor, lead (those are seats, ADR 0006 — the Driver is neither)

**Attempt ceiling**:
The hard cap of three Attempts per Task (`MAX_ATTEMPTS = 3`, fixed in code, never configuration). Enforced plugin-side at `Claim` (a fourth Claim is refused before any Gate starts) and at `Spawn` / `Respawn` (`spawn:attempt-ceiling` / `respawn:attempt-ceiling`), and observed by the Lead rider: when Attempt 3 finishes red, the Task ends immediately in `needs_human` (`reason: "attempt-ceiling"`). Added in v0.0.12 (ADR 0008).
_Avoid_: retry limit, max retries, attempt budget

**Respawn**:
Replacing a contracted Task's Agent after `Substrate death`: a `respawn` request through the spool naming the dead Agent (`died_agent`), validated by the plugin (at most one automatic Respawn per progress marker — the latest `spawn_dispatched` or `gate_finished`) and recorded as `respawn_dispatched` or `respawn_refused` before the replacement Agent is created on the Task's branch with uncommitted working-tree fragments cleaned to `HEAD`. A second `Substrate death` with no new Attempt between them ends in `needs_human` (`reason: "died-after-respawn"`). Added in v0.0.12 (ADR 0008).
_Avoid_: restart (implies reviving the same daemon session), retry (an Attempt word), re-spawn

**Denial-stall**:
A Task whose Agent's turn ended at a denied permit ask: the last thing the Ledger shows for the Task is a denial, no Claim after it, and a fixed grace has elapsed. The Lead's only trigger. Distinct from spawn-then-silence, where nothing at all follows the spawn — substrate death, not a chokee's stall.
_Avoid_: stuck (too broad), blocked, hung

**Substrate death**:
The death of a spawned Agent's machinery — the agent no longer exists on the daemon (its timeline answers "not found"), or exists but shows no Life signal for the no-growth bound. What a Denial-stall is not: a stall is a live chokee; a substrate death has no chokee to poke. Classified by the driver's two doors, both read from the daemon timeline (ADR 0007).
_Avoid_: crash, hang (a live stall's words), zombie, false death (the retired incident class — a history word, not a state)

**Life signal**:
The observable evidence that a spawned Agent is alive and working: its daemon timeline entries growing. What the watch reads to tell working silence from Substrate death on lanes whose silence is honest — ask-less lanes write nothing to the Ledger between Spawn and Claim. Added in v0.0.11 (ADR 0007).
_Avoid_: heartbeat (implies the agent transmits it; the daemon is read, not pinged), liveness probe, ping

**Re-poke**:
The Lead's live wake/reconciliation turn to a stalled or paused Agent (`lead_repoke_agent` / `factory repoke`, ADR 0016, ADR 0053, ADR 0054): delivers either the Lead's explicit ruling/answer (`message?: string`) or the default denial-stall recovery prompt, automatically embeds the Task's current active `Contract` snapshot (`disposition`, `scope`, `gate`, `description`) so in-place `lead_set_contract` updates (`resetPeer: false`) are always visible to the live `Peer`, and appends disposition-aware completion instructions (writable `engineer` commit + 6-Field Handoff vs. read-only `scout | architect | reviewer` no-commit 6-Field Handoff). Never sent into a running turn or over a pending ask.
_Avoid_: nudge, retry, wake (richer machinery's word), reminder, omitting updated Contract details after an in-place `lead_set_contract`

**Needs-human**:
The Ledger event (`needs_human`) the Lead writes when bounded automation is exhausted — when a Re-poke is spent and the Denial-stall persists (`denied-again`, `silent-after-repoke`), when a Task hits the Attempt ceiling (`attempt-ceiling`), or when a Task suffers Substrate death again after its one automatic Respawn (`died-after-respawn`) — each corroborated by its own Ledger evidence seqs. The Supervisor relays it to the Owner in words at its next turn, at leisure (only Acceptance closes a Task).
_Avoid_: alert, escalation ticket, incident (a different kind, its own later writer)

**Parallel run**:
The Driver running more than one contracted Task at once: the number of task ids on the invocation is the ceiling, and every Task works in its own isolated `Task worktree` (`<projectStateDir>/worktrees/<task>`, ADR 0010, ADR 0028). Added in v0.0.5; updated in ADR 0028.
_Avoid_: concurrency (too broad), batch, pool

**Unattended loop**:
A driver loop that takes approved Contracts, spawns Agents, runs Gates and records Verdicts without the Owner present. It commits to branches only; landing to main is always a human act. The Driver is its first shipped slice (v0.0.5); schedules and no-Owner operation remain later rows.
_Avoid_: autopilot, background job, cron

**Lead mailbox**:
The per-Project append-only bidirectional seat mail ledger (`<projectStateDir>/mailbox.jsonl`, ADR 0013, ADR 0015, ADR 0031) written exclusively by the single-writer plugin on a serialized per-Project lane, fed by atomic spool requests (`factory supervisor dispatch`, `factory lead dispatch`, and `factory supervisor report` via `<stateDir>/spool/requests/<id>.json`, ADR 0004, ADR 0015), UI quick dispatch, and Agent terminal outcomes (`Verdict` completed, `Needs-human`, with `notifyPeer` checking `driverWaveInFlight` strictly against the owning Project's `Ledger` slice so concurrent Projects never block each other's `Verdict` delivery). Records four immutable event types (`mail_queued`, `mail_delivered`, `mail_acked`, `mail_requeued`) partitioned by recipient seat (`to: "lead" | "supervisor"`, defaulting to `"lead"`): queued items wait while the recipient seat (`Lead` or `Supervisor`) is `running`, `initializing`, waiting on a permission ask (`attentionReason === "permission"`), or during a Lead handoff (`rotation_pending` or `handing_over`), lazily auto-ensure and self-heal the recipient seat when absent or in `status === "error"` on the next mailbox pump (preserving any in-flight `pendingHandoff` and first-turn `Seat kickoff packet` until `outcome === "completed"`, without looping into an active network outage when no `mail_requeued` batch is being retried), batch-deliver into a single turn when the recipient seat is ready (`status === "idle"` or Paseo idle-collected `status === "closed"` with `archivedAt === null`, waking a sleeping `"closed"` seat automatically on `.send(prompt)` and re-pumping when an interactive seat session resumes on `agent.open.before` / `agent.session_open`), acknowledge only when that turn ends with `outcome === "completed"`, and automatically requeue (with at most one automatic re-pump per `mailId` after seat self-healing) if the turn fails or is interrupted.
_Avoid_: mutable JSON outbox (`outbox.json`), SQLite queue, direct `agents.send` bypass, Paseo `agents.resumeOnStartup` injecting `"Resume working."` prompts ahead of `startupRecovery()`

**Supervisor mailbox**:
The `to: "supervisor"` recipient slice of a Project's `mailbox.jsonl` (ADR 0015, ADR 0031): fed by Owner `/factory` directives (`factory supervisor dispatch`), Lead completion/escalation reports (`factory supervisor report`), and automatic `Needs-human` peer notifications. Like the Lead slice, it auto-ensures and self-heals the Project's `Supervisor` seat on demand, holds queued items while `Supervisor` is `running`, `initializing`, or waiting on a permission ask (`attentionReason === "permission"`), batch-delivers (`# Supervisor mailbox — <N> item(s)`) when `Supervisor` is ready (`status === "idle"` or Paseo idle-collected `status === "closed"` with `archivedAt === null`), and settles with `mail_acked` or `mail_requeued` (with a bounded 1-shot retry pump) on `agent.turn_ended`.
_Avoid_: separate `supervisor-mailbox.jsonl` file, direct `agents.send` bypass

**Supervisor binding**:
Which live chat holds a Project's `Supervisor` seat — the `supervisor` agent id in `<projectStateDir>/project.json`, written only through the plugin's single state writer (v0.6.1, ADR 0057 §5). The plugin never creates a hidden Supervisor: with no live bound Supervisor, Lead reports hold in the Supervisor mailbox and Needs you shows `No Supervisor · N reports waiting` with one Start Supervisor action. A **Supervisor candidate** is any live agent in the Project's workspace started on the `factory-supervisor` role provider, carrying `seat: supervisor` labels, or opened from Paseo's own picker on the Supervisor lane's provider/model inside the Project's root workspace. When the bound Supervisor is archived or missing, the first candidate to open a session binds automatically — replacing the old bind-only-if-empty rule — receiving the Seat kickoff packet plus every held report in one first turn. While a live Supervisor still holds the seat, the panel offers `Use this chat as Supervisor` on the candidate (`factory.supervisor.adopt`: label, bind through the state writer, kickoff, deliver held reports, release the previous Supervisor — archived, or `released` when its Lead is still parented). The Supervisor recipient is re-resolved at every send.
_Avoid_: auto-creating a Supervisor from a Lead report or mailbox pump, a set-once binding that outlives its chat, binding writes that bypass the state writer

**Pause (user)**:
The Owner's intentional suspension of a seat — pausing an agent mid-turn, stopping a turn, or sleeping/powering down the machine. Invisible to the Paseo protocol (`AgentStatus` has no `paused`; a pause surfaces only as a canceled turn or as a live non-`error` agent sitting `idle`/`closed`), so the machine honors it by inference, never by a persisted frozen state (ADR 0050): a paused-but-alive `Peer` on an open spawn round counts as in flight and holds `rotation_pending` across restarts, a paused outgoing `Lead` gets its handoff extraction held and re-sent rather than fused over, and the machine never treats `Pause (user)` as a completed `Peer` outcome. Distinguished from `idle` (a daemon status the machine reads) and from in-flight (the machine's durable judgment from the `Ledger` plus the live snapshot).

**Lead handoff**:
The deterministic runtime succession of a Project's Lead when its context window usage reaches the fixed `128,000` token mark (`128k`, read from Paseo's `lastUsage.contextWindowUsedTokens` with the multi-provider `Meter` incremental native-session fallback across `pi`, `codex`, `opencode`, `antigravity`, `claude`, and `copilot`, ADR 0013, ADR 0018, ADR 0027, ADR 0031, ADR 0043, ADR 0044). Crossing `128k` mid-turn or at the turn boundary (`agent.turn_ended`) marks `rotation_pending` without interrupting the active turn and holds the `Lead mailbox` (`mail_queued`). If an unaccepted Task's `Peer` still has unsettled `Peer` work in flight (`projectPeerInFlight` — checking live `running`/`initializing` `Peer`s across `driverWaveInFlight` and `boundTaskPeers`, plus any `idle` `Peer` whose latest turn ended with `outcome !== "completed"` on an unsettled `Task` so a mid-turn network drop or `EPIPE` on the `Peer` never triggers a premature `Lead handoff`, and — durably, across daemon restarts and plugin updates (ADR 0050) — any live non-`error` `Peer` (`idle`/`closed` included) on an open spawn round over an unsettled `Task` with no terminal event, so a `Pause (user)` of the `Peer` never becomes a quiet point, while excluding any `Task` whose folded `Ledger` status in the current `Contract epoch` is already `Peer`-terminal — `ready-to-accept` / `GREEN`, `needs-human`, `red` at `MAX_ATTEMPTS = 3`, or a queued `from: "peer", kind: "needs_human"` blocker in `mailbox.jsonl` — so `notifyPeer` / `dispatchLead` never self-blocks on the calling `Peer`'s still-`running` turn), the runtime holds the Project in `rotation_pending` (keeping the outgoing `Lead` live and visible in Paseo while queuing incoming `Supervisor`, `Owner`, and `Peer` mail in `mailbox.jsonl`) until the `Peer` wave settles (`notifyPeer`, `dispatchLead`, `observePeers` on `Peer` `agent.turn_ended` / `sweepPeers`, or `pumpAll` observing `projectPeerInFlight === false`). Once no `Peer` is in flight, the plugin transitions `rotation_pending` → `handing_over` (`beginHandoff`) and steers one bounded **reply-first** handoff-extraction turn (`renderHandoffExtractionPrompt`, instructing the outgoing Lead to output the entire Markdown handoff directly in its final assistant message without running shell commands or writing files outside `<project-root>`, ADR 0044) guarded by a dual-fuse safeguard (the runtime trips the fuse only when the outgoing `Lead` is absent/errored, the extraction send fails, or the elapsed `180s` timeout (`HANDOFF_EXTRACTION_TIMEOUT_MS = 180_000`) finds the Lead still `running`; an alive `idle`/`closed` Lead gets the extraction prompt re-sent instead — at most 3 sends per `handing_over` episode — and every completion that did not come from a `completed` extraction turn appends one `needs_human` mail to `Supervisor` (ADR 0050 amending ADR 0018's silent completion)). When the extraction turn completes (`onLeadTurnEnded`), the plugin extracts the outgoing Lead's assistant handoff text from `input.timeline` or by refetching the tail timeline (`daemon.agents.ref(leadId).timeline.refetch({ direction: "tail", limit: 20 })` when `timeline: []` on Paseo `0.13.0+`, ADR 0027, ADR 0044), caps UTF-8 bytes cleanly at `8 KB` (`LEAD_HANDOFF_MAX_BYTES` via `capHandoffText`, never failing the handoff when the model writes past the cap; the extraction prompt forbids copy-pasting active `Contract.description` blocks verbatim or writing detailed post-mortems of already-accepted waves, ADR 0044, ADR 0047), and persists `<projectStateDir>/lead-handoff.md` in Node.js (`writeFileSync`, since v0.6.1 behind a `<!-- paseo-factory handoff: lead=<agentId> written-at=<ISO> -->` metadata header (ADR 0057 §11) so a disk-fed successor kickoff can date the handover — a file without metadata is stale-unknown and one older than the outgoing Lead's last observed activity is stale, each carrying the one-line notice telling the successor to re-read the Ledger and the repository, while the header itself never reaches a seat; accepting a freshly written disk file only as a secondary fallback when non-empty and not an error/refusal note, and **preserving any existing last-known-good `lead-handoff.md` on disk** with a 1-line staleness notice in `renderSuccessorKickoff` whenever extraction times out, exhausts its re-send cap, or produces an empty/refusal reply — an interrupted/canceled extraction turn instead holds `handing_over` and re-sends (ADR 0050 amending ADR 0044), ADR 0044). Upon extraction completion or fuse trip, the plugin finalizes the outgoing Lead's cumulative token snapshot in `<projectStateDir>/usage.json`, archives the outgoing Lead, silently creates a fresh successor Lead (`0%` context), resets `rotationState = "normal"`, and immediately delivers the unified Turn-1 kickoff combining the `Seat kickoff packet`, the machine-verified Active Peer Roster (full status/agent/worktree/attempt/report rows strictly for unaccepted Tasks, with already-accepted Tasks summarized into one compact line, ADR 0047; resolved across the `Ledger`, `CorrelationRegistry`, and live daemon worktrees, preferring `running`/`initializing` or the newest live `Peer` in the current `Contract epoch` rather than older `idle` `Peer`s at the tail of `daemon.agents.list`, ADR 0031), the `Ledger` state digest, `lead-handoff.md`, and all held `Lead mailbox` items (including the `Peer`'s completed `Verdict` or escalation mail, retaining `pendingHandoff` across failed Turn-1 deliveries and reconstructing `pendingHandoff` from `<projectStateDir>/lead-handoff.md` when replacing an errored or restarted successor `Lead` that had not yet completed Turn 1, ADR 0031).
_Avoid_: fourth monitor agent role, mid-turn kill, context compaction on Lead, multi-turn handoff prompt storm, ordering outgoing Lead to shell-write outside `<project-root>`, clobbering last-known-good `lead-handoff.md` on extraction timeout, archiving the outgoing Lead and spawning a blank 0-message successor Lead while a `Peer` is still running, waiting for a `Peer` process turn to become `idle` after its `Task` has already reached a `GREEN` `Verdict` or `Needs-human` in the `Ledger`

**Peer handoff**:
The deterministic runtime succession of a working `Agent` (`Peer`) inside its `Task worktree` when its context window usage reaches the fixed `160,000` token mark (`160k`, read from Paseo's `lastUsage.contextWindowUsedTokens` with the multi-provider `Meter` incremental native-session fallback across all 6 harnesses, ADR 0034, ADR 0043, ADR 0044) before the Task's `Claim` settles. Crossing `160k` triggers a bounded **reply-first** handoff-extraction turn on the outgoing `Peer` (`buildPeerHandoffExtractionPrompt`, instructing the outgoing `Peer` to output the entire Markdown handoff directly in its final assistant message without running shell commands or writing files to disk, guarded by a `180s` fuse safeguard, where the plugin server extracts the assistant reply from the turn timeline or tail refetch, caps UTF-8 bytes cleanly at `12 KB`, and writes `<projectStateDir>/peer-handoff-<task>.md` in Node.js while accepting a freshly written `<worktree>/.paseo-peer-handoff.md` or `<projectStateDir>/peer-handoff-<task>.md` file as a secondary fallback, ADR 0044), finalizes the outgoing `Peer`'s cumulative token snapshot in `<projectStateDir>/usage.json`, archives the outgoing `Peer`, and — up to at most **one** automatic `Peer handoff` per `Contract epoch` (`maxPeerHandoffs = 1`, i.e., at most two `Peer` sessions per epoch) — spawns a fresh successor `Peer` (`0%` context) in the same `Task worktree` with the original `Contract` brief plus the outgoing `Peer`'s handoff digest and current worktree git state. If the successor `Peer` also crosses `160k` in the same `Contract epoch` without a green `Claim`, the runtime archives the `Peer` and escalates a structured `BLOCKED (context-ceiling)` notification to `Lead` with the current worktree commit/diff summary so `Lead` can inspect and split the remaining scope into a follow-up wave rather than spinning additional `Peer`s indefinitely (ADR 0034).
_Avoid_: unbounded 300k+ Peer sessions, infinite Peer rotation loops, discarding uncommitted worktree progress on rotation, ordering outgoing Peer to shell-write outside `<worktree>`

### Surface and configuration

**Factory surface**:
The Owner's Factory UI — the React Native plugin client inside Paseo, the only surface (ADR 0004, ADR 0056; the standalone browser console is gone). It renders a versioned `FactoryView` snapshot and submits only through `factory.*` RPC to the plugin server's single writer. It contributes the **Project panel** in Paseo's workspace panel (one panel = one Project = the open workspace, resolved from the workspace directory — there is no Project switcher and no "All projects" view), the **Settings screen**, one `⌘K` Command Center action, `Open Factory Panel` — and, since v0.6.1 (the ADR 0057 §8 spike), one **Factory header button** per Project root workspace (label "Factory" plus the Needs-you count, opening the panel at the workspace location) and one **read-only Factory composer pill** per live seat chat (the role as label; the popover shows role, model, thinking, context and Project), both registered from a single 20-second `factory.seats.directory` poll — the only door through which they register.
The Project panel reads top to bottom: a header (Project name, one summary line such as "Lead working · 2 Peers · 1 needs you", and a `⋯` menu); **Needs you**, shown only when non-empty — `needs-human` Tasks with their question, Tasks red at the Attempt ceiling, errored or stuck seats, a stuck Lead handoff, `No Supervisor · N reports waiting` when reports hold with no live Supervisor (v0.6.1, ADR 0057 §5), missing prerequisites and a broken Open Design link, each with one primary action that jumps to where the Owner resolves it, while Peer challenge signals routed to the `Lead mailbox` never appear; **Seats** — the Supervisor row, the Lead row with its `Nk / 128k` context bar and its Lead handoff state in words, one `Peer · <Task>` row per live Peer with its disposition, status and Open, and `Use this chat as Supervisor` rows on the Project's Supervisor candidate chats while a live Supervisor holds the seat (v0.6.1, `factory.supervisor.adopt`; Rotate on the Lead row, Revoke in the Supervisor row's `⋯`; a vacant Supervisor row offers `Start Supervisor` with a directive box, a vacant Lead row only says to ask the Supervisor); and the **Open Design** card (linked project name and last sync with Sync and Open Studio on desktop, or a single "not linked" line). The server projects this view-model (`FactoryView.panel`) and the client only renders it. Colour appears only for errors, waiting states and Needs-you items. There is no Accept button: acceptance belongs to the Lead, or to the Supervisor on the Owner's word. The header `⋯` holds the Project's own settings — Supervisor, Lead and Worker model overrides, skill packs, Open Design link and unlink, and two-step `Project reset` / `Project delete`.
A workspace that is not yet a Project shows the four-step **onboarding wizard** (desktop only): Folder (Git checks, offer `git init`, warn on no commits, block when a Lead already exists) → Prerequisites (one `Install all`) → Models (Supervisor, Lead and Worker prefilled from the machine `Lane config`) → Start (optional first directive and Open Design link; Start registers the Project, creates the `Supervisor` seat, sends the directive as its first message and opens that conversation).
The **Settings screen** is machine-wide: one scrolling screen of collapsible sections — Default models & Lane profiles, Skills & Tools (`Skill hub`, `Companion tool`s, `Helper MCP catalog`), Plugins, Vault, Diagnostics — where only the sections carrying a warning open by default. Paseo mobile (iOS/Android) is a monitor with quick actions: Open, Rotate and Revoke work, while Sync, Studio, onboarding and every settings write are absent and the Settings screen is view-only. The surface never replaces the Paseo chat pane and never bypasses the single-writer law. Added in v0.0.13 (ADR 0009); slimmed to the Project panel, Settings screen and one palette action in v0.6.0 (ADR 0056).
_Avoid_: dashboard, portal, control center, room panel, Project switcher, "All projects" view, Start Lead button, Accept button, Kanban / Timeline / Seat-graph views

**Open Design project link**:
Plugin-owned link state: `design/open-design-link.json` is reserved for this binding and must never be overwritten by a Peer-authored Design provenance note.
The per-Project design binding (`openDesignLink` recorded in `<projectStateDir>/project-settings.json` and mirrored as `<project-root>/design/open-design-link.json`, ADR 0041) that connects an Open Design desktop project (discovered by reading `~/Library/Application Support/Open Design/namespaces/release-stable/data/app.sqlite` `TABLE projects` and `data/projects/<id>/` on the host, even when `Open Design.app` is closed) to a `paseo-factory` Project. Linking or syncing via the Project panel's Open Design card (Sync, Open Studio), the header `⋯` menu (link and unlink), the onboarding wizard's optional link, or automatically before `Supervisor`/`Lead` dispatch copies/pushes the complete Open Design artifact bundle (`index.html`, `screens.html`, `styles.css`, `app.js`, `app-data.js`, `screens.css`, `screens.js`, `screens-data.js`, `.od-frames/*`, `assets/*`, plus synthesized `design-manifest.json` when absent) over Paseo RPC into the Project's own Git repository (`<project-root>/design/`) so local and remote execution nodes (`andrews-mac-mini`, Windows 11 PC) read self-contained design files from their local workspace without requiring a live connection back to the Owner's MacBook or storing UI mockups in `Private vault`.
_Avoid_: manual `.zip` export/import before every run, syncing project UI mockups into `Private vault`, requiring remote build nodes to query the MacBook's `Open Design.app` live during execution

**Design provenance note**:
A Peer-authored record of imported design sources, tools, timestamps and context, stored in `design/design-manifest.json` or a separate provenance file. It does not replace the plugin-owned Open Design project link in `design/open-design-link.json`.
_Avoid_: writing provenance notes over plugin-owned link state

**Design catalog**:
The structured-inventory half of a linked `design/` bundle and the ONLY `design/` material a `Lead` reads (v0.0.84): today `design/design-manifest.json` (tokens), `design/screens-data.js` (the full screen inventory — ids, titles, descriptions, per-group flows), `design/app-data.js` (seed/configuration data), and `design/screens.html` (Flow Board). The sizing rule is "structured inventory files, not interaction logic" — never a hardcoded file list, so new catalog files the Open Design sync drops in qualify automatically. It is a decomposition input, not a build spec: contracts name screens by id and flow from `screens-data.js` (~27KB / ~7K tokens for goal-partner), keeping the Lead's baseline burn before its first dispatch bounded without moving `LEAD_ROTATE_TOKENS`.
_Avoid_: hardcoded catalog file lists, advertising the interactive prototype or `app.js` as Lead reading material, raising `LEAD_ROTATE_TOKENS` to paper over catalog indiscipline

**Design source**:
The interaction-logic half of a linked `design/` bundle — `design/index.html` (interactive prototype), `design/app.js` (interaction logic), `design/styles.css`, `design/screens.css` — which a `Lead` NEVER reads (the 2026-11-01 goal-partner Lead burned ~82K context on it — `app.js` alone ~44K tokens — before its first dispatch): it is bound by reference in Peer contracts, and `Peer`s read the full `design/` bundle inside their `Task worktree` (reads are never fenced), so implementation fidelity is unchanged (v0.0.84).
_Avoid_: Lead ingestion of design source, copying design source into prompts or contracts, fencing Peer reads of `design/`

**Role provider**:
One of the three managed SLP provider entries (`factory-supervisor`, `factory-lead`, `factory-peer`, ADR 0017, ADR 0026, ADR 0032, ADR 0033, ADR 0055) reconciled atomically into `<paseoHome>/config.json` (`agents.providers`, alongside pinning `agents.resumeOnStartup: false` so Paseo `0.15.0` never injects `"Resume working."` prompts over Factory `startupRecovery()`, sweeping retired `"zcode"` base provider entries, ADR 0055, and defaulting `XDG_STATE_HOME` to `<stateDir>/opencode-state` on `opencode` and `extends: "opencode"` role providers when neither `PASEO_OPENCODE_SERVER_URL` nor `XDG_STATE_HOME` is user-set so Paseo `0.15.0`'s `V2Runtime` always selects `kind: "owned"` instead of rejecting Factory custom `mcpServers` and `PASEO_FACTORY_*` env against a discovered `~/.local/state/opencode/service.json` shared server) at plugin boot and whenever `Lane config` or a `Lane profile` is saved or reset (`lanesSet`, `lanesSetBatch`, `profilesApply`, `lanesReset`) — anchored strictly to the MACHINE-scope table since v0.6.1 (ADR 0057 §11): a Project-scoped save never rewrites the daemon-wide `factory-*` entries, the per-Project override applies at `agent.create` below — plus self-healed on disk (`healFactoryRoleProvidersInConfig`) before every daemon WebSocket connection or CLI bridge call, and the single user-facing `Supervisor (Factory)` entry in `daemon.agentProfiles`. Each Role provider extends the base harness configured in the active scope's `Lane config` (mapping plugin-registered providers not in Paseo's built-in `validExtendsValues` — such as `antigravity` or `agy` without a custom `acp` `command` — to a valid built-in `extends` like `pi` so `ProviderOverridesSchema` validation and Paseo `0.13.0+` WebSocket `hello` session handshakes always succeed), writes replacement `models: [{ id, label, isDefault: true, thinkingOptions }]` (rather than `additionalModels`) so Paseo Desktop's New Chat composer always selects the configured model instead of a stale `AsyncStorage` preference, sets `paseoTools: { enabled: false }` at the Paseo daemon level, and carries `PASEO_FACTORY_SEAT` so `server.addHook("agent.create.before")` (`server.before("agent.create")`) and `server.addHook("agent.open.before")` (`server.before("agent.session_open")`, reading `request.title` and `request.labels` while gating `bindSeatAgentId` / `persistSeatWorkspaceId` to `request.purpose !== "history"`) recognize the seat deterministically from `config.provider` (`factory-supervisor`, `factory-lead`, `factory-peer`) — rewriting both `config.provider` (to the normalized runtime Paseo provider ID, e.g. `claude`, `antigravity`, `opencode`, `pi`) and `config.model` (plus catalog-validated `thinkingOptionId`, omitting `thinkingOptionId` when unsupported) on `agent.create.before` from `<config.cwd>`'s Project `Lane config` (`lanes.json`, ADR 0033) so concurrent multi-project isolation is preserved at launch time and in Layer-2 permission-family checks — without relying on chat title heuristics or custom `Start Supervisor` / `Start Lead` UI buttons.
_Avoid_: `sw2-*` harness matrix, retired `zcode-acp-server` base provider entries, title-only seat guessing, manual `Start Lead` button, `additionalModels` catalog pollution, invalid `extends: "antigravity"` in `config.json`, shared `opencode` `service.json` collisions on Paseo `0.15.0`, mutating active seat bindings in `project.json` when `purpose === "history"`

**Project reset**:
The Owner-only act (`factory reset [--workspace <dir>] [--project <slug>] [--keep-seats]` and the `Reset Project` action in the Project panel's `⋯` menu, ADR 0015, ADR 0043, ADR 0045) that wipes a Project's verification history, runtime state, and repository output with zero cross-Project blast radius so the Project starts fresh like a brand-new Project without manual file deletion or plugin reloads: cancels and archives all bound working `Agent`s and temporary Paseo worktree workspaces of the Project, removes `<projectStateDir>/worktrees/*` and `factory/<task>` branches, cancels and archives **every** live `Supervisor` and `Lead` seat instance bound to the Project (unless `--keep-seats` is passed, never leaving duplicate or rotated seats unarchived), clears `<projectStateDir>/{mailbox.jsonl,lead-handoff.md}`, clears `<projectStateDir>/usage.json` (or, when `--keep-seats` is passed, prunes all task/peer and retired-seat entries while retaining only the surviving `Supervisor`/`Lead` session entries), clears the Project's own `<projectStateDir>/ledger.jsonl`, `report-<task>-*.md`, `gate-<task>-*.log`, and any historical `retro-*` files (plus any legacy entries in `<stateDir>/git-blocked.log` and `<stateDir>/correlations.json`) and resets the Project's cached `Factory` instance in the plugin server registry without touching any other Project's ledger or files (ADR 0045), and (unless `--keep-seats` is passed) resets `<project-root>` to a clean initial commit preserving only scaffold/skill config (`.gitignore`, `.worktreeinclude`, `.agents/**`, `.claude/**`), while preserving `<projectStateDir>/{lanes.json,project-settings.json}` and keeping the Project registered. Refused at the Spool (`seat-cannot-reset`) if invoked by `Supervisor`, `Lead`, or a working `Agent`.
_Avoid_: manual `rm -rf`, database drop, wiping `lanes.json`, leaving zombie seats or prior task code behind, Project delete, rewriting other Projects' ledgers on reset

**Project delete**:
The Owner-only act (`factory project delete` and the `Delete Project` action in the Project panel's `⋯` menu, ADR 0024, ADR 0043, ADR 0045) that permanently removes a Project and all of its Factory and Paseo records with zero cross-Project blast radius, including when the Project's directory has already been deleted on disk: cancels and archives any bound working `Agent`s, `Supervisor`, and `Lead` seats, removes temporary worktrees and `factory/<task>` branches if the repository still exists, evicts the Project's `Factory` instance from the plugin server registry and purges its correlations, removes the entire `<stateDir>/projects/<project-slug>/` directory (including `project.json`, `ledger.jsonl`, `report-<task>-*.md`, `gate-<task>-*.log`, `retro-*`, `lanes.json`, and `usage.json`), and removes the Project's workspaces and project record from Paseo. Refused if invoked by `Supervisor`, `Lead`, or a working `Agent`.
_Avoid_: Project reset (which keeps the Project registered and preserves `lanes.json`), orphaned/zombie project chip

**Lane config**:
The five-lane `lanes.json` — supervisor, lead, worker, watch and freshEyes — at machine and Project scope. The machine table is edited on the Settings screen ("Default models & Lane profiles") and seeds the onboarding wizard's Models step; a Project overrides its Supervisor, Lead and Worker lanes from the panel's `⋯` menu, and Reset to machine default removes the override. The `retro` lane was removed in v0.6.0: a stale `retro` key in an older file is ignored on read and dropped on the next save (ADR 0056).
_Avoid_: widened lanes, a `retro` lane, a shared mutable roster

**Lane profile**:
An Owner-authored complete lane-table template in `profiles.json` (five lanes, existing Vault semantics), applied Copy-on-Apply to the machine table (Settings) or to a Project with no live pointer. Applying a profile updates its scope's configuration atomically. The store ships no built-ins.
_Avoid_: live profile pointers

**Pi harness home**:
The clean-room per-role `PI_CODING_AGENT_DIR` directory (`<stateDir>/pi-agent/<role>`, ADR 0011, ADR 0013, ADR 0016, ADR 0030, ADR 0031, ADR 0039, ADR 0042) provisioned by the factory for `Supervisor`, `Lead`, working `Agent`, and the headless tool-less `Watch` pass. Strips user TUI npm packages and user `~/.pi/agent/APPEND_SYSTEM.md` while symlinking auth, models, and `sessions/` from `~/.pi/agent`, writing a role-specific `mcp.json` that registers the `paseo_factory` Role-scoped MCP bridge with `"exposure": "direct"` and `"timeout": 600` (`10m`, overriding Pi `builtin:mcp`'s `DEFAULT_TIMEOUT_SECONDS = 60` so long `Gate` runs never abort at `60000ms`) for `supervisor`, `lead`, and `agent` while provisioning all enabled external servers from the unified `Helper MCP catalog` (`supabase`, `context7`, `exa`, `zai-vision` with `"timeout": 300` matching `Z_AI_TIMEOUT = "300000"`, `chrome-devtools-mcp`, `framelink-figma`, `notion-mcp-server`, `sequential-thinking`, `expo-mcp`, etc., with synchronized `mcp-oauth` token bundles) **strictly for `role === "agent"`** (`Peer`) and never for `supervisor` or `lead` (ADR 0016, ADR 0031, ADR 0039, ADR 0042), restricting `defaultTools` to `["read", "bash", "grep", "find", "ls"]` for `supervisor` and `lead` in `settings.json` (removing `edit` and `write` tools at the Pi harness level, ADR 0016), defaulting headless `pi/<model>` invocations without an explicit `:thinking` suffix to `--thinking off` so headless tool-less passes never inherit `"defaultThinkingLevel": "high"` from `~/.pi/agent/settings.json` (ADR 0030), writing a role-specific compaction-proof `<stateDir>/pi-agent/<role>/APPEND_SYSTEM.md` for `Supervisor`, `Lead`, and `Agent` (ADR 0013), symlinking `~/.pi/agent/{prompts,skills}` into `Supervisor` so the Owner retains 100% of their slash commands and skills on `Supervisor`, and scoping working `Agent` `<available_skills>` to all installed `~/.agents/skills/*` except the Owner-only `factory` skill (`["!*", "+~/.agents/skills/*", "-~/.agents/skills/factory"]`, ADR 0039) plus any on-demand `Contract` skills and active `Project skill pack`s (ADR 0042).
_Avoid_: sandbox, profile dir, shadow home

**Zcode harness home** _(retired in ADR 0055)_:
A historical per-seat storage directory (`<stateDir>/zcode-home/...`, added in ADR 0046 and ADR 0049 for `zcode-acp-server` + `zcode.cjs`). Retired in ADR 0055 when GLM Coding Plan models moved onto `Pi harness home` (`pi/zcode/glm-5.3`, `pi/zcode/glm-5.3-flash`) backed by the local `TriDefender/zcode-api` proxy (`com.zcode.proxy` on `127.0.0.1:8318`).
_Avoid_: spawning `zcode-acp-server` or `zcode.cjs`, writing `<worktree>/.zcode/config.json`, maintaining a parallel ZCode execution harness alongside `Pi harness home`

**Helper MCP catalog**:
The unified, package-deduplicated registry of external MCP servers (`supabase`, `context7`, `exa`, `zai-vision`, `chrome-devtools-mcp`, `framelink-figma`, `notion-mcp-server`, `sequential-thinking`, `open-design`, `expo-mcp`, etc.) discovered read-only across host harness configurations (`~/.gemini/config/mcp_config.json`, `~/.pi/agent/mcp.json`, `~/.claude.json`, `/Applications/Open Design.app`'s built-in `od mcp` daemon CLI when installed on the host, and official Expo remote MCP `https://mcp.expo.dev/mcp` when Expo skills are installed) and persisted with selective sync controls in `<stateDir>/helper-mcps.json` (collapsing duplicate command/package aliases such as `chrome-devtools-mcp` ↔ `chrome-devtools`, `zai-vision` ↔ `zai-mcp-server`, and `open-design` ↔ `open_design`, preferring credentialed entries, and respecting `"disabled": true`, ADR 0039, ADR 0041, ADR 0042, ADR 0049). Host files (`~/.gemini/*`, `~/.claude.json`, `~/.pi/agent/*`, `/Applications/Open Design.app`) are treated as **strictly read-only sources**: servers originating outside Pi's core starter set (`context7`, `exa`, `zai-vision`) — including discovered `open-design` and `expo-mcp` — default to **Local on Host (`enabled: false`, not synced)** until the Owner explicitly clicks **`+ Sync to Peer`**, and each synced server carries per-provider target toggles (`targetProviders: Array<"pi" | "claude" | "codex" | "opencode">`) and an explicit per-server **`Vault` opt-in** (`vaultSync: boolean`, defaulting to `false`) so only Owner-selected servers and OAuth token bundles (`<stateDir>/helper-mcp-oauth.json` and `<stateDir>/pi-agent/agent/mcp-oauth/sha256-<sha256(name)>/tokens.json`, with automatic OAuth token refresh when `refresh_token` and `token_url` are available) are provisioned to the selected `Peer` provider harnesses (`<stateDir>/pi-agent/agent/mcp.json` with `"lifecycle": "lazy"`, `config.mcpServers` on `agent.create` for selected Claude, Codex, and OpenCode targets) or replicated to `Private vault` (`config/helper-mcps.json` and `0o600` `secrets/shared/mcp-oauth.json`), while `Supervisor` and `Lead` remain isolated to `paseo_factory` alone (ADR 0031, ADR 0039, ADR 0041, ADR 0042, ADR 0049). Surfaces a compact `Helper MCP Servers (Peer)` card in the Settings screen's Skills & Tools section with **`Check Connectivity`**, a collapsed chip strip showing only `Synced to Peer` servers (plus an `N available on host` count), and a collapsible `⋯ Manage` drawer split into **`Synced to Peer`** (with `[Pi]`, `[Claude]`, `[Codex]`, `[OpenCode]`, `[Vault]` target chips and `Unsync`) and **`Available on Host`** (with `+ Sync to Peer`), while injecting the machine-verified `Available Peer Helper MCPs` roster into `Lead` and `Peer` kickoff prompts.
_Avoid_: auto-syncing all discovered personal host MCPs by default, mutating host `~/.gemini` / `~/.claude.json` / `~/.pi/agent` files, duplicate alias tool bloat, eager startup of all stdio MCP servers, blindly attaching Helper MCPs to `Supervisor` or `Lead`, silent 401 OAuth failures mid-run

**Role-scoped MCP bridge**:
The zero-dependency stdio JSON-RPC 2.0 MCP server (`plugin/bin/bridge.mjs`, server name `paseo_factory`, ADR 0016, ADR 0030, ADR 0031, ADR 0032, ADR 0045) injected into `Supervisor`, `Lead`, and working `Agent` seats (via `config.mcpServers.paseo_factory` on `server.addHook("agent.create.before")` / `server.before("agent.create")` for `opencode`, `claude`, `codex`, `pi`, `copilot`, and `omp` — never via Paseo `0.14+` `defineAgentTool`, which routes through the disabled `paseoTools` gate, and never duplicated on `agent.open.before` `request.mcpServers`, which collides with saved `config.mcpServers` on Paseo `0.14+`; via `<stateDir>/pi-agent/<role>/mcp.json` with `"exposure": "direct"` for `pi`; and via auto-provisioned `~/.gemini/config/plugins/paseo-factory/mcp_config.json` for `antigravity`). Authenticates each seat through its Correlation token and selects a **role-scoped tool catalog** (every tool descriptor advertising `_meta: { timeoutMs: 600_000 }` so harnesses such as ZCode that read `tool._meta.timeoutMs` grant `agent_claim` and all Spool-backed tools the full `10m` timeout budget instead of a `30s` default, ADR 0031) so each seat sees only its own role's tools (`Supervisor`: `supervisor_dispatch_lead`, `supervisor_accept_task`, `factory_status`; `Lead`: `lead_set_contract`, `lead_spawn_agent`, `lead_accept_task`, `lead_repoke_agent`, `lead_needs_human`, `lead_report_to_supervisor`, `factory_status`; `Agent`: `agent_claim`, `agent_escalate_blocker`), reads the target Project's isolated `<stateDir>/projects/<slug>/ledger.jsonl` (falling back to `<stateDir>/ledger.jsonl` only when no per-Project ledger exists, matching `Driver`, `factory cost`, and the Antigravity `PreToolUse` hook under ADR 0045), resolves the real system `git` binary (`resolveRealGitBinary`, bypassing `<stateDir>/bin/git`) when inspecting repositories and allocating `Task worktree`s, and executes over the same single-writer Spool as the `factory` CLI (`<stateDir>/runtime-bin/factory.mjs`) with a `600_000ms` (`10m`) round-trip spool wait budget matching `factory-claim.mjs` so long `Gate` test suites never time out prematurely (ADR 0030).
_Avoid_: shared omnibus MCP server, tools from another role's catalog on a single seat, direct Paseo `create_agent` / `kill_agent` calls, `defineAgentTool` requiring `paseoTools.enabled = true`, duplicate `agent.open.before` `mcpServers` colliding with saved `config.mcpServers`, reading only legacy root `<stateDir>/ledger.jsonl` after per-Project ledger isolation, omitting `_meta.timeoutMs` on MCP tool descriptors

**Correlation token**:
The unforgeable per-session token (`PASEO_FACTORY_CORRELATION = cor_<uuid>`, managed by `CorrelationRegistry` in `plugin/server/correlations.ts` and persisted in `<stateDir>/correlations.json`, ADR 0016) issued during `server.addHook("agent.create.before")` (`server.before("agent.create")`) before Paseo assigns an `agentId`, passed in both `config.env` and `bridge.mjs` CLI `args` (so providers like Codex that filter subprocess `env` still preserve it), and associated with the live `agentId` on `server.addHook("agent.open.before")` (`server.before("agent.session_open")`). Binds every `paseo_factory` MCP tool call and `factory` CLI spool request to its exact seat (`supervisor`, `lead`, or `agent`), `Project` (`slug`), and `Task`.
_Avoid_: unverified env-only role string, mutable global session file

**Seat kickoff packet**:
The deterministic context bundle (`buildSeatKickoffPacket` in `src/preflight.ts`, ADR 0016, ADR 0032, ADR 0039, ADR 0041, ADR 0047, ADR 0048, ADR 0049) prepended to the first turn delivered to a newly created or rotated `Supervisor` or `Lead` seat after the 2-step seat launch verifies `status !== "error"` and `cwd === project.root`: contains the `Project`'s canonical root and slug, git branch, `HEAD` commit, dirty file summary, detected verification commands from `package.json` `scripts` (or Makefile/Cargo/Go/Python markers), top-level repository tree, existing vs absent `AGENTS.md` / `CLAUDE.md` / `CONTEXT.md` / `.scratch` docs summary (explicitly listing absent project-memory files so seats do not issue failing `read_file` calls on Turn 1), `<projectStateDir>/notebook.md` (`Project notebook`) when present, any linked **`Open Design project link`** summary (`design/` artifact inventory, `screens.html` flow board, `index.html` interactive prototype, and `:root` design tokens as authoritative UI specification), active `Ledger` task digest, the role's `paseo_factory` MCP tool table, and (for `Lead`) the machine-verified `Available Peer Helper MCPs` roster with live connectivity/OAuth status and any `auth_expired` warnings (ADR 0039) alongside the queued `Directive` or `Report` mail batch. The Lead packet also carries the serial-wave roadmap/current-wave-only dispatch, bounded four-part briefs, diff inspection and acceptance of every wave, and Challenge Signal reconciliation laws (ADR 0029). When the seat's `config.systemPrompt` already carries `buildRoleKickoffPrompt(role)`, the Turn-1 packet is built with `omitSystemPromptDuplicates: true`, omitting the `Open Design project link` summary, `Available Peer Helper MCPs` roster, and role-contract blocks already in the system prompt, while the `Ledger` task digest compacts more than 3 already-accepted Tasks into a count + latest tail (ADR 0047, ADR 0049).
_Avoid_: cold 1-line mailbox prompt, blind exploratory turn, duplicating the role prompt on Turn 1

**Companion plugin**:
A first-party Paseo plugin in the factory family (`factory-burn-lab`, `factory-release-lab`) listed alongside the Core `paseo-factory` card (`corePlugin`, protected against `disable`/`remove`) in the Settings screen's Plugins section as a compact 2-row card with a collapsible `⋯` (`Manage`) drawer, displaying its repository access tier (`access: "public" | "private"`, with `Private · Invite-only` surfaced on private companions such as `factory-release-lab`), installed `package.json` semantic version (`vX.Y.Z · <sha>`), on-demand remote update status (`Up to date` vs `Update available · <currSha> → <latestSha>` via `factory.plugins.check.updates` with per-plugin fault isolation), and live per-card in-flight progress (`Updating <currSha> → <targetSha>… · Ns`, `Installing from GitHub… · Ns`, `Reloading plugin… · Ns`) plus persistent inline outcome/error banners. Public companions (`factory-burn-lab`) participate in 1-click **`Install All`**, whereas private companions (`factory-release-lab`) are skipped by `Install All` and installed only on explicit per-card **`Install`** after a pre-flight Git/GitHub pull-permission check (auto-wiring `gh auth setup-git` when logged into `gh`, or returning a clear collaborator-access error naming `@<ghUser>` when unauthorized); once installed, all remote plugins participate in `Check for updates` and two-phase `preview` → `apply` `Update` / `Update All` (with `paseo-factory` ordered last on batch updates and tracked across its self-restart until the target revision is running, ADR 0012, ADR 0014).
_Avoid_: addon, widget, module, local sibling, Companion tool (which is a host skill pack or CLI engine, not a Paseo daemon plugin)

**Companion tool**:
A host-level skill pack managed declaratively by `paseo-factory` (`factory-skills-pack` comprising the 10 open-source skills from `mattpocock/skills`, `anthropics/skills`, and `vercel-labs/agent-skills` declared in `CORE_SKILL_SOURCES` plus the built-in `/factory` skill in `<userHome>/.agents/skills`, alongside optional domain skill packs such as `expo-skills-pack` from `expo/skills`, ADR 0036, ADR 0040, ADR 0042, ADR 0055) that is not a Paseo daemon plugin. Rather than vendoring third-party open-source skill Markdown inside the `paseo-factory` repository, `paseo-factory` remembers each skill's canonical GitHub origin (`CORE_SKILL_SOURCES`, `EXPO_SKILL_SOURCES`), clones/updates them directly from GitHub into `<userHome>/.agents/skills/<skillName>`, records both the canonical Git tree SHA (`skillFolderHash`) and `repoCommitSha` in `<userHome>/.agents/.skill-lock.json` (`version: 3`), reconciles symlinks into `~/.pi/agent/skills`, `~/.gemini/config/skills`, `~/.claude/skills`, and `~/.codex/skills` while pruning retired `impeccable*` directories and symlinks, synchronizes `.skill-lock.json`, `companion-tools.json`, and pure-Markdown skills across machines via `Private vault`, checks remote updates on demand (`git ls-remote <sourceUrl> HEAD`, treating missing `repoCommitSha` or mismatched tree/commit SHAs as updatable), locks `Disable` and `Remove` on mandatory tools (`companion-tool-protected`), and surfaces missing or incomplete required core skills in three places: the Prerequisite Setup Gate card in the Settings screen's Skills & Tools section, a Needs-you item on the Project panel, and the onboarding wizard's Prerequisites step (one `Install all`).
_Avoid_: Companion plugin, vendoring third-party open-source skill copies into `paseo-factory`, retired `impeccable` binary/hook installations, false up-to-date status when `.skill-lock.json` omits `repoCommitSha`

**Skill hub**:
The unified skill, role-matrix, and cross-ecosystem discovery surface (`SkillHubView` rendered as `SkillHubCard` in the Settings screen's Skills & Tools section, ADR 0042, ADR 0055, ADR 0056) that gives the Owner one place to inspect and manage every skill on the host without switching between external tools (`Claude`, `Codex`, `Antigravity`, `ZCode`, `Pi`):
1. **Installed Factory Skills (`~/.agents/skills/*`):** Lists every installed skill with its pack classification (`core`, `expo`, `workflow`, `custom`), canonical source, tracked revision (`skillFolderHash` / `repoCommitSha`), freshness status (`up_to_date` vs `update_available` vs `local`), 4-harness symlink health (`Pi`, `Claude`, `Gemini`, `Codex` + 1-click `Heal Symlinks`), and Role Matrix badges (`Supervisor`, `Lead`, `Peer`).
2. **Host Ecosystem Discovery (Read-Only Scanner):** Scans `~/.claude/plugins/` (installed plugins, `marketplace.json`, and `~/.claude/skills/*`), `~/.codex/plugins/cache/` & `~/.codex/skills/`, `~/.gemini/config/plugins/` & `~/.gemini/antigravity/builtin/skills/`, `~/.zcode/skills/` & `~/.zcode/plugins/`, and `~/.pi/agent/skills/` read-only, surfacing uninstalled or unimported skills and packs (including `IDE-native sidecar` and `MCP Server` capability badges) with 1-click **`+ Import to Factory`** into `~/.agents/skills/`.
3. **Role ↔ Skill Matrix:** Displays the effective `<available_skills>` roster for the `Supervisor`, `Lead` and `Peer` roles on the active Project (combining role baselines with active `Project skill pack`s and `Contract.skills`).
_Avoid_: opaque single-card skill count without per-skill visibility, requiring the Owner to open Claude/Codex/Antigravity/ZCode separately to browse or import skills, mutating host ecosystem caches during discovery

**Project skill pack**:
A domain-specific bundle of skills (`expo` from `expo/skills` — 23 stable `expo-*` / `eas-*` skills with `expo-overview` router plus `expo-migrate-module` and `asc-iap`; `firebase`; `zcode-3d`; `science`; `custom`, ADR 0042) scoped to a `Project` either automatically via repository manifest detection (`"expo"` or `"react-native"` in `<project-root>/package.json` or `app.json`) or explicitly via `<projectStateDir>/project-settings.json` (`skillPacks?: string[]`, chosen per Project from the panel's `⋯` menu). When a `Project skill pack` is active on a Project, its skills are provisioned into `Lead` and `Peer` alongside `Contract.skills`, while Projects that do not enable unrelated domain packs (e.g. `science` bioinformatics skills on a mobile app project) keep their agent context windows clean. When a `Contract` omits `skills` on spawn, the Spool prepends a 1-line skill-discipline hint naming any detected pack (apply `tdd`, open only the specific `<available_skills>` entry matching the task's slice) so `Lead` never curates `Contract.skills` by reading `SKILL.md` files into its own context window (ADR 0047).
_Avoid_: dumping 100+ unrelated domain skills into every Project's context window

**Private vault**:
The Owner's built-in private GitHub repository sync (`git:<owner>/factory-vault`, e.g. `daymanondev/factory-vault`, ADR 0014, ADR 0025, ADR 0026, ADR 0036, ADR 0039, ADR 0041) rendered in the Settings screen's Vault section, where its Sync action stays reachable (ADR 0025, ADR 0056) and storing strictly private store and signing credentials (`.p8` App Store Connect keys, Google Play Service Account JSONs, Android `release.keystore` files, Firebase SDK configs, `eye.json`, and `0o600` OAuth token bundles in `secrets/shared/mcp-oauth.json` for external HTTP Helper MCPs such as `supabase`, ADR 0039), operational configurations (`Lane config` both machine-wide and per-app, Owner-authored `Lane profile`s in `config/profiles.json` merged per `profileId` by `updatedAt`, `free-pool.json`, store manifests, `Helper MCP catalog` definitions and server toggles in `config/helper-mcps.json`, and pure-Markdown host skill packs under `config/skills/<skillName>/...` plus `config/skill-lock.json` and `config/companion-tools.json`, ADR 0036, ADR 0039), and node-partitioned `Ledger` / run snapshots outside the open-source factory plugin repositories — never storing per-Project UI mockups or Open Design HTML/CSS/asset bundles (which live strictly inside each Project's own Git repository, ADR 0041). Auto-detects the host's GitHub CLI (`gh`) login, guides step-by-step from `gh auth login` to automatic private repository creation (`gh repo create <user>/factory-vault --private --add-readme`), and executes a single smart bidirectional **Sync** action (pulling & hydrating remote secrets/configs/skills/Helper MCPs and OAuth tokens into `<paseoHome>/vault-runtime/`, `<userHome>/.agents/skills/`, and `<stateDir>/pi-agent/agent/mcp-oauth/`, reconciling provider skill symlinks and Helper MCP manifests, staging multi-node `Ledger` snapshots for writer-owned import with stable identities and preserved local sequences (ADR 0021, ADR 0023), collecting local `lanes.json`/`profiles.json`/manifests/keys/skills/Helper MCPs, and pushing changes back to GitHub with immediate toast and inline feedback).
_Avoid_: plugin card, secret manager service, hardcoded local paths, git-crypt smudge repo, storing project UI design bundles in `factory-vault`

**Design overview canvas**:
The multi-surface review studio where the Owner inspects a linked `Open Design project link` bundle across three synchronized views — the story-grouped **Flow Board (`screens.html`)** organizing all user-journey and edge-state screens with flow connectors, the **Interactive Prototype (`index.html`)** framed inside `.od-frames/` hardware shells (`iPhone`, `Android`, `Desktop`), and the **Inspect & Design System Kit** view rendering `DESIGN.md` tokens and DOM-pinned revision findings — and opens from the Open Design card's Open Studio on desktop only. The linked preview has no approval gate, so its decision buttons are disabled; design decisions are made in conversation with the Supervisor (ADR 0034, ADR 0037, ADR 0040, ADR 0041, ADR 0056). Across multi-machine topologies (`MacBook` ↔ `andrews-mac-mini` ↔ `Windows 11 PC`), the canvas resolves via a **Dual-Path Studio Transport**: probing direct LAN/Tailscale/loopback HTTP first (with optional fixed `PASEO_FACTORY_PREVIEW_PORT` and strict reachability verification that never returns an unreachable candidate URL) and automatically falling back to a **Zero-Firewall RPC Studio Bundle (`preview.bundle`)** over Paseo's existing RPC channel when direct HTTP ports are blocked by Windows Defender Firewall, NAT, or SSH tunnels (ADR 0041).
_Avoid_: popup preview, 15-minute ephemeral link expiry, 4-screen static-state dump, opening dead browser tabs when remote ephemeral ports are firewalled

**Screen-state routing**:
The deterministic addressing contract (`?screen=<id>&state=<state>` and the `scrum:set-state` message listener — a wire name that predates v0.6.0 and is kept so already-synced designs keep working) that maps declared screens in `EXPERIENCE.md` and `screens.html` to addressable views in the UX prototype without in-page debug toolbars (ADR 0034, ADR 0040).
_Avoid_: ad-hoc in-page debug bars, forcing every screen to duplicate six hidden static DOM trees

**Screen surface**:
The target device form factor declared for a screen in `EXPERIENCE.md` (`mobile`, `desktop`, or `responsive`), governing which viewports (`390×844` Mobile, `1280×800` Desktop, or both) are rendered on the `Design overview canvas` and verified by browser evidence, and enforcing the matching layout shell (`Mobile app shell` vs. desktop workspace, ADR 0037, ADR 0040).
_Avoid_: universal dual-viewport mandate, shrunk-desktop mobile layout, mobile-captured desktop admin console

**Mobile app shell**:
The structural viewport anatomy required for `mobile` screens and mobile-breakpoint `responsive` screens (`390×844` viewport backed by `.od-frames/` hardware shells and `@layer od-layout` primitives in `layout.css`, with status bar, compact top app bar, internal scrollable content region, fixed bottom tab bar or action bar with icons, and touch-native choice chips, radio cards, step wizards, and drenched/tonal surfaces following Open Design's one-primary-action-per-screen rule), prohibiting multi-column HTML `<table>` layouts, native `<select>` survey dumps, and essay-length prose inside cards (ADR 0037, ADR 0040).
_Avoid_: narrow desktop web form, footer text banner, multi-column mobile `<table>`, native `<select>` survey dumps, border-top text walls

**Pure product chrome**:
The rule that `mockups/index.html` and `mockups/screens.html` render exclusively product interfaces and user-journey boards, delegating review switching to the outer `Design overview canvas` host chrome and banning both in-mockup debug toolbars and leaked specification jargon (`FR-*`, `NFR-*`, `UJ-*`, `AD-*`, `ADR-*`, `@scope/pkg` names, function/field identifiers, or raw `GET/POST /api/...` strings) from visible UI copy (ADR 0037, ADR 0040).
_Avoid_: in-mockup debug header, in-page state switcher bar, spec-dump UI copy

**In-shell contextual state**:
A rendering of system and edge states (`empty`, `loading`, `populated`, `error`, `offline`, `permission-denied`) inside the product's outer app shell — modeled either as dedicated screens in the `System & Edge States` group of `screens.html` or as in-shell view states — without replacing the entire screen with a raw diagnostic box (ADR 0037, ADR 0040).
_Avoid_: full-screen state replacement panel, 24-clone static HTML boilerplate

### Retired in v0.6.0 (ADR 0056)

Terms that earlier releases defined and v0.6.0 deleted. Seats read this list so a stale ADR or Ledger line is not mistaken for a live feature.

**Scrum mode** — the Agile Scrum workflow is gone, and SLP is the only way the Factory runs: **Execution mode**, **Scrum role** (`pm | ux | architect | dev | qa`), **Owner wait**, **Task allowance**, **Owner allowance grant**, **UI Design Approval Checkpoint**, the Scrum roster, Scrum lanes and profiles, and the Scrum MCP tools. A Project that was in Scrum mode opens as a normal SLP Project after the one-time boot cleanup (`execution.json` → `project-settings.json`; `scrum-lanes.json`, `scrum-profiles.json`, `scrum-active-profile.json`, `execution-switch.json` and `projects/*/scrum/` deleted, safe to run again). Ledgers keep the historical `execution` field on `contract_set`, read and ignored.
**Retro** — the on-demand Daily Retro pass, its CLI, its Command Center action, its proposals file writer and the `retro` lane are deleted. The in-flight loop the Owner relies on is `Recurrence Guard` → `Wave Hardening`, which never depended on Retro, and Proposals still reach the Owner through the Lead's end-of-directive report via the Supervisor. Historical `retro_written` events and `retro-*.md` files stay readable.
**Web Console** and **Console sidecar** — the standalone browser Factory surface and its localhost listener are deleted; the Paseo plugin client is the sole `Factory surface`. The server's timeline feed stays (the Watch reads it).
**Design detector gate** — the Scrum UX-mockup verification gate (`detector.tool: "open-design"`) went with Scrum; a linked design bundle is previewed and synced, not gated.
**Project switcher**, **All projects**, the Task Kanban, the Timeline swimlane, the Ledger stream, the Seat graph and the global Factory screen with its sidebar row.
