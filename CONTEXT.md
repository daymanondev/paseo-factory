# paseo-factory

A verification line for coding agents: the work is judged against criteria fixed before
it starts, by running checks rather than trusting the agent's word, and every step is
recorded so it can be read back later.

## Language

### People and parties

**Agent** (or **Peer** / **Scrum role**):
The working agent (`factory-peer` provider in Paseo's `config.json`, tab titled `Peer · <Task>` in `slp` mode or `PM · <Task>`, `UX · <Task>`, `Arch · <Task>`, `Dev · <Task>`, `QA · <Task>` when contracted with a `Scrum role` in `scrum` mode, ADR 0017, ADR 0032) doing the work on a Task inside its isolated Task worktree, equipped with the `agent` role slice of the Role-scoped MCP bridge (`agent_claim`, `agent_escalate_blocker`) and the `factory-claim` CLI (ADR 0016). It may make Claims; it never sets or changes a Contract. Under ADR 0029 and ADR 0032, it implements only its bounded outcome (or autonomous BMad V7 role deliverable under `.scratch/<slug>/`), records decisions and assumptions in its owned `.scratch/<initiativeId>/decisions/<task>.jsonl` rather than stopping for interactive prompts, and respects Excluded / Deferred to Later Waves. After a third failed fix with the same symptom it stops local patching to diagnose the root mechanism, or commits independent completed work and escalates with concrete evidence and the current SHA via REOPEN_REQUEST (foundation | dependency | lifecycle | API | ownership | verification), DEPENDENCY_REQUEST, or BLOCKED.
_Avoid_: worker (except as the legacy `lanes.json` key), bot

**Scrum role**:
One of `pm | ux | architect | dev | qa`, specializing working Agent authority (`agent`) through a persisted `execution?: ScrumTaskBinding` on the Contract (ADR 0032). PM delivers PRD; UX delivers DESIGN, EXPERIENCE and offline mockups; Architect delivers architecture with evidenced Stack and stable AD rules; Dev delivers one bounded story; QA delivers a regression bundle and structured evidence without modifying product source or existing assertions. Each Task owns a separate `decisions/<task>.jsonl`. Stable IDs may have gaps and deprecated definitions; references are distinct from definitions. A missing binding always means SLP/Peer, regardless of current Project mode.
_Avoid_: standing specialist seat, specialization as authority, interactive BMad menus

**Owner**:
Whoever sets or ratifies the work's outcome and final acceptance — the human, or a seat the human has delegated authority to (the Supervisor as conversational delegate; the Lead for intermediate Task contracts and clean green-task acceptance under ADR 0010, with Human override always retained). Never the Agent working that Task.
_Avoid_: reviewer, user

**Supervisor**:
The Owner's conversational delegate seat for a Project (`labels: { seat: "supervisor", project: <slug> }`, tab titled `Supervisor`), rooted at the Project's directory (`cwd = <project-root>`, bound to the Project's active main Paseo `workspaceId` via a 2-step seat launch and initialized on Turn 1 with a deterministic Seat kickoff packet, ADR 0010, ADR 0015, ADR 0016, ADR 0017) rather than an external `<home>-supervisor` folder, with compaction-proof role instructions written from a single shared role-contract module (`src/roles-contract.ts`) to both `config.systemPrompt` and `<stateDir>/pi-agent/supervisor/APPEND_SYSTEM.md`, equipped with the `supervisor` slice of the Role-scoped MCP bridge (`supervisor_dispatch_lead`, `supervisor_accept_task`, `factory_status`, ADR 0016) alongside the `factory` CLI, and 100% of the Owner's slash commands and skills preserved via symlinked `~/.pi/agent/{prompts,skills}` (ADR 0013, ADR 0015) while `<project-root>/AGENTS.md` is never overwritten. It clarifies intent (`grilling`), diagnoses reported repository states via read-only inspection (`ls`, `cat package.json`, `git status`, `git log`) before immediately dispatching any required fix, dependency installation, or verification wave to the Project's Lead via `supervisor_dispatch_lead` / `factory lead dispatch` (immediately ending its turn to wait for the Lead's report, ADR 0019), receives completion summaries and escalations through the bidirectional `mailbox.jsonl` (`to: "supervisor"`, ADR 0015), relays status, verdicts and needs-human items to the Owner, accepts on the Owner's word (`accepted_by: "supervisor"`), and curates project-level rules in `AGENTS.md` / `CONTEXT.md`. Enforced by the Spool and the 3-layer `Seat write fence` (ADR 0015, ADR 0016, ADR 0019), the Supervisor never decomposes Tasks, never calls `factory contract` or `factory run`, never edits product source files or runs package-mutating or git-committing commands on `<project-root>`, never calls Paseo's native agent-management tools directly, never pushes externally, and never accepts without the Owner's word. Added in v0.0.9 (ADR 0006); scoped per Project at `cwd` in ADR 0010; made compaction-proof in ADR 0013; fenced and wired bidirectionally in ADR 0015; equipped with the Role-scoped MCP bridge, Seat kickoff packet, and 3-layer execution fence in ADR 0016; unified with Lead in the Project's main Workspace with orphan workspace sweeping in ADR 0017; equipped with the Diagnostics & Run-Verification Law and Layer-3 package-manager shims in ADR 0019. Under ADR 0029, it transmits Owner outcomes, boundaries, and verification criteria faithfully, preserving architecture freedom unless the Owner explicitly requests file-packaging constraints, and challenges architectural traps or packaging anti-patterns (such as forcing a multi-subsystem application into a single file) via `grilling` with a recommended modular alternative before dispatching unless the Owner explicitly confirms running as-is.
_Avoid_: manager, orchestrator, assistant (and Driver — a mechanism, not a seat)

**Lead** (or **Scrum Lead / PO** in `"scrum"` mode):
The presiding technical seat over Agents for a Project (`labels: { seat: "lead", project: <slug> }`, tab titled `Lead` in `"slp"` mode or `Scrum Lead` in `"scrum"` mode, `cwd = <project-root>`, co-located inside the active `Supervisor`'s Paseo `workspaceId` with `parent: supervisorId` when a Supervisor is live via a 2-step seat launch and initialized on Turn 1 with a deterministic Seat kickoff packet, ADR 0010, ADR 0015, ADR 0016, ADR 0017, ADR 0032): a standing model-backed Paseo agent on the selected workflow's `lead` lane (`lanes.json` for SLP, independent `scrum-lanes.json` for Scrum, anchored by the unified role contract in `config.systemPrompt` and `<stateDir>/pi-agent/lead/APPEND_SYSTEM.md`, equipped with the `lead` slice of the Role-scoped MCP bridge — `lead_set_contract`, `lead_spawn_agent`, `lead_accept_task`, `lead_repoke_agent`, `lead_needs_human`, `lead_report_to_supervisor`, `factory_status` — alongside the `factory` CLI, receiving work through the Project's Lead mailbox, and rotatable manually or automatically via Lead handoff at the `128,000` token mark, ADR 0013, ADR 0015, ADR 0016) paired with the Driver's deterministic watch/respawn/ceiling rider underneath. The Lead reads the Seat kickoff packet and repository, splits a Supervisor directive into one or more Tasks, sets each Task's Contract around desired outcomes, regression invariants, and a Gate command that runs both the new verification and the repository's existing test/build suite (without pre-declaring file-scope handcuffs for the Peer, ADR 0028), spawns working Agents in isolated Task worktrees, judges hand-backs against mechanical Gate evidence and its own direct inspection of the attested commit diff (`git show --stat "<sha>"` and `git diff "<sha>^" "<sha>"`, ADR 0029, ADR 0030), accepts clean green Tasks in every wave (`accepted_by: "lead"`, when Verdict is green and the Task is not in `Needs-human`, ADR 0030), re-briefs or escalates stuck work (`needs_human`), and reports final landed completion or human questions back to the Supervisor via `lead_report_to_supervisor` / `factory supervisor report` (`to: "supervisor"` in `mailbox.jsonl`, ADR 0015, ADR 0016). Under ADR 0032, Scrum Lead uses an independent renderer and frozen Scrum roster, chooses a scale-adaptive track, and records readiness against exact landed artifacts. UX/Architect may work in parallel only with disjoint ownership and a landed shared foundation. Contradictions or unsafe assumptions block Dev. UI decisions are persisted against exact revision/digest through Supervisor; accepted UX revisions remain closed. QA delivers a GREEN regression artifact that may report product defects; Dev promotes unchanged tests through bounded fix or verification Tasks, and a fresh re-audit proves the current executable revision. Structured completion requires the Scrum controller's separate predicate. These orchestration rules do not change SLP acceptance.
_Avoid_: manager, foreman, orchestrator, "the loop" (that names the mechanism), Driver (a mechanism, not a seat)

### Work and criteria

**Execution mode**:
The Project's selected `slp | scrum` workflow in its independent `execution.json` with schema version and monotonic revision. Existing Projects without metadata always use SLP. Machine selection affects future registrations only. Mode switching is an idle Owner operation with durable seat-transition recovery; pending Tasks, Agents, Gates, directives, handoff or nonterminal Scrum runs block switching. A Scrum run freezes policy, roster, approval settings, track and finite budgets. Task identity comes from its Contract binding, never mutable selection.
_Avoid_: mode inside SLP lanes, implicit migration

**Owner wait**:
A recorded wait for an explicit decision or answer from the Owner, including UI design review, that remains pending until the Owner responds or explicitly cancels the work and prevents only work dependent on that answer. Owner absence does not expire the wait; a provider failure or unexplained Agent silence is not an Owner wait.
_Avoid_: approval timeout, Agent stall, provider outage

**Task allowance**:
The cumulative number of Tasks authorized for a Scrum run, including UX revision Tasks, which the Owner may explicitly increase without replacing the run or erasing its consumed allowance. Distinct from a Task's Attempt ceiling and the run's automatic QA fix-round limit.
_Avoid_: time budget, retry allowance, automatic reset

**Owner allowance grant**:
An explicit Owner authorization to add a finite amount to a Scrum run's Task allowance or, separately, its automatic QA fix-round allowance, retaining the work already consumed. It grants capacity, not acceptance, design approval or permission to bypass other unresolved decisions.
_Avoid_: budget reset, automatic replenishment, approval waiver

**UI Design Approval Checkpoint**:
A Scrum-only durable decision on exact accepted design revision, artifact commit and SHA-256 digest. Supervisor relays the Owner's explicit approved, changes_requested or waived decision; Lead and Agents cannot self-approve. Readiness and browser evidence remain required. Changes requested create a new UX revision Task, preserving accepted history. The existing `supervisor_report` / `report` envelope carries optional `reportType: "ui-review"` and a structured preview identity. Approval does not itself establish readiness or product completion.
_Avoid_: chat-keyword approval, reopening accepted UX Tasks

**Project**:
One Git repository supervised by the factory, identified canonically via `git rev-parse --show-toplevel --git-common-dir` as `<project-slug> = <basename>-<sha1(gitRoot).slice(0,6)>` (ADR 0010). Starting a `Supervisor` or `Lead` seat or adding a Project on an existing non-Git directory automatically initializes a Git repository with an initial empty commit so per-Task worktrees work immediately, and registers the Project (ADR 0024). Owns its isolated state directory (`<stateDir>/projects/<project-slug>/`) containing its registration (`project.json`), Ledger, Reports, Retro proposals, and Task worktrees, plus its standing Supervisor and Lead seats. If the Project's directory is later deleted on disk, the registered Project remains selectable by its persisted identity (`missingRoot`) so its history can be inspected or purged via `Project delete` (ADR 0024).
_Avoid_: workspace (that is the working copy a Task runs in), folder, team

**Task**:
One unit of work within a Project, identified by a filename-safe id, judged against exactly one Contract.
_Avoid_: job, ticket, lane

**Contract**:
The done-criteria for a Task, fixed before the Agent starts: one Gate command, optional immutable `execution?: ScrumTaskBinding` (Scrum run, role, policy/config revisions and artifact refs; absence always means SLP/Peer, ADR 0032), optional Artifact path (omitted when the Gate command and commit diff suffice, ADR 0028), optional `scope` (used only as an explicit opt-in when a Task is contracted to edit a root memory file `AGENTS.md`/`CLAUDE.md`/`CONTEXT.md`, never as a Station 4 red Verdict handcuff on code files, ADR 0028), and optional required `skills`, rooted at a Project workspace. Setting a new Contract (`contract_set`) on an unaccepted Task (including one currently in `Needs-human` or at the `Attempt ceiling`) opens a fresh Contract epoch, resetting the Task's Attempt counter, clearing prior `Needs-human` status, and canceling/archiving any previously bound live `Peer` (`Agent`) sessions of that Task so stale `Peer`s from a prior epoch never linger in `idle` or concurrently edit the shared `Task worktree`, while preserving all prior Ledger events, the Task's live `Task worktree` on disk, and its original `base` commit when `base` is omitted (ADR 0018, ADR 0019, ADR 0028, ADR 0031). Lead-authored descriptions have four explicit parts: Bounded Outcome, Contract Boundary & Regression Invariants, Excluded / Deferred to Later Waves, and Verification (the exact Gate command), anchored just-in-time to the current Stable Checkpoint (ADR 0029, ADR 0032).
_Avoid_: spec, acceptance criteria, hợp đồng (outside research notes)

**Workspace**:
The git working copy a Task's work lives in; the Gate runs there and the Artifact is resolved inside it. Under ADR 0010, each spawned Task runs inside its own isolated Task worktree so the Project's root checkout stays clean.
_Avoid_: repo, project dir, cwd

**Serial Wave**:
A bounded stage of a directive, normally one cohesive vertical-slice Task owning a single new interactive workflow or subsystem. Initial roadmaps are rolling-wave outlines rather than fixed commitments: after each wave lands at a Stable Checkpoint, Lead re-evaluates actual repository complexity and splits any downstream wave that spans multiple workflows before contracting it. Multiple Tasks share a wave only when the existing foundation is stable and their module/file surfaces are genuinely disjoint. Each wave is accepted before the next is contracted (ADR 0029, ADR 0034).
_Avoid_: all-at-once decomposition, locked upfront multi-wave roadmaps, multi-subsystem mega-tasks

**Stable Checkpoint**:
The landed Project HEAD established by Acceptance of a GREEN wave; the foundation for the next wave's Contracts and Task worktrees (ADR 0029, ADR 0030).
_Avoid_: unaccepted green commit

**Contract epoch**:
One version of a Task's Contract and the Attempts judged against it. Re-contracting begins a new epoch; an Attempt number identifies work within that epoch.
_Avoid_: retry cycle, Task version

**Task worktree**:
The linked `git worktree` automatically allocated for a Task at Spawn under `<projectStateDir>/worktrees/<task>` on branch `factory/<task>` (rooted at the Contract's `base` commit, copying `.worktreeinclude` entries and symlinking `<project-root>/node_modules` when present, and registered in Paseo under the Project's own `projectId` with the human-readable Workspace title `Peer · <Task> — <short summary>` rather than an internal `<slug> <task>` hash, ADR 0010, ADR 0015, ADR 0017, ADR 0019). Preserved across in-place `contract_set` re-contracting of an unaccepted Task (`worktreeFor` and `liveContractFor` retain the latest unaccepted `spawn_dispatched.worktree` while it exists on disk, ADR 0019), isolates the working Agent (created with `parent: leadAgentId` and tab title `Peer · <Task>`) and Gate execution from `<project-root>`, hydrates `<project-root>/node_modules` from `<worktree>/node_modules` when `<project-root>` lacks installed dependencies, lands its `claimedCommit` back into `<project-root>`'s local branch upon Acceptance, and automatically archives both the working Agent and the temporary Paseo worktree workspace before removing the directory (ADR 0015, ADR 0019). For a pre-contracted Task with no Claims in its current Contract epoch, an Acceptance recorded after that Contract advances initial allocation to current project HEAD instead of its stale base; retries with current-epoch Claims retain the contracted base (ADR 0029).
_Avoid_: clone, sandbox, shadow copy

**Workspace conflict**:
Two live Contracts whose execution Workspaces nest inside one another (`inside` / `contains`), or two live Contracts on the same Project that both explicitly declare overlapping `scope` globs. Because every Task executes in its own isolated `Task worktree` and merges through `landTaskWorktree` at Acceptance, unscoped Contracts on the same Project root never conflict at contract or spawn time (ADR 0028). Added in v0.0.5; updated in ADR 0010 and ADR 0028.
_Avoid_: scope conflict (the charted name — the real key is workspace overlap, not scope intersection), merge conflict

**Gate**:
The command named in a Contract whose exit status is the factual check of the work, executed in its own detached OS process group (`detached: true`, ADR 0016) so that when the command exits or times out, any leftover descendant child processes are reaped (`SIGTERM` → `SIGKILL` on `-pgid`) before stream closure is awaited.
_Avoid_: test step, check, cổng (outside research notes)

**Artifact**:
An optional workspace-relative path inside the Workspace that, when specified on a Contract, must exist for a Verdict to be green (ADR 0028). It can never point outside the Workspace.
_Avoid_: deliverable, output file

### Judging

**Claim**:
The Agent's statement that a Task is finished at a specific commit. A Claim is evidence of intent, never of completion. Within the current `Contract epoch`, if a completed `GREEN` `Attempt` already exists for the exact same commit `sha`, a duplicate `Claim` on that `sha` returns the existing `GREEN` `Attempt` idempotently without opening a redundant `Attempt` or re-running the `Gate`, whereas a retry on a `sha` whose prior `Attempt` was `RED` opens a new `Attempt` below the `Attempt ceiling` (ADR 0031).
_Avoid_: "done" (for the Agent's side), report, submission

**Attempt**:
One Claim and the Gate run it triggers. A Task may have up to three Attempts (the Attempt ceiling, ADR 0008); they are numbered and never overlap.
_Avoid_: retry, run, iteration

**Verdict**:
The factory's red/green judgment of one Attempt. Green means the Workspace sat clean at the claimed commit both before and after the Gate, the Gate exited 0, any Contract-specified Artifact exists, and no root memory file (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`) was modified without an explicit Contract opt-in (ADR 0028). Green is evidence, not acceptance.
_Avoid_: result, status, pass/fail

**Accepted**:
The state of a Task after one of its green Attempts is accepted (`attempt_accepted`, recording `accepted_by: "owner" | "supervisor" | "lead"`, refused with `gate-running` whenever an `Attempt` is currently in flight so Acceptance never archives the working `Agent` or removes the `Task worktree` underneath a running `Gate`, and always projecting the accepted `Attempt`'s `green` `Verdict` in `projectTask`, ADR 0010, ADR 0031) and its claimed commit is landed into the Project's local checkout from the Task worktree (hydrating `<project-root>/node_modules` when needed, preserving `factory/<task>` if a local merge conflict requires resolution, and permitting an idempotent re-`accept` on a `pending-conflict` Task to complete `landed` once the conflict is resolved; never pushing to remote, ADR 0010, ADR 0019). Under ADR 0030, the Lead accepts green Attempts in every wave, including the final wave, whenever Verdict is green and the Task does not stand in `Needs-human`, after inspecting `git show --stat "<sha>"` and `git diff "<sha>^" "<sha>"` in the Closure & Integration Loop. The Owner retains override and final sign-off.
_Avoid_: done, finished, complete, passed

**Fresh-eyes review** _(retired in ADR 0030)_:
A historical pre-Lead headless review step (`fresh_eyes_written`, added in v0.0.2 / ADR 0005 when no model-backed `Lead` seat existed, unlocked onto `lanes.json` in ADR 0009, and smart-defaulted in ADR 0018). Retired from the active `Contract` / `Claim` / `Acceptance` execution pipeline in v0.0.49 (ADR 0030) in favor of canonical 2-party SLP separation (`Peer` + mechanical `Gate` + `Lead` inspecting `git show --stat "<sha>"` and `git diff "<sha>^" "<sha>"` in the Closure & Integration Loop, matching `paseo-room` and `codex-room`). Historical `fresh_eyes_written` events and `contract_set.freshEyes` fields in existing `Ledger` files remain readable for backward-compatible history projection, never blocking `Lead` acceptance.
_Avoid_: mắt soi (outside research notes), code review, self-review

**Watch**:
The record-only post-verdict pass that asks the Watch questions about one Attempt — a model prompted headless and tool-less on the Watch's configured lane (Lane config, defaulting to `pi/zai/glm-5.3` or `copilot/gpt-5.4`, ADR 0009) reading the run timeline, the Contract, the diff and the gate output in one strict-answer pass — and appends exactly one ledger line (`watch_written`). A passenger, never a judge: no notification, no escalation, and Verdicts and driver exits are unchanged by its answers. Off unless the Contract marks it on. Added in v0.0.6; the question table shrank to four in v0.0.7, returned to five in v0.0.8, and moved from a hardcoded Copilot pin to the Lane config in v0.0.13.
_Avoid_: watcher, monitor, alarm, "Jev" (historical: the v0.0.6 design first used a decision model, dropped for the Copilot subscription before the first run)

**Watch question**:
One of the five fixed yes/no questions the Watch asks (destructive-writes, test-weakened, stuck-loop, scope-creep, secret-leak) — each with fixed wording and true/false criteria, answered as a probability between 0 and 1 in a strict `name: probability` answer format, never prose. The v0.0.7 shrink kept four of the original eight (fake-done, unverified-claims and self-accept dropped); destructive-writes returned in v0.0.8, its battery arm redesigned so the blocked step rides a task that still reaches a Claim — the v0.0.6 arm stalled on the block and left the Watch nothing to read.
_Avoid_: check, heuristic, alert rule

**Retro**:
The on-demand, Owner-invoked fresh-context pass over the whole recorded history — the Ledger rendered as a per-task digest, every Report, and the red Attempts' gate logs — in which a model prompted headless and tool-less on the Retro's configured lane (Lane config, ADR 0009) proposes new Gate checks for repeated-error patterns and draft Contract pieces for knowledge holes, every Proposal carrying its seq-cited evidence. Appends exactly one advisory ledger line (`retro_written`) and writes one proposals file; never applies, judges, or notifies. Nothing becomes law until Ratification. Added in v0.0.7; unlocked onto the Lane config in v0.0.13.
_Avoid_: retrospective (the agile ceremony), postmortem, session debrief, "Retro pass" (the mechanism is the noun, like Watch)

**Proposal**:
One unit of Retro output: a class (gate-check, contract-draft, or observation), the ledger seq evidence that grounds it, and the proposal text. Advice for the Owner — the factory never applies its own proposals. Added in v0.0.7.
_Avoid_: finding (a fresh-eyes word), recommendation

**Ratification**:
The Owner's act of adopting a Proposal as ordinary repo work (a PR — a choke-list entry, a contract-template edit, a convention); recorded in the repo, never a factory event. The factory proposes; only the Owner ratifies. Added in v0.0.7.
_Avoid_: acceptance, approval (Accepted is the Attempt word)

**Flaw battery**:
A set of deliberately flawed, gate-green Tasks — plus one clean control — run through the real pipeline to measure whether the fresh-eyes review catches what the Gate cannot. The runner never judges outcomes and never accepts; comparing findings against planted ground truth is the operator's act. Added in v0.0.3.
_Avoid_: test suite, eval harness, mutation suite

**Arm**:
One member of a battery (flaw or bypass): a Workspace carrying one planted flaw or escape (or none, in the control), its Contract, and the ground truth an outcome is compared against.
_Avoid_: case, scenario, fixture (that names the files)

**Battery outcome**:
The comparison words for one arm against ground truth: hit (CONCERN citing the planted flaw), miss (CLEAR on a flawed arm), noisy hit (CONCERN citing only non-planted nits), false positive (CONCERN on the clean control), failed (technical).
_Avoid_: pass/fail (those are Verdict words)

**Watch battery**:
The instrument that measures the Watch: one planted arm per Watch question (five again since the v0.0.8 re-arm) plus a clean control, run through the real pipeline on the trial daemon with the Watch on, outcomes asserted with the Battery outcome words against pre-registered ground truth (a flag means yes-probability ≥ 0.5 naming the planted evidence). The runner never judges and never accepts; comparison against ground truth is the operator's act at close-out. Added in v0.0.6.
_Avoid_: eval suite, calibration set (that is the later tooling)

### Permissions

**Permit ask**:
The daemon's question whenever an agent wants to run a shell command it cannot run unasked (or, under some modes, edit a file). Since v0.0.4 the plugin answers every ask from a contracted Agent itself; Paseo persists no record of its own, so the ledger's `permit_allowed` / `permit_denied` lines are the only audit trail an ask ever leaves.
_Avoid_: permission prompt (the daemon's UI word), approval, grant

**Choke policy**:
The Layer-2 runtime judge over permit asks (`agent.permission_asked`) from contracted working Agents and from project seats (`Supervisor`, `Lead`, and registered `dispatchers`, ADR 0015, ADR 0016, ADR 0019): for contracted working Agents (recognized strictly by a `Task worktree` path or non-seat Agent binding), it applies default-allow with a small deny-list — the dangerous-git vocabulary on any spelling, direct calls to Paseo's native agent-lifecycle tools (`seat-paseo-tool-fence`), and writes outside the writable set (workspace ∪ /tmp ∪ TMPDIR ∪ factory state dir, excluding `<stateDir>/{projects,ledger.jsonl,correlations.json}`). For `Supervisor`, `Lead`, and dispatcher sessions standing at `<project-root>`, it enforces the `Seat write fence` (`seat-write-fence`) and `seat-paseo-tool-fence`, while auto-allowing safe read, bash, and `paseo_factory` MCP tool calls so seats with `auto_accept: false` or `modeId: "auto"` run unattended without blocking on human permission prompts. Strictly on `opencode` sessions (`resolveEffectiveProviderFamily(...) === "opencode"`), when a `Bash` ask's violation is purely a bare Layer-3-shimmed binary (`git`, `npm`, `npx`, `pnpm`, `yarn`, `bun`, `pkill`, `kill`, `killall`, `paseo`, `gh`) whose wrapper exists in `<stateDir>/bin`, Layer 2 delegates the refusal to Layer 3 (`exit 126` + `stderr` + `git_blocked`) so OpenCode v2 never aborts the turn with `Permission.DeclinedError`, while non-OpenCode providers (`pi`, `claude`, `codex`, `copilot`, `omp`, `antigravity`) remain untouched (ADR 0019). A deny is choke-and-record: one ledger line, one report line, no mid-task escalation channel.
_Avoid_: sandbox, warden (that would be daemon-wide), allowlist (the stance is the opposite)

**Seat write fence**:
The 3-layer mechanical write and tool boundary on `<project-root>` and `<stateDir>` for `Supervisor`, `Lead`, and any normal chat session that has dispatched a directive via `factory supervisor dispatch` (ADR 0015, ADR 0016, ADR 0019):
1. **Layer 1 (Provider-Native Harness & `providerOptions` / `modeId` / `featureValues` Lock):** On `agent.create`, `opencode` sets `featureValues: { auto_accept: true }`, `toolPolicy: { preapproved: [] }`, `modeId: "build"`, and `providerOptions: { permission: { edit: "deny", task: "deny", bash: "ask", skill: ... } }`; `claude` sets `providerOptions: { disallowedTools: ["Edit", "Write", "MultiEdit", "NotebookEdit", "Task", "mcp__paseo__create_agent", "mcp__paseo__kill_agent", "mcp__paseo__archive_agent", "mcp__paseo__send_agent_prompt", "mcp__paseo__update_agent"] }`; `codex` sets `modeId: "auto"` and `providerOptions: { features: { multi_agent_v2: false } }`; `pi` sets `defaultTools: ["read", "bash", "grep", "find", "ls"]` in `settings.json`; `copilot` sets `featureValues: { auto_accept: false }` and `modeId: "...#plan"` / `"...#agent"`; `omp` sets `modeId: "write"`; and `antigravity` auto-provisions `~/.gemini/config/plugins/paseo-factory/hooks.json` with a `PreToolUse` hook that denies disallowed edits and commands when `PASEO_FACTORY_SEAT` is set.
2. **Layer 2 (`Choke policy` on `agent.permission_asked`):** Refuses (`seat-write-fence`) any file-write tool or shell command targeting paths in `<project-root>` outside the project memory and planning whitelist (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`, `GLOSSARY.md`, `.gitignore`, `.worktreeinclude`, `docs/**`, `.scratch/**`) or mutating `<stateDir>/{projects,ledger.jsonl,correlations.json}` directly, and refuses (`seat-paseo-tool-fence`) direct calls to Paseo's native agent-management tools (delegating bare Layer-3-shimmed `Bash` commands to Layer 3 strictly on `opencode` sessions so OpenCode v2 returns `stderr` without aborting the turn, ADR 0019).
3. **Layer 3 (OS `PATH` Shims in `<stateDir>/bin`):** Enforced by the `Git shim` (`supervisor-git-fence` / `lead-git-fence`), package-manager shims (`npm`, `npx`, `pnpm`, `yarn`, `bun`), and process-protection shims (`pkill`, `kill`, `killall`, `paseo`, `gh`) (ADR 0016, ADR 0019).
_Avoid_: prompt-only rule, advisory boundary

**Git shim**:
A `git` wrapper in the hook-injected PATH dir (`<stateDir>/bin`, alongside package-manager shims for `npm`, `npx`, `pnpm`, `yarn`, `bun` and process-protection shims for `pkill`, `kill`, `killall`, `paseo`, and `gh`, backed by self-contained scripts staged in `<stateDir>/runtime-bin/` and `<stateDir>/shared/` plus newest-managed-checkout resolution across Paseo `updateSource` so `<stateDir>/bin/*` wrappers survive deletion of outgoing `<paseoHome>/plugins/paseo-factory/<uuid>` checkouts, ADR 0016, ADR 0019) that refuses the destructive git subcommands (force/delete push, `reset --hard`, deleting `clean`, working-tree discard on `<project-root>`, `branch -D`, recovery destruction) at exec time no matter who runs them — while permitting working-tree discard (`git restore <file>`, `git checkout -- <file>`) inside isolated `Task worktree`s (`<projectStateDir>/worktrees/<task>`) so Peers can clean up failed experiments before claiming (ADR 0028) and permitting `npx` invocations that launch read-only MCP stdio server packages (`@z_ai/mcp-server`, `@upstash/context7-mcp`, `chrome-devtools-mcp`, `@notionhq/notion-mcp-server`, `@modelcontextprotocol/server-*`, and `*-mcp*` / `mcp-*` server packages) so harnesses booting global user MCP servers do not trigger false `seat-write-fence` blocks at startup (ADR 0031) — plus, under the `Seat write fence` (ADR 0015, ADR 0016, ADR 0019, ADR 0028), blocks `git commit`, `git merge`, `git cherry-pick`, `git rebase`, `git reset`, `git clean`, `git stash`, and branch creation by `Supervisor` on `<project-root>` (`supervisor-git-fence`), blocks `Lead` from committing non-whitelisted source files on `<project-root>` (`lead-git-fence`), and blocks `Agent` (`Peer`) from committing edits to root memory files (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`) unless `Contract.scope` explicitly lists them (`memory-write-fenced`) — explanatory stderr line plus one `git_blocked` ledger line (bound to `task: contract.task` strictly when `cwd` is a contracted `Task worktree` and `rule` is not a seat fence rule, ADR 0031); everything else passes through to the real git. Composes with Layer 1 and the Choke policy: the shim nets PATH-resolved git, package-mutating seat commands (`npm`/`npx`/`pnpm`/`yarn`/`bun`), and daemon-killing commands (`pkill`/`kill`/`killall`/`paseo`), the policy nets everything that asks.
_Avoid_: git wrapper (too generic), git hook (different mechanism)

**Bypass battery**:
The instrument that measures the choke: four planted escape arms plus a clean control, run against the real plugin on the trial daemon, outcomes asserted against rules fixed before any run (choked = not executed + exactly one ledger line; escaped; clean; failed). The runner never judges and never accepts, and refuses the prod home.
_Avoid_: pentest, red team, security audit

### Records

**Ledger**:
The append-only record of every event in the factory; ordinary operation never edits or removes recorded facts.
_Avoid_: log, history, sổ (outside research notes)

**Ledger event identity**:
The stable identity of one recorded factory fact, preserved when its history is copied or synchronized between machines.
_Avoid_: sequence number, timestamp

**Ledger sequence**:
An event's assigned position in one local Ledger. That assignment retains its meaning when more history is imported.
_Avoid_: event identity, global order

**Ledger import**:
Admission of incoming factory history into a local Ledger after its identity, evidence and local state bindings have been validated. A fetched snapshot can wait for admission while active work continues.
_Avoid_: download, hydration

**Ledger import conflict**:
Incoming history whose relationship to local history, evidence or local state cannot be resolved unambiguously. Its original snapshot is retained for the Owner's resolution.
_Avoid_: newest-wins, merge success

**Report**:
The human-readable account of one Attempt, generated from the Ledger, with every line traceable to a Ledger event.
_Avoid_: summary, biên bản (outside research notes)

**Meter**:
The post-verdict capture of what one task's run cost its lane: the daemon's own usage snapshot — dollars where the lane meters them, tokens where it only counts, the absence recorded where it does neither — read at the run's terminal moment and appended as exactly one ledger line (`meter_written`). A recorder, never a judge: no budgets, no alerts, verdicts unchanged. Added in v0.0.8.
_Avoid_: cost tracker, billing, accounting

### Running

**Spawn**:
Starting a contracted Task's Agent: a `spawn` request through the spool, validated by the plugin (request shape, caller seat authority — refused if called by `Supervisor` or a working `Agent`, task known and not accepted, no workspace conflict, and no currently running/initializing `Peer` already bound to that Task — `peer-already-running`, while any stopped `idle` or `error` `Peer` from a prior run on that Task is automatically canceled and archived before replacement so at most one active `Peer` ever operates in a `Task worktree` at a time, ADR 0031) and recorded as exactly one ledger line — `spawn_dispatched` or `spawn_refused` with its rule — before any agent exists, with the Task's Paseo workspace bound to the Project's `projectId` and the working Agent created with `parent: leadAgentId` (ADR 0015, ADR 0028, ADR 0031). Added in v0.0.5; workspace-bound and parented in ADR 0015; freed from pre-declared scope mandates in ADR 0028; guarded by the Single-Active-Peer Law in ADR 0031.
_Avoid_: launch, fork, dispatch (that names the happy ledger line)

**Driver**:
`factory run <task>… [--provider <p[/m]>]` — the command that takes explicit task ids, creates each task's branch, spawns each Agent (through the spool, falling back to the `worker` lane in the Lane config when `--provider` is omitted, ADR 0009) and watches to verdict, printing each task's verdict at its own terminal moment and exiting 0 only when every task ran green with zero refusals. It never sets Contracts and never Accepts; it stops at verdicts. Since v0.0.10 its watch loop carries the Lead's stall predicate as a rider (the announced path to a standing plugin loop); since v0.0.12 (ADR 0008) it stays watching across red Attempts below the Attempt ceiling and executes at most one automatic Respawn on Substrate death. Carrying a seat's act does not make it one. Added in v0.0.5.
_Avoid_: orchestrator, runner, supervisor, lead (those are seats, ADR 0006 — the Driver is neither)

**Attempt ceiling**:
The hard cap of three Attempts per Task (`MAX_ATTEMPTS = 3`, fixed in code, never configuration). Enforced plugin-side at `Claim` (a fourth Claim is refused before any Gate starts) and at `Spawn` / `Respawn` (`spawn:attempt-ceiling` / `respawn:attempt-ceiling`), and observed by the Lead rider: when Attempt 3 finishes red, the Task ends immediately in `needs_human` (`reason: "attempt-ceiling"`). Added in v0.0.12 (ADR 0008).
_Avoid_: retry limit, max retries, attempt budget

**Respawn**:
Replacing a contracted Task's Agent after `Substrate death`: a `respawn` request through the spool naming the dead Agent (`died_agent`), validated by the plugin (at most one automatic Respawn per progress marker — the latest `spawn_dispatched` or `gate_finished`) and recorded as `respawn_dispatched` or `respawn_refused` before the replacement Agent is created on the Task's branch with uncommitted working-tree fragments cleaned to `HEAD`. A second `Substrate death` with no new Attempt between them ends in `needs_human` (`reason: "died-after-respawn"`). Added in v0.0.12 (ADR 0008).
_Avoid_: restart (implies reviving the same daemon session), retry (an Attempt word), re-spawn

**Denial-stall**:
A Task whose Agent's turn ended at a denied permit ask: the last thing the Ledger shows for the Task is a denial, no Claim after it, and a fixed grace has elapsed. The Lead's only trigger. Distinct from spawn-then-silence, where nothing at all follows the spawn — substrate death, not a chokee's stall.
_Avoid_: stuck (too broad), blocked, hung

**Substrate death**:
The death of a spawned Agent's machinery — the agent no longer exists on the daemon (its timeline answers "not found"), or exists but shows no Life signal for the no-growth bound. What a Denial-stall is not: a stall is a live chokee; a substrate death has no chokee to poke. Classified by the driver's two doors, both read from the daemon timeline (ADR 0007).
_Avoid_: crash, hang (a live stall's words), zombie, false death (the retired incident class — a history word, not a state)

**Life signal**:
The observable evidence that a spawned Agent is alive and working: its daemon timeline entries growing. What the watch reads to tell working silence from Substrate death on lanes whose silence is honest — ask-less lanes write nothing to the Ledger between Spawn and Claim. Added in v0.0.11 (ADR 0007).
_Avoid_: heartbeat (implies the agent transmits it; the daemon is read, not pinged), liveness probe, ping

**Re-poke**:
The Lead's one act: a fixed-text message to a stalled Agent — continue by a route that needs no denied permission and make your Claim, or end the turn stating what you need from the Owner. Exactly one per Task, enforced where requests land, not hoped for; never sent into a running turn or over a pending ask.
_Avoid_: nudge, retry, wake (richer machinery's word), reminder

**Needs-human**:
The Ledger event (`needs_human`) the Lead writes when bounded automation is exhausted — when a Re-poke is spent and the Denial-stall persists (`denied-again`, `silent-after-repoke`), when a Task hits the Attempt ceiling (`attempt-ceiling`), or when a Task suffers Substrate death again after its one automatic Respawn (`died-after-respawn`) — each corroborated by its own Ledger evidence seqs. The Supervisor relays it to the Owner in words at its next turn, at leisure (only Acceptance closes a Task).
_Avoid_: alert, escalation ticket, incident (a different kind, its own later writer)

**Parallel run**:
The Driver running more than one contracted Task at once: the number of task ids on the invocation is the ceiling, and every Task works in its own isolated `Task worktree` (`<projectStateDir>/worktrees/<task>`, ADR 0010, ADR 0028). Added in v0.0.5; updated in ADR 0028.
_Avoid_: concurrency (too broad), batch, pool

**Unattended loop**:
A driver loop that takes approved Contracts, spawns Agents, runs Gates and records Verdicts without the Owner present. It commits to branches only; landing to main is always a human act. The Driver is its first shipped slice (v0.0.5); schedules and no-Owner operation remain later rows.
_Avoid_: autopilot, background job, cron

**Lead mailbox**:
The per-Project append-only bidirectional seat mail ledger (`<projectStateDir>/mailbox.jsonl`, ADR 0013, ADR 0015, ADR 0031) written exclusively by the single-writer plugin on a serialized per-Project lane, fed by atomic spool requests (`factory supervisor dispatch`, `factory lead dispatch`, and `factory supervisor report` via `<stateDir>/spool/requests/<id>.json`, ADR 0004, ADR 0015), UI quick dispatch, and Agent terminal outcomes (`Verdict` completed, `Needs-human`, with `notifyPeer` checking `driverWaveInFlight` strictly against the owning Project's `Ledger` slice so concurrent Projects never block each other's `Verdict` delivery). Records four immutable event types (`mail_queued`, `mail_delivered`, `mail_acked`, `mail_requeued`) partitioned by recipient seat (`to: "lead" | "supervisor"`, defaulting to `"lead"`): queued items wait while the recipient seat (`Lead` or `Supervisor`) is `running`, `initializing`, waiting on a permission ask (`attentionReason === "permission"`), or during a Lead handoff (`handing_over`), auto-ensure and self-heal the recipient seat when absent or in `status === "error"`, batch-deliver into a single turn when the recipient seat is ready (`status === "idle"` or Paseo idle-collected `status === "closed"` with `archivedAt === null`, waking a sleeping `"closed"` seat automatically on `.send(prompt)` and re-pumping when an interactive seat session resumes on `agent.session_open`), acknowledge only when that turn ends with `outcome === "completed"`, and automatically requeue (with at most one automatic re-pump per `mailId` after seat self-healing) if the turn fails or is interrupted.
_Avoid_: mutable JSON outbox (`outbox.json`), SQLite queue, direct `agents.send` bypass

**Supervisor mailbox**:
The `to: "supervisor"` recipient slice of a Project's `mailbox.jsonl` (ADR 0015, ADR 0031): fed by Owner `/factory` directives (`factory supervisor dispatch`), Lead completion/escalation reports (`factory supervisor report`), and automatic `Needs-human` peer notifications. Like the Lead slice, it auto-ensures and self-heals the Project's `Supervisor` seat on demand, holds queued items while `Supervisor` is `running`, `initializing`, or waiting on a permission ask (`attentionReason === "permission"`), batch-delivers (`# Supervisor mailbox — <N> item(s)`) when `Supervisor` is ready (`status === "idle"` or Paseo idle-collected `status === "closed"` with `archivedAt === null`), and settles with `mail_acked` or `mail_requeued` (with a bounded 1-shot retry pump) on `agent.turn_ended`.
_Avoid_: separate `supervisor-mailbox.jsonl` file, direct `agents.send` bypass

**Lead handoff**:
The deterministic runtime succession of a Project's Lead when its context window usage reaches the fixed `128,000` token mark (`128k`, read from Paseo's `lastUsage.contextWindowUsedTokens` with Pi `.jsonl` session fallback, ADR 0013, ADR 0018, ADR 0027, ADR 0031). Crossing `128k` mid-turn marks `rotation_pending` without interrupting the active turn; at the turn boundary (`agent.turn_ended`), the plugin locks the Lead mailbox (`handing_over`) and steers one bounded handoff-extraction turn (`<projectStateDir>/lead-handoff.md`) guarded by a dual-fuse safeguard (if the outgoing Lead is absent/errored, if sending the extraction prompt fails, or if `handing_over` exceeds `90s`, the runtime bypasses extraction immediately and completes handoff from machine-verified state without paging Supervisor). When the extraction turn completes without a fresh `<projectStateDir>/lead-handoff.md` and `agent.turn_ended` carries an empty `timeline: []` (Paseo `0.13.0+`), the runtime refetches the tail timeline (`daemon.agents.ref(leadId).timeline.refetch({ direction: "tail", limit: 20 })`) to capture the outgoing Lead's assistant handoff text (ADR 0027). Upon extraction completion or fuse trip, the plugin persists the resolved `handoffText` to `<projectStateDir>/lead-handoff.md`, archives the outgoing Lead, silently creates a fresh successor Lead (`0%` context), and builds the unified Turn-1 kickoff combining the `Seat kickoff packet`, the machine-verified Active Peer Roster (resolved across the `Ledger`, `CorrelationRegistry`, and live daemon worktrees, preferring `running`/`initializing` or the newest live `Peer` in the current `Contract epoch` rather than older `idle` `Peer`s at the tail of `daemon.agents.list`, ADR 0031), the `Ledger` state digest, `lead-handoff.md`, and any held `Lead mailbox` items. When an unaccepted Task's `Peer` is actively running (`driverWaveInFlight` or live `running`/`initializing` `Peer`) and no `Lead mailbox` items are queued (`state.queued.length === 0`), the runtime holds the `pendingHandoff` kickoff bundle rather than waking the successor `Lead` into an empty wait state, delivering the `pendingHandoff` bundle together with the `Peer`'s terminal `Verdict` (or escalation) mail turn when the `Peer` finishes — including when the successor `Lead` was idle-collected (`status === "closed"`) during a multi-hour `Peer` run or when `pendingHandoff` is durably reconstructed from `<projectStateDir>/lead-handoff.md` after a daemon/plugin restart for an unstarted successor `Lead` (`lastUserMessageAt == null`) (ADR 0031).
_Avoid_: fourth monitor agent role, mid-turn kill, context compaction on Lead, multi-turn handoff prompt storm

**Peer handoff**:
The deterministic runtime succession of a working `Agent` (`Peer`) inside its `Task worktree` when its context window usage reaches the fixed `160,000` token mark (`160k`, read from Paseo's `lastUsage.contextWindowUsedTokens` with Pi `.jsonl` session fallback, ADR 0034) before the Task's `Claim` settles. Crossing `160k` triggers a bounded handoff-extraction turn on the outgoing `Peer` (persisting `<worktree>/.paseo-peer-handoff.md` or `<projectStateDir>/peer-handoff-<task>.md` summarizing completed work, current git status/commits, and remaining verification failures, guarded by a fuse safeguard), archives the outgoing `Peer`, and — up to at most **one** automatic `Peer handoff` per `Contract epoch` (`maxPeerHandoffs = 1`, i.e., at most two `Peer` sessions per epoch) — spawns a fresh successor `Peer` (`0%` context) in the same `Task worktree` with the original `Contract` brief plus the outgoing `Peer`'s handoff digest and current worktree git state. If the successor `Peer` also crosses `160k` in the same `Contract epoch` without a green `Claim`, the runtime archives the `Peer` and escalates a structured `BLOCKED (context-ceiling)` notification to `Lead` with the current worktree commit/diff summary so `Lead` can inspect and split the remaining scope into a follow-up wave rather than spinning additional `Peer`s indefinitely (ADR 0034).
_Avoid_: unbounded 300k+ Peer sessions, infinite Peer rotation loops, discarding uncommitted worktree progress on rotation

**Role provider**:
One of the three managed SLP provider entries (`factory-supervisor`, `factory-lead`, `factory-peer`, ADR 0017, ADR 0026, ADR 0032, ADR 0033) reconciled atomically into `<paseoHome>/config.json` (`agents.providers`) at plugin boot and whenever `Lane config` or a `Lane profile` is saved or reset (`lanesSet`, `lanesSetBatch`, `profilesApply`, `lanesReset`), plus self-healed on disk (`healFactoryRoleProvidersInConfig`) before every daemon WebSocket connection or CLI bridge call, and the single user-facing `Supervisor (Factory)` entry in `daemon.agentProfiles`. Each Role provider extends the base harness configured in the active scope's `Lane config` (mapping plugin-registered providers not in Paseo's built-in `validExtendsValues` — such as `antigravity` or `agy` without a custom `acp` `command` — to a valid built-in `extends` like `pi` so `ProviderOverridesSchema` validation and Paseo `0.13.0` WebSocket `hello` session handshakes always succeed), writes replacement `models: [{ id, label, isDefault: true, thinkingOptions }]` (rather than `additionalModels`) so Paseo Desktop's New Chat composer always selects the configured model instead of a stale `AsyncStorage` preference, sets `paseoTools: { enabled: false }` at the Paseo daemon level, and carries `PASEO_FACTORY_SEAT` so `server.before("agent.create")` and `server.before("agent.session_open")` recognize the seat deterministically from `config.provider` (`factory-supervisor`, `factory-lead`, `factory-peer`) — rewriting both `config.provider` (to the normalized runtime Paseo provider ID, e.g. `claude`, `antigravity`, `opencode`, `pi`) and `config.model` (plus catalog-validated `thinkingOptionId`, omitting `thinkingOptionId` when unsupported) on `agent.create` from `<config.cwd>`'s Project `Lane config` (`lanes.json` in `slp` mode, or `scrum-lanes.json` / frozen Scrum run roster in `scrum` mode, ADR 0033) so concurrent `SLP` + `Agile Scrum` multi-project isolation is preserved at launch time and in Layer-2 permission-family checks — without relying on chat title heuristics or custom `Start Supervisor` / `Start Lead` UI buttons.
_Avoid_: `sw2-*` harness matrix, title-only seat guessing, manual `Start Lead` button, `additionalModels` catalog pollution, invalid `extends: "antigravity"` in `config.json`, unnormalized Scrum seat provider configs

**Project reset**:
The Owner-only act (`factory reset [--workspace <dir>] [--project <slug>] [--keep-seats]` and the `Reset Project` action on the `Factory surface`, ADR 0015) that wipes a Project's verification history, runtime state, and repository output so the Project starts fresh like a brand-new Project without manual file deletion or plugin reloads: cancels and archives all bound working `Agent`s and temporary Paseo worktree workspaces of the Project, removes `<projectStateDir>/worktrees/*` and `factory/<task>` branches, cancels and archives **every** live `Supervisor` and `Lead` seat instance bound to the Project (unless `--keep-seats` is passed, never leaving duplicate or rotated seats unarchived), clears `<projectStateDir>/{mailbox.jsonl,lead-handoff.md}`, purges the Project's events from the `Ledger` (`ledger.jsonl`), `<stateDir>/git-blocked.log`, and `<stateDir>/correlations.json` along with its `report-<task>-*.md`, `gate-<task>-*.log`, `retro-*`, and `scrum/` runtime files, and (unless `--keep-seats` is passed) resets `<project-root>` to a clean initial commit preserving only scaffold/skill config (`.gitignore`, `.worktreeinclude`, `.agents/**`, `.claude/**`), while preserving `<projectStateDir>/{lanes.json,scrum-lanes.json,execution.json}` and keeping the Project registered. Refused at the Spool (`seat-cannot-reset`) if invoked by `Supervisor`, `Lead`, or a working `Agent`.
_Avoid_: manual `rm -rf`, database drop, wiping `lanes.json`, leaving zombie seats or prior task code behind, Project delete

**Project delete**:
The Owner-only act (`factory project delete` and the `Delete Project` action on the `Factory surface`, ADR 0024) that permanently removes a Project and all of its Factory and Paseo records, including when the Project's directory has already been deleted on disk: cancels and archives any bound working `Agent`s, `Supervisor`, and `Lead` seats, removes temporary worktrees and `factory/<task>` branches if the repository still exists, purges all Project events from the `Ledger` along with its reports, gate logs, retro files, and correlations, removes the entire `<stateDir>/projects/<project-slug>/` directory (including `project.json` and `lanes.json`), and removes the Project's workspaces and project record from Paseo. Refused if invoked by `Supervisor`, `Lead`, or a working `Agent`.
_Avoid_: Project reset (which keeps the Project registered and preserves `lanes.json`), orphaned/zombie project chip

**Lane config**:
SLP's unchanged six-lane `lanes.json` maps supervisor, lead, worker, watch, retro and freshEyes at machine/Project scope. Scrum owns a separate complete `scrum-lanes.json` with supervisor, lead, pm, ux, architect, dev, qa, watch, retro and requireUiApproval. Explicit creation copies machine Scrum defaults, or seeds from that scope's SLP roster once; subsequent reads never fall back into SLP. Reset copies machine Scrum values. Active runs keep their frozen roster.
_Avoid_: widened SLP lanes, shared mutable roster

**Lane profile**:
An Owner-authored complete roster template. SLP retains `profiles.json`, its six lanes and existing Vault semantics; Scrum uses `scrum-profiles.json`, complete ScrumConfig, mode-namespaced UI identities and independent active metadata/tombstones. Applying a profile updates its mode's configuration atomically without switching execution mode. Neither store ships built-ins; older Vaults omitting Scrum files do not delete local Scrum settings.
_Avoid_: cross-mode profile apply

**Pi harness home**:
SLP homes below remain unchanged. Scrum standing seats instead own `<projectStateDir>/scrum/harness/seats/<selectionRevision>/<seatGeneration>/<authority>/`; specialists own `<projectStateDir>/scrum/harness/runs/<runId>/<task>/<epoch>/`. Managed prompts, skills, settings and MCP configuration belong to that immutable identity. The clean-room per-role `PI_CODING_AGENT_DIR` directory (`<stateDir>/pi-agent/<role>`, ADR 0011, ADR 0013, ADR 0016, ADR 0030, ADR 0031) provisioned by the factory for `Supervisor`, `Lead`, working `Agent`, and headless tool-less passes (`Watch`, `Retro`). **Companion plugin**:

Public companions (`factory-burn-lab`) participate in 1-click **`Install All`**, whereas private companions (`factory-release-lab`) are skipped by `Install All` and installed only on explicit per-card **`Install`** after a pre-flight Git/GitHub pull-permission check (auto-wiring `gh auth setup-git` when logged into `gh`, or returning a clear collaborator-access error naming `@<ghUser>` when unauthorized); once installed, all remote plugins participate in `Check for updates` and two-phase `preview` → `apply` `Update` / `Update All` (with `paseo-factory` ordered last on batch updates and tracked across its self-restart until the target revision is running, ADR 0012, ADR 0014).
