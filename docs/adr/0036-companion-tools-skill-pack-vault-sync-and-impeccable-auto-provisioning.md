# 0036 — Companion Tools, Declarative GitHub Skill Origins, Prerequisite Setup Gate, and Impeccable Auto-Provisioning

- **Date:** 2026-10-31
- **Status:** Accepted
- **Amends:** ADR 0012, ADR 0014, ADR 0034
- **Preserves:** ADR 0001–0035

## Context

In `ADR 0034`, `pbakaus/impeccable` (`v4.8.0+`) was adopted as the mechanical anti-slop and visual-quality detector gate for Scrum `UX`, `Dev`, and `QA` specialists (`impeccable detect --json --no-advisory`). In addition, `paseo-factory` seats and working agents rely on 11 core workflow skills (`CORE_FACTORY_SKILLS`): 10 open-source skills from external GitHub repositories (`mattpocock/skills`, `anthropics/skills`, `vercel-labs/agent-skills`) plus the built-in `/factory` skill generated by `src/skill.ts`.

Previously:
1. `provisionImpeccable` (`src/scrum/impeccable.ts`) assumed `<userHome>/.agents/skills/impeccable` had already been manually installed on each host machine, and did not reconcile provider skill symlinks (`~/.pi/agent/skills`, `~/.gemini/config/skills`, `~/.claude/skills`).
2. `paseo-factory` did not declare the canonical GitHub origins of its 10 open-source skills (`tdd`, `diagnosing-bugs`, `codebase-design`, `code-review`, `domain-modeling`, `grill-with-docs`, `grilling`, `research`, `frontend-design`, `web-design-guidelines`), nor did it guide the Owner with a setup gate or remote version/update checker when those mandatory tools and skills were missing or outdated.
3. Because the 10 workflow skills are open-source upstream repositories and `paseo-factory` does not maintain a forked skill library, bundling/vendoring copies of third-party skill Markdown inside `paseo-factory` would create staleness and licensing/maintenance drift. Instead, `paseo-factory` should remember where each skill comes from on GitHub, install/update directly from those canonical repositories, guide the user when prerequisites are missing, and manage versions/updates in the `Plugins` tab.

## Decision

### 1. Declarative `Companion tool` Catalog & Canonical GitHub Skill Registry (`CORE_SKILL_SOURCES`)

Define a first-class **`Companion tool`** domain concept (`COMPANION_TOOLS_CATALOG` in `plugin/shared/companions.ts`) alongside Paseo daemon `Companion plugin`s (`COMPANION_CATALOG`), without vendoring third-party skill Markdown into `paseo-factory`:
- **`impeccable`** (`Impeccable UI Detector & Skill Pack`, canonical source `npx:impeccable@latest`, minimum version `4.8.0`): Upstream `pbakaus/impeccable` self-contained Rust/Wasm visual anti-slop detector CLI (`scripts/impeccable`), `SKILL.md` playbooks, and UI PostToolUse design hook.
- **`factory-skills-pack`** (`Factory Core Skill Pack`, canonical source `git:mattpocock/skills + anthropics/skills + vercel-labs/agent-skills`, 11 core skills in `CORE_FACTORY_SKILLS`):
  - `mattpocock/skills` (`https://github.com/mattpocock/skills.git`):
    - `tdd` (`skills/engineering/tdd`)
    - `diagnosing-bugs` (`skills/engineering/diagnosing-bugs`)
    - `codebase-design` (`skills/engineering/codebase-design`)
    - `code-review` (`skills/engineering/code-review`)
    - `domain-modeling` (`skills/engineering/domain-modeling`)
    - `grill-with-docs` (`skills/engineering/grill-with-docs`)
    - `grilling` (`skills/productivity/grilling`)
    - `research` (`skills/engineering/research`)
  - `anthropics/skills` (`https://github.com/anthropics/skills.git`):
    - `frontend-design` (`skills/frontend-design`)
  - `vercel-labs/agent-skills` (`https://github.com/vercel-labs/agent-skills.git`):
    - `web-design-guidelines` (`skills/web-design-guidelines`)
  - Built-in `/factory` skill (`src/skill.ts` → `<userHome>/.agents/skills/factory/SKILL.md`).

### 2. Single Source of Truth at `<userHome>/.agents/skills`, `.skill-lock.json`, & Provider Symlink Reconciliation

Standardize `<userHome>/.agents/skills/<skillName>` as the single host directory for all shared skills and `impeccable*` directories, tracked by `<userHome>/.agents/.skill-lock.json` (`version: 3`, recording `source`, `sourceType`, `sourceUrl`, `skillPath`, `skillFolderHash`, `repoCommitSha`, `installedAt`, and `updatedAt`). Whenever `ensureProviderSkillSymlinks(userHome)` runs:
- Ensure every skill directory in `<userHome>/.agents/skills/*` is symlinked into:
  - `<userHome>/.pi/agent/skills/<skillName>`
  - `<userHome>/.claude/skills/<skillName>`
  - `<userHome>/.gemini/config/skills/<skillName>` (unless `<userHome>/.gemini/config/skills` is already a directory symlink pointing directly to `<userHome>/.agents/skills`).
- Preserve each Scrum specialist's isolated `<roleHome>/skills` allowlist (`!<all>`, plus only the role's permitted skills in `SCRUM_ROLE_SKILLS[role]`).

### 3. Direct GitHub Skill Provisioning (`installOrUpdateFactorySkillPack`) & `Private vault` Sync

- **Direct GitHub Installation & Update (`installOrUpdateFactorySkillPack`):**
  - Reconciles the built-in `/factory` skill (`ensureFactorySkillSafe`), materializes any skills cached in `<paseoHome>/vault-runtime/config/skills`, and clones the canonical GitHub repositories (`git clone --depth 1 <sourceUrl> <tmpDir>`) for any missing `CORE_SKILL_SOURCES` (on `install`) or all 3 canonical repositories (on `update`).
  - Copies each `skillPath` directory into `<userHome>/.agents/skills/<skillName>`, records `repoCommitSha` and `skillFolderHash` in `<userHome>/.agents/.skill-lock.json`, and runs `ensureProviderSkillSymlinks(userHome)`.
- **`Private vault` Sync (`config/skills/`, `config/skill-lock.json`, `config/companion-tools.json`):**
  - `collectVaultSkillsIntoRuntime(paseoHome)` collects pure-Markdown skill directories under `<userHome>/.agents/skills/<skillName>` (skipping `impeccable*`, `.git`, `node_modules`, and files `> 512 KB`), `<userHome>/.agents/.skill-lock.json` (`config/skill-lock.json`), and `config/companion-tools.json` into `<paseoHome>/vault-runtime/`.
  - `materializeVaultSkillsFromRuntime(paseoHome, overwriteConfigs)` materializes `<paseoHome>/vault-runtime/config/skills/<skillName>/...` and `config/skill-lock.json` into `<userHome>/.agents/` and runs `ensureProviderSkillSymlinks(userHome)`.
- **OS/Arch-Specific `impeccable` Binary via Upstream Installer:**
  - Never commit `impeccable`'s OS/CPU-compiled binary (`scripts/impeccable`) into `factory-vault`. Install and update `impeccable` on each host via its upstream installer (`npx --yes impeccable@latest install --yes --global --no-hooks --force --providers=codex,claude,gemini,opencode,pi`) so macOS arm64, macOS x64, and Linux hosts each receive their native binary.

### 4. Pre-Spawn Self-Healing + Fail-Fast Guard (`tool-missing`)

In `provisionImpeccable(roleHome, userHome, sourceCodexHome, options)`:
1. Reconcile provider skill symlinks (`ensureProviderSkillSymlinks(userHome)`) when running against the real host home (`userHome === homedir()`).
2. Inspect `<userHome>/.agents/skills/impeccable` (and fallback provider directories) via `inspectImpeccableTool(userHome)` for `SKILL.md` frontmatter `version:` (`>= 4.8.0`), executable `scripts/impeccable`, and `scripts/VERSION` (engine version).
3. When `impeccable >= 4.8.0` is missing on the real host home (`userHome === homedir()` or `options?.autoInstall === true`), automatically invoke `installOrUpdateImpeccableTool({ userHome, action: "install" })` before linking `<roleHome>/skills`.
4. If `options?.requireInstalled === true` (or when `autoInstall` was attempted and failed), throw `FactoryError("tool-missing", ...)` with a clear diagnostic so a live Scrum `UX`/`Dev`/`QA` specialist never launches blind without its required detector binary.

### 5. Guided Prerequisite Setup Gate, Version Checking, & Protected Companion Tools

- **Prerequisite Setup Gate on `Factory surface` (`plugin/client/factory/shell.tsx`):**
  - Whenever any entry in `view.companionTools` has `status !== "running"` or `error !== null` (e.g., `impeccable` missing/outdated or any of the 11 `CORE_FACTORY_SKILLS` missing), render a prominent **Prerequisite Setup Gate** card right below the Header across all tabs explaining which tools/skills are missing, their GitHub/npm origins, copyable CLI install commands, and a 1-click **`Install Required Skills & Tools`** CTA (`pluginsInstall({ target: "all", includeTools: true })`).
- **Protected Mandatory Companion Tools (`companion-tool-protected`):**
  - Both `impeccable` and `factory-skills-pack` are required by Factory: `pluginsManage` refuses `disable` and `remove` on `MANAGEABLE_TOOL_IDS` with `companion-tool-protected` (matching `core-plugin-protected` on `paseo-factory`), and `CompanionCard` in `plugin/client/factory/plugins.tsx` locks `Disable`/`Remove` on companion tools while exposing `Install`, `Update`, and `Reload` (re-link symlinks).
- **Remote Version & Update Checking (`checkCompanionToolsUpdates`):**
  - `factory.plugins.check.updates` (`pluginsCheckUpdates`) checks remote updates for `impeccable` (via `npm view impeccable version` against the installed version) and `factory-skills-pack` (via `git ls-remote <sourceUrl> HEAD` across `mattpocock/skills`, `anthropics/skills`, and `vercel-labs/agent-skills` against `.skill-lock.json` `repoCommitSha` and missing core skills), surfacing `Update available` / `Up to date` pills and including updatable companion tools in `Update All (N)`.

## Consequences

- `paseo-factory` stays clean of vendored third-party skill Markdown while knowing the exact GitHub origin of every required skill (`CORE_SKILL_SOURCES`).
- New machines immediately guide the Owner with a 1-click Prerequisite Setup Gate before running Factory, and keep both `impeccable` and the 11 core skills versioned, symlinked, and updatable from the `Plugins` tab.
