## Context

As `paseo-factory` evolved through Store Release gating ([ADR 0071](0071-capability-gated-store-release-role-contracts-and-mcp-tools.md)), Factory Operator provisioning ([ADR 0073](0073-supervisor-factory-operator-tiered-setup-and-quick-start-onboarding.md)), and epistemic symmetry ([ADR 0069](0069-epistemic-symmetry-agent-ask-gate-decoupled-handoff-and-andon-cord.md)), five structural gaps remained across prompts, contracts, MCP schemas, and acceptance:

1. **Unstructured prompt growth & inline CLI noise:** Role contracts lacked a uniform front-loaded layout and static UTF-8 size budgets, embedded redundant Day-1 `factory` CLI flag tables alongside MCP instructions inside `renderRoleContract`, and hardcoded Vietnamese labels inside `SUPERVISOR_OUTCOME_BOUNDARY`'s 4-Line Ratification Card despite multi-language Owner conversations.
2. **Disposition bloat & unsafe mid-flight switching:** Every `Peer` received guidance or framing without strict per-disposition isolation (`engineer`, `scout`, `architect`, `reviewer`), risking instruction leakage (such as `--sha` commit rules on read-only Peers) or bloating shared Pi `APPEND_SYSTEM.md`. Meanwhile, `setContract` allowed changing an unaccepted Task's `disposition` in place (`resetPeer: false`) while a live `Peer` bound to the old disposition's system prompt and evidence contract remained active.
3. **Redundant legacy tools in `tools/list`:** `lead_retire_task` (both seats), `lead_close_task` on `Supervisor`, and `lead_create_worktree` / `lead_remove_worktree` on `Lead` remained advertised in `sharedRoles` / `tools/list` despite canonical `lead_close_task` (`Lead` only) and server-managed Task worktrees.
4. **Empty Brief bodies & brittle `git diff` Gate checks:** `missingBriefSections` verified heading presence (`1. Bounded Outcome`, `2. Contract Boundary & Regression Invariants`, `3. Excluded / Deferred`, `4. Verification`) without checking whether section bodies were empty, and `Lead`s could encode raw `git diff --exit-code` or `git diff --name-only` path-locking segments in `gate` instead of behavioral checks or `Contract.scope`.
5. **Advisory-only `Watch` alarms on `test-weakened` and `secret-leak`:** `Watch` logged `watch_written` probabilities without any acceptance friction, allowing high-confidence test weakening or secret leaks (`>= 0.5`) to land into `<project-root>` without explicit `Lead` / `Supervisor` / `Owner` acknowledgement.

## Decision

1. **5-Section Front-Loaded Role Contracts, UTF-8 Byte Budgets, 1-Line CLI Fallback Pointer, & English Ratification Card (R1; Q1, Q2, Q3, Q4):**
   - `renderRoleContract(role, options)` (`src/roles-contract.ts:200-325`) renders every role (`"supervisor"`, `"lead"`, `"agent"`) in exact 5-section front-loaded order:
     `## 1. Role & Core Goal` → `## 2. Front-Loaded Rules & Negative Constraints` → `## 3. Step-by-Step Workflow & Checkpoints` → `## 4. Anti-Hallucination & Uncertainty Protocol` → `## 5. Output Schema`.
   - All existing exports (`ProjectIdentity`, `StoreReleaseContractGate`, `SeatName`, `RoleName`, `RoleContractOptions`, `SeatBootstrapInput`, `SEAT_TITLES`, `ROLE_SKILL_INDEX`, `FOOTER_MARK`, `LEAD_WAVE_LAWS`, `LEAD_STORE_RELEASE_LAW`, `SUPERVISOR_FACTORY_OPERATOR_BOUNDARY`, `SUPERVISOR_OUTCOME_BOUNDARY`, `SUPERVISOR_STORE_RELEASE_BOUNDARY`, `SUPERVISOR_STORE_RELEASE_OFF_HINT`, `skillFooter`, `renderRoleContract`, `renderSeatBootstrapPrompt`, `renderRoleAppendSystem`, `buildRoleKickoffPrompt`, `renderPeerSkillScope`), `DESIGN_LINK_OWNERSHIP` (`design/open-design-link.json`), `FOOTER_MARK` (`"paseo-factory role skills:"`), capability-gated Store Release tiers (`"hidden"` | `"off-hint"` | `"full"`, `leadEnabled`), and topology-blind Peer framing (`ADR 0069`) are preserved.
   - Static CI tests (`test/role-budgets-and-disposition.test.ts:85-188`) enforce strict UTF-8 byte budgets (`1 KB = 1024 bytes`, `Buffer.byteLength(..., "utf8")`) across `minimal`, `realistic-open-design`, and `utf8-long-open-design` scenarios:
     - `Lead <= 12288` bytes (`12 KB`; both `leadEnabled: false` and `leadEnabled: true`).
     - `Supervisor <= 6144` bytes (`6 KB`; across `"hidden"`, `"off-hint"`, `"full"`, and `renderRoleAppendSystem("supervisor")`).
     - `Peer <= 4608` bytes (`4.5 KB`; for `renderRoleAppendSystem("agent")` and each disposition-scoped `renderRoleContract("agent", { disposition })`).
   - `renderRoleContract` replaces inline Day-1 `factory` CLI flag tables on `supervisor` and `lead` (`src/roles-contract.ts:232,263`) with the exact 1-line pointer: `"If paseo_factory MCP is absent, use the factory CLI fallback via factory --help."` Full Day-1 CLI command tables remain in `renderSeatCommandBlock` (`src/roles-contract.ts:134-194`) exclusively for `renderSeatBootstrapPrompt` (`src/roles-contract.ts:330-378`, dropping `lead_create_worktree`).
   - `SUPERVISOR_OUTCOME_BOUNDARY` (`src/roles-contract.ts:113`) normalizes the 4-Line Ratification Card labels to English (`1. Recurrence`, `2. Root Cause`, `3. Proposed Diff`, `4. Expected Effect`, `"matching Owner's active conversation language"`).

4. **Contract Gate Linter (R4; Q8, Q9):**
   - On `seat === "lead"` in `setContract` (`src/factory.ts:1665-1678`), `parseBriefHeadingLine` (`:146-199`), `analyzeBriefSections` (`:201-227`), and `emptyBriefSections` (`:240-247`) require non-empty body content under every one of the 4 Brief sections (`FactoryError("invalid-contract", "the 4-Part Brief has empty section(s): ...")`, allowing `"None"` for `3. Excluded / Deferred`).
   - On any non-empty `gate` (`src/factory.ts:1585-1593`), `findForbiddenGitDiffGateSegment` (`:474-480`, via `splitShellSegments` `:249-379` and `inspectSegmentForForbiddenGitDiff` `:381-471`) splits shell segments and unwraps common prefixes (`env`, `command`, `exec`, `time`, `nohup`, env assignments, global `git` options `-C`/`-c`/`--git-dir`/`--work-tree`) to reject raw `git diff --exit-code` or `git diff --name-only` path-locking segments with `FactoryError("invalid-contract", ...)` directing `Lead` to `scope` plus behavioral verification or repo check scripts (e.g. `npm run check`, `npm run sync:plugin-core:check`), without blocking `git status`, plain `git diff`, `git diff --stat`, quoted strings, or repo check scripts. (Adversarial `sh -c` / `bash -c` nested sub-invocations remain out of scope for this raw-segment linter.)

5. **Watch Soft-Block & `watchAck` Persistence (R5; Q10, Q11):**
   - Reopening [ADR 0005](0005-lead-duties-become-mechanisms.md) and [ADR 0006](0006-supervisor-and-lead-seats.md), `Watch` remains non-blocking on `Verdict` (`green`/`red`), but `resolveAcceptanceCheck` (`src/factory.ts:1452-1562`) soft-blocks acceptance across `lead_merge` / `lead_accept_task`, `supervisor_accept_task`, and `factory accept` (`plugin/bin/factory.mjs:118-123,751,770-788`) **only** when the Attempt carries a completed `watch_written` (`outcome === "written"`) with `test-weakened >= 0.5` OR `secret-leak >= 0.5` (`WATCH_CALLOUT_THRESHOLD = 0.5`, `WATCH_SOFT_BLOCK_QUESTIONS = ["test-weakened", "secret-leak"]` in `src/constants.ts:68-71`).
   - Acceptance **never** blocks when `watch` is off, absent, or `outcome === "failed"`.
   - When soft-blocked, `factory.accept` / `factory.validateAccept` throws `FactoryError("watch-soft-blocked", ...)` unless `acknowledgeWatch` (CLI `--ack-watch "<reason>"`) satisfies `isValidWatchAck` (`WATCH_ACK_MIN_CHARS = 10` non-whitespace characters, `src/constants.ts:74-79`). Supplying an invalid non-flagged `acknowledgeWatch` throws `FactoryError("invalid-watch-ack", ...)`.
   - `executeAcceptance` (`plugin/server/commands.ts:25,35`) validates via `factory.validateAccept(...)` before committing root memory (`commitSeatMemoryOnRoot`), and valid `acknowledgeWatch.trim()` persists as backward-compatible optional `watchAck?: string` on `AttemptAccepted` (`src/events.ts:443`, validated in `v2PayloadIsValid` at `src/ledger-validation.ts:433` while keeping v1 Ledger replay intact, and preserved across `pending-conflict` retries at `src/factory.ts:1531-1536`).
   - `acknowledgeWatch?: string` is exposed in `src/mcp/shared.ts:62-66,154-158` and `plugin/bin/bridge.mjs:3289-3304,3789-3804` on `supervisor_accept_task` and `lead_accept_task` / `lead_merge`.

6. **Scope Boundaries: Runtime Stuck Detection & External Knowledge Capabilities (R6; Q12):**
   - **Sole runtime stuck-detection mechanism:** [ADR 0069](0069-epistemic-symmetry-agent-ask-gate-decoupled-handoff-and-andon-cord.md)'s ~50% token **Andon Checkpoint** (`plugin/server/peer-handoff.ts:406-435`, firing at `turn_ended` once per Contract epoch when `reading.usedTokens >= Math.floor(mark * 0.5)` and zero `claim_reported` or `peer_asked` exist) remains the sole runtime stuck-detection mechanism; no timeline-parsing repetition heuristics are added.
   - **No internal vector DB:** No vector store or embedding index is built into `paseo-factory`; RAG and live web search remain Peer-owned external capabilities (via skills and Helper MCPs).

## Considered Options

- **Keep Day-1 CLI flag tables inside `renderRoleContract`:** Rejected — duplicates MCP usage instructions in every live session prompt and exceeds the tight `Supervisor <= 6144` B / `Lead <= 12288` B UTF-8 budgets; keeping Day-1 CLI tables in `renderSeatBootstrapPrompt` and using a 1-line `factory --help` pointer in `renderRoleContract` preserves CLI discoverability without runtime bloat.
- **Embed all 4 dispositions inside Pi's shared `APPEND_SYSTEM.md`:** Rejected — forces read-only `scout`/`architect`/`reviewer` sessions to carry `engineer` commit/test rules and inflates Peer base prompts beyond the `4608`-byte budget; keeping `APPEND_SYSTEM.md` disposition-neutral and resolving active `Contract.disposition` via `agent.open.before` and kickoff mirrors ADR 0071's Store Release pattern.
- **Allow silent in-place `disposition` switches without `resetPeer: true`:** Rejected — leaves a live Peer running under its prior disposition's `agent.open.before` system prompt and kickoff evidence instructions while `setContract` and `admitClaim` judge against the new disposition.
- **Hard-block `Verdict` or fail-closed on `Watch` errors:** Rejected — Watch is a probabilistic post-verdict LLM pass (`watch` lane) that must never turn a clean mechanical `GREEN` Gate into `RED` or wedge acceptance when Watch is disabled or `outcome === "failed"`; soft-blocking only `test-weakened >= 0.5` / `secret-leak >= 0.5` on `outcome === "written"` with explicit `watchAck` keeps mechanical Gates deterministic while forcing conscious review.
- **Add timeline-parsing repetition heuristics or an internal vector DB:** Rejected (Q12) — heuristic timeline scrapers risk false-positive mid-task interruptions alongside ADR 0069's 50% Andon Checkpoint, and an internal vector DB adds daemon complexity where external Helper MCPs and Peer skills already suffice.

## Consequences

- **Bounded, front-loaded prompts across providers:** `Supervisor` (`<= 6144` B), `Lead` (`<= 12288` B), and disposition-scoped `Peer` (`<= 4608` B) prompts put role, negative constraints, workflow, anti-hallucination rules, and output schema up front in English (with Owner-language adaptation on the 4-Line Ratification Card), verified statically in CI (`test/role-budgets-and-disposition.test.ts`).
- **Cleaner Contract & MCP surfaces:** `tools/list` drops legacy `lead_retire_task` / `lead_create_worktree` / `lead_remove_worktree` / Supervisor `lead_close_task` clutter without breaking existing callers, `setContract` catches empty Brief sections and raw `git diff --exit-code`/`--name-only` path locks before spawn, and live Peers cannot silently straddle incompatible dispositions.
- **Accountable Watch overrides with Ledger auditability:** High-confidence `test-weakened` or `secret-leak` Watch warnings cannot be bypassed silently at `lead_merge`, `supervisor_accept_task`, or `factory accept`, while valid `watchAck` justifications (`>= 10` non-whitespace chars) are recorded permanently on `attempt_accepted`.
- **Aligned domain model:** `CONTEXT.md` adds **Contract Gate linter**, **Watch soft-block**, and **Disposition-scoped role contract**, and updates **Contract**, **Gate**, **Accepted**, **Watch**, **Pi harness home**, and **Role-scoped MCP bridge** / **Live role contract** to match the implemented behavior.
