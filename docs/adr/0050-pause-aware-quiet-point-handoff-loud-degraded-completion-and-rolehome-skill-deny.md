# 0050 — Pause-Aware Quiet-Point and `Lead handoff`, Loud Degraded Completion, and `Zcode harness home` Skill-Override Deny

- **Date:** 2026-11-06
- **Status:** Accepted — Owner confirmed Q1–Q8 in `/grill-with-docs` ("toàn bộ theo bạn khuyến nghị, nhưng phải check kĩ lại trên các spec"); cross-check against ADR 0013/0018/0031/0044/0046/0047 found no violated spec and is recorded per-decision below.
- **Amends:** [ADR 0018](0018-airtight-lead-handoff-and-smart-default-fresh-eyes.md) (Fuse 2 becomes pause-aware and no longer completes silently — it pages `Supervisor` on every degraded completion) · [ADR 0044](0044-vertical-wave-slicing-contract-bounded-review-reply-first-handoff-heredoc-choke-and-worktree-process-reaping.md) (an interrupted extraction turn no longer completes the handoff with the prior text — it holds `handing_over` and re-sends) · [ADR 0031](0031-idempotent-claims-single-active-peer-handoff-and-role-scoped-mcp-isolation.md) (Decision 3's `interruptedPeerIds` hold becomes an accelerator over a durable ledger-first in-flight rule that survives daemon restarts and plugin updates) · [ADR 0046](0046-zcode-acp-harness-integration-clean-room-home-and-token-metering.md) (Decision 4 errata 3: the scoped `skills/` symlink directory cannot reach the user-scope roots `zcode.cjs` hardcodes; enforcement moves to the `Zcode harness home` config's native per-path skill override).

## Context

Three incidents on the live `goal-partner` Project (`goal-partner-f17f4d`, Paseo Desktop `~/.paseo`, plugin v0.1.0 then v0.2.1), all on 2026-11-06, each verified from `daemon.log`, `mailbox.jsonl`, the Project `ledger.jsonl`, and the Peer session database:

1. **Paused `Peer` became a quiet point (17:22 local).** The `Lead` crossed `128k`, `rotation_pending` held with "a Task Peer is still running" at 17:22:39. The Owner paused the freshly spawned `GP-T16b` Peer (`2c28ae28`) to power down the machine; the daemon received the cancel request and collected the runtime to idle. Thirteen seconds later (17:22:52) the quiet-point check found no `running`/`initializing` Peer — the open `spawn_dispatched` round's liveness arm dropped it — and the runtime began the handoff, archiving the outgoing `Lead` and spawning a successor at 17:23:44. The Task had no terminal event at all (ledger shows only `contract_set` + `spawn_dispatched`; the Peer session made exactly one tool call). v0.2.1's `interruptedPeerIds` hold targets exactly this case, but it is an in-process `Set`: the plugin update the Owner performed the same hour wiped it, and the Owner's stated reason for pausing — powering down — would wipe it on every reboot.
2. **Paused outgoing `Lead` mid-extraction (13:03–13:06 local).** The extraction turn hung (no `agent.turn.after`); the `180s` Dual-Fuse tripped and force-completed the handoff with the stale prior text, logging "handoff complete … rotation reset to normal" as if clean. Separately, the `settleTurnAndRotate` arm completes the handoff on **any** turn end while `handing_over` — including `outcome.kind === "canceled"` — so a user stop of the extraction turn rotates immediately.
3. **`Peer` loaded the Owner-only `/factory` skill (17:22:48 local).** The `GP-T16b` Peer's Turn-0 skill list carried `factory` twice (`~/.zcode/skills/factory` and `~/.agents/skills/factory`), and its first and only tool call was `Skill(factory)`, reading the entire Owner bootstrap content. Forensics: `zcode.cjs` hardcodes user-scope skill roots to `<homedir()>/.zcode/skills` and `<homedir()>/.agents/skills`; `ZCODE_STORAGE_DIR` redirects storage, session db, and plugin cache only — never those roots. The `<roleHome>/skills` symlink directory ADR 0046 Decision 4 provisions is therefore never the source of the session's skill list (verified: 56 skills from each real root, zero from the roleHome), and the plugin itself installs `/factory` into `~/.agents/skills` and `~/.claude/skills` at every boot (ADR 0013 Decision 3).

Protocol facts established during design (verified against `@getpaseo/protocol` and `zcode.cjs`): `AgentStatus` is exactly `error | initializing | idle | running | closed` — there is no `paused`; `turn_canceled.reason` is a free-form provider string with no vocabulary; no pause/suspend hook exists; cancel requests carry no suspend flag. ZCode has no skill env var, but its config layer carries `skill` (skillOverrides): `{"<absolute path>": {"enable": false}}`, honored at discovery time (a disabled skill is un-loadable, not merely unlisted) and matched by realpath, so one `~/.agents/skills/factory` key also disables the `~/.zcode/skills/factory` symlink copy.

## Decision

1. **Durable, ledger-first in-flight (the quiet point respects `Pause (user)`).** An unaccepted Task counts as having `Peer` work in flight — holding `rotation_pending` — whenever its spawn round is open in the current Contract epoch and its bound Peer is **live and not `error`**: `running`, `initializing`, `idle`, or `closed` alike, with no `Peer`-terminal folded status and no queued `from: "peer"` verdict/blocker mail. `idle`-because-paused is thereby indistinguishable-proof from `idle`-because-done at the only layer that survives restarts: the ledger plus the live daemon snapshot. The `interruptedPeerIds` turn-event marker remains purely as an accelerator; correctness never depends on it, so daemon restarts, plugin updates, and reboots cannot dissolve the hold. A `Peer` that is archived, in `error`, or absent from the daemon never holds (unchanged anti-deadlock law — the `Lead` owns re-dispatch).

2. **A canceled extraction turn holds `handing_over` and re-sends.** While `handing_over`, only two outcomes complete the handoff: a `completed` extraction turn yielding valid handoff text, or a legitimate fuse trip (Decision 3). A `failed`/`canceled` extraction turn (user stop, provider drop) keeps the lock, keeps all mail queued, and re-sends the fixed extraction prompt on the next pump once the outgoing `Lead` is seat-ready. At most **3 extraction sends per `handing_over` episode** (the original plus 2 re-sends) bound the loop; beyond the cap the runtime completes via the loud degraded path (Decision 4) so a repeatedly-stopped extraction cannot ping-pong forever.

3. **Pause-aware fuse.** The `180s` fuse no longer trips on elapsed time alone. It trips when the outgoing `Lead` is absent, is in `error`, when sending the extraction prompt throws, or when the elapsed timeout finds the Lead still `running` (a genuinely hung stream). When the timeout elapses over an alive `idle`/`closed` Lead — the paused-mid-extraction shape — the runtime re-sends instead (within Decision 2's cap). The fuse timer resets on each send. On boot after a real shutdown, the same rule applies: an alive Lead gets a fresh extraction (strictly better than completing from a stale prior); a dead one trips. The immediate-bypass arm of ADR 0018 Fuse 1 is unchanged.

4. **Loud degraded completion.** Every handoff completion that did not come from a `completed` extraction turn — fuse trip, send-failure bypass, exhausted re-send cap — appends exactly one `needs_human` mail to the `Supervisor` slice (stating the completion reason and that the successor's handoff layer is the preserved prior with the staleness notice), alongside the existing log line. This amends ADR 0018's "without paging `Supervisor`": the rotation itself stays fully autonomous (the mail is appended after completion and blocks nothing), but the machine no longer reports a degraded succession as a clean one.

5. **Auto-wake law unchanged.** `.send()` on an `idle`/`closed` seat still wakes it (ADR 0031); no fourth frozen state is introduced. `Pause (user)` is honored through the holds and the fuse policy, not through a persisted machine state.

6. **`Zcode harness home` skill-override deny for the Owner-only `factory` skill.** The roleHome provisioner writes the native per-path override — `skill: {"<userHome>/.agents/skills/factory": {"enable": false}}` — into the `config.json` it already generates for every role that excludes `factory` today (`agent`, `lead`, Scrum non-supervisor roles); the SLP `supervisor` (whole-dir Owner parity) is exempt. The realpath matching disables both real-root copies with one key. Global `/factory` installs (`~/.agents/skills`, `~/.claude/skills`) continue unchanged. The scoped symlink directory stays as belt-and-suspenders. **Live-verify gate before release:** spawn one real zcode-lane Peer, read its session database, assert the Turn-0 skill list contains no `factory` and that the Owner's own ZCode session still lists it.

7. **Deny scope is `factory` only.** The broad user-skill catalog visible to Peers is ADR 0047's by-design "Peer discovers `<available_skills>` natively"; a vetted allowlist would contradict it and is out of scope. `pi` keeps its settings filter; `opencode`/`claude` SLP Peers remain unfenced (no live lanes on the Owner's stack) — recorded as a known limitation.

## Consequences

- **Positive:** Pausing any seat to move, sleep, or shut down no longer mutates the succession plan; quiet points and fuses now distinguish dead/hung from alive-paused across restarts; every degraded succession is visible to the `Supervisor` and the Factory surface's needs-human affordances; the Owner-only orchestration skill is invisible and un-invocable to zcode-lane Peers without sacrificing `/factory` for the Owner.
- **Negative / accepted costs:** A paused-but-alive Peer holds `rotation_pending` for as long as the Owner keeps it paused (deliberate: pause freezes the machine; the Owner un-pausing, killing, or the `Lead` re-contracting releases it). The re-send cap means a thrice-stopped extraction completes loudly from the prior text. The skill deny depends on `zcode.cjs` continuing to honor the `skill` config key and to read the roleHome `config.json` (indirectly proven by the working `ROLE_SYSTEM.md` `instructions.userFile` wiring; the live-verify gate is the proof).
- **Errata recorded:** ADR 0046 Decision 4's symlink mechanism does not reach the roots `zcode.cjs` actually reads (errata 3 above). ADR 0044's "is interrupted → complete with prior + staleness notice" is superseded by Decision 2 for cancel-shaped interruptions; the staleness-notice machinery remains for genuine fuse trips.
