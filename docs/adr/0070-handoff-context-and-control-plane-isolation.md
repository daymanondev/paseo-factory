## Context

When `paseo-factory` upgrades live mid-project, new successor seats always load the fresh **Control Plane** (`Live role contract`, per-session `paseo_factory` MCP tool schemas, CLI shims, and `Seat kickoff packet` from the installed plugin). However, continuity files generated by outgoing seats (`lead-handoff.md`, `supervisor-handoff.md`, `peer-handoff-<task>.md`) and Lead's `notebook.md` travel across updates and rotations.

A combined primary-source literature review, codebase audit, and empirical inspection of `387` continuity files across `8` live Paseo Desktop Projects (`research/agent-handoff-context-and-tool-isolation.md`) uncovered five concrete continuity defects:

1. **Bottom-of-file truncation deletes the highest-leverage continuity sections:** Under tail-line `capHandoffText`, `48 / 358` extracted Peer handoffs hit the `12 KB` limit: `22 / 48` (`45.8%`) lost all of Section 4 (`Read-First Files for Successor`) and `14 / 48` (`29.2%`) truncated mid-Section 3 (`Remaining Requirements`). Similarly, `goal-partner-f17f4d/lead-handoff.md` (`8,177 B`) lost all of `# 5. Read-First Files` because `# 3. Key Technical Findings` filled the budget.
2. **Duplication & absolute `file://` URL bloat waste scarce budget:** `345 / 358` extracted Peer handoffs (`median 597 B`, `avg 714 B`, `p90 1,256 B`, `max 5,502 B`) copy `Worktree Git Status & Uncommitted Edits` even though `peer-handoff.ts:275` already prepends the authoritative `Machine-Verified Worktree Digest`. Worse, `59` Peer handoffs contain `832` absolute `file:///.../.paseo/.../worktrees/<task>/...` Markdown links costing up to `2.5–3.0 KB` per file.
3. **Missing `Dead Ends & Do-Not-Retry` and control-plane contamination:** Only `8 / 369` Peer (`2.2%`) and `0 / 7` Lead handoffs record failed hypotheses / dead ends to prevent successor thrashing. Meanwhile, `285 / 332` non-self-hosting Peer handoffs (`85.8%`), `3 / 3` Supervisor handoffs, `3 / 4` Lead handoffs, and `2 / 5` `notebook.md` files embed Factory MCP tool names, CLI flags (`57 / 343` citing retired `factory-claim` / `agent_escalate_blocker`), or obsolete plugin wiring quirks (e.g., `goal-partner-f17f4d/supervisor-handoff.md` spent `>550 B` / `~14%` on an old MCP wiring bug and phantom `lead_retire_task`, crowding `### Open questions`).
4. **Three structural bugs in `Substitute handover`:**
   - `lead-mailbox.ts:485, 538` wire `peerHandoff` and `supervisorHandoff` to `projectStreamOf`, whose legacy root-bridge branch (`peer-in-flight.ts:197`) leaks task-less `git_blocked` events from `source.factory` into every Project (`13 / 15` substitute files flooded with root `git refused` lines). Meanwhile `projectEventsOf` (`peer-in-flight.ts:212`) strips all task-less events, hiding Project-own `store_release_*` events.
   - `supervisor-handoff.ts:70` serializes raw timeline objects via `JSON.stringify(entry)`; `peer-handoff.ts:207` echoes the `# Peer handoff extraction` prompt as `"timeline"` (`7 / 11` Peer substitutes).
   - `peer-handoff.ts:209` passes Lead's `<projectStateDir>/notebook.md` into Peer `Substitute handover`, leaking `lead_merge` / root stash recipes into `2 / 11` Peer substitutes (`print-connect` `T-08a`, `T-08b`).
5. **Missing active `Store release` state in `Seat kickoff packet`:** While `src/preflight.ts` surfaces `Store release: mode=..., platforms=..., vault=...` and `- Ledger tasks: ...`, task-less `store_release_started` / `store_release_paused` state is omitted from `Seat kickoff packet`, risking lost `runId` / `Hole` context across mid-release handoffs.

## Decision

Include all P0, P1, and P2 improvements cleanly in one cohesive release (`Q1`) while keeping byte caps unchanged (`4 KB` Supervisor, `8 KB` Lead, `12 KB` Peer, `Q4`) and keeping scope strictly focused on continuity & kickoff isolation (no new runtime pause state machine, `Q5`):

1. **4-Layer Context Isolation & Semantic-Only Enforcement (`Q1`, `Q2`):**
   - Formalize the four runtime context layers across `CONTEXT.md` and extraction prompts:
     - **Layer 1 — Control Plane** (Role contracts, `paseo_factory` MCP tool schemas, CLI shims, SLP workflow laws): injected fresh at every successor boot (`Live role contract` / `APPEND_SYSTEM.md`), **never** written into handoffs or `notebook.md`.
     - **Layer 2 — Machine-Verified State** (`Seat kickoff packet`, `Machine-Verified Worktree Digest`, `Active Peer Roster`, `Ledger State Digest`, `Active store release` status): computed deterministically by the plugin from Git & Ledger, **never** duplicated by outgoing seats.
     - **Layer 3 — Curated Project Memory** (`AGENTS.md`, `CONTEXT.md`, Lead-only `notebook.md`): strictly **project-owned** facts, verification commands, and codebase recurrence rules.
     - **Layer 4 — Extracted Continuity** (`lead-handoff.md`, `supervisor-handoff.md`, `peer-handoff-<task>.md`): **purely project/task baton** — decisions taken, verified state, open questions, `Dead Ends & Do-Not-Retry`, and repo-relative file pointers.
   - Enforce control-plane isolation strictly through **semantic instructions in prompts** (never server-side regex scrubbing over tool/symbol names) so self-hosting development on `research-slp` (`paseo-factory` itself) can freely cite its own symbols such as `lead_*`, `agent_*`, or `supervisor_*`.

2. **Priority-First Extraction Schemas & Unified Peer Extraction Prompt (`Q1`, `Q4`, `Q10`):**
   - Put the highest-leverage continuation items first so any residual budget pressure trims only low-priority trailing summaries:
     - **Peer (`12 KB`, 4 sections — drop `Worktree Git Status` because `worktreeDigest` already supplies authoritative git state):**
       1. `1. Remaining Requirements & Failing Checks`
       2. `2. Dead Ends & Do-Not-Retry` (hypotheses/edits attempted + exact failure/error so the successor does not repeat them)
       3. `3. Read-First Files for Successor` (repo-relative `path:line`, up to 10 items)
       4. `4. Completed & Verified Slice`
     - **Lead (`8 KB`, 5 sections — promote `Open Questions & Owner Decisions` to #2 and require `Dead Ends` at #3):**
       1. `1. Current Wave & In-Flight State`
       2. `2. Open Questions & Owner Decisions`
       3. `3. Dead Ends & Failed Approaches`
       4. `4. Read-First Files` (repo-relative)
       5. `5. Key Technical Findings & Next Wave Plan`
     - **Supervisor (`4 KB`, 3 sections — promote `Open Questions` to #2):**
       1. `1. Owner Goals & Active Constraints`
       2. `2. Open Questions & Pending Confirmations`
       3. `3. Decisions Taken`
   - Unify the duplicated Peer context-mark (`plugin/server/peer-handoff.ts:426`) and Owner-initiated (`plugin/server/peer-handoff.ts:519`) extraction prompts into one shared helper `renderPeerHandoffExtractionPrompt`. All three seat prompts explicitly prohibit recording Factory MCP tool names, CLI flags, SLP rules, or runtime wiring quirks, and require repo-relative paths.

3. **Repo-Relative Path Normalization & Section-Aware Capping (`Q7`, `Q8`):**
   - Add pure helper `normalizeHandoffPaths(text, roots)` in `plugin/server/handoff-text.ts`: strip exact `file://` URLs and raw filesystem prefixes matching the task's `worktree` or `projectRoot` down to repo-relative paths (`[label](file://<root>/<rel>)` → `[label](<rel>)` and `file://<root>/<rel>` → `<rel>`), applied to extracted continuity before capping (safe for self-hosting because only the active root/worktree filesystem prefixes are rewritten).
   - Upgrade `capHandoffText(text, maxBytes)` in `plugin/server/handoff-text.ts` to parse top-level Markdown sections (`^#{1,2}\s+`):
     - When sections exist and total size exceeds `maxBytes`, trim **bottom-up from the lowest-priority trailing sections first**, while guaranteeing each section preserves a reserved floor (`min(sectionBytes, Math.min(512, Math.floor(maxBytes / (sections.length * 2))))`) so no section vanishes completely (protecting Priority-First anchors even if a single earlier section is oversized).
     - Fall back cleanly to existing line-boundary truncation for plain prose without `^#{1,2}\s+` headings.

4. **Clean `Substitute handover` & Project-Scoped Ledger Events (`Q3`, `Q9`):**
   - **Project-scoped Ledger stream (`plugin/server/peer-in-flight.ts`):** When `project !== source.factory`, `projectStreamOf` must no longer pull task-less events (`!evt.task`, notably root `git_blocked`) from the legacy root bridge `source.factory.ledger.events`; add/use a dedicated helper (`projectOwnAndTaskEventsOf`) that retains **all** events from the Project's own `project.ledger.events` (preserving task-less `store_release_*` and `release_*`) plus only matching-workspace legacy root tasks. Exclude task-less `git_blocked` lines from `Substitute handover` `Ledger digest`.
   - **Shared `extractCleanTimelineText(entries)` (`plugin/server/substitute-handover.ts`):** Extract only human-readable `user_message` and `assistant_message` text across Lead, Supervisor, and Peer substitutes, stripping plugin-sent extraction prompts (`# Peer handoff extraction`, `# Lead handoff extraction`, `Supervisor handoff:`) and eliminating raw `JSON.stringify(entry)` dumps (`supervisor-handoff.ts:70`).
   - **Omit `Project notebook` from Peer `Substitute handover` (`Q3`):** Make `notebook?: string` optional on `buildSubstituteHandover` and skip rendering `## Project notebook` when `undefined`. Peer substitute passes `notebook: undefined` (honoring `CONTEXT.md`'s Lead-only `Project notebook` boundary); Lead and Supervisor substitutes continue passing `readNotebook(...)`. Update `test/peer-handoff.test.ts:559` accordingly.

5. **Clean `Project notebook` Law (`Q1`, `Q6`):**
   - Tighten `LEAD_WAVE_LAWS` (`Project Notebook & Recurrence Guard`) in `src/roles-contract.ts` (and regenerate synced copies via `npm run sync:plugin-core && npm run generate:policies`) to state explicitly that `notebook.md` records **strictly project-owned** verification/run facts and codebase recurrence mechanisms — never Factory MCP tool names, CLI flags, or SLP workflow laws.

6. **Machine-Verified Active/Paused `Store release` Line in `Seat kickoff packet` (`Q11`):**
   - Fold `input.ledgerEvents` (`store_release_started`, `store_release_paused`, `store_release_completed`, `store_release_failed`) purely inside `src/preflight.ts` (`summarizeActiveStoreRelease`, without extra file I/O) for both `role === "lead"` and `role === "supervisor"`.
   - Whenever the latest event for a `runId` is `store_release_started` or `store_release_paused`, emit one concise line directly beneath `- Store release: mode=..., platforms=..., vault=...`:
     - Running: `- Active store release: runId=<id>, action=<action>, platforms=[...], status=running`
     - Paused (`Hole`): `- Active store release: runId=<id>, action=<action>, platforms=[...], status=paused, phase=<phase>, holeKind=<kind>[, guide=<guidePath>]`
   - Omit when idle or after `store_release_completed` / `store_release_failed`.

7. **Operational Mid-Run Upgrade Procedure (`Q5`, `Q12`):**
   - Document the existing zero-code upgrade procedure in `docs/runbooks/live-run.md` (`Gate queue Pause` → Paseo Desktop plugin update → Owner `Lead Handoff` / `Supervisor Handoff` → `Resume queue`) rather than introducing a new runtime pause state machine.

## Considered Options

- **Server-side regex scrubber stripping `lead_*` / `agent_*` / `supervisor_*` from handoffs:** Rejected (`Q2`) — breaks self-hosting when `paseo-factory` develops its own codebase (`research-slp`), where legitimate code references use those exact identifiers. Semantic prompt boundaries + structural `Substitute handover` fixes achieve clean isolation without false positives.
- **Increase handoff caps (`4 / 8 / 12 KB` → `8 / 16 / 24 KB`):** Rejected (`Q4`) — larger extracted prose bloats fresh successor context windows (context rot / lost-in-the-middle). Eliminating `worktreeDigest` duplication (`~600 B–5.5 KB`), normalizing `file://` URLs (`up to 3 KB`), dropping old wiring noise, and ordering Priority-First with section-aware capping fit higher-signal content comfortably inside `4 / 8 / 12 KB`.
- **Keep `Project notebook` in Peer `Substitute handover`:** Rejected (`Q3`) — leaks `lead_merge` and root-workspace workflows into `Task worktree` Peers, contradicting `CONTEXT.md` and polluting Layer 4 Peer context.
- **Read `<paseoHome>/release-lab/runs/*.json` in `buildSeatKickoffPacket`:** Rejected (`Q11`) — `src/preflight.ts` is pure-Node over `ledgerEvents`, and `src/events.ts` already persists `store_release_started`, `store_release_paused`, `store_release_completed`, and `store_release_failed` with all fields needed (`runId`, `action`, `platforms`, `phase`, `holeKind`, `guidePath`).
- **Build a new `upgrade-pause` daemon state machine:** Rejected (`Q5`) — the machine-wide `Gate queue Pause` + Owner `Lead Handoff` / `Supervisor Handoff` workflow already handles safe mid-run upgrades once continuity hygiene is fixed.

## Consequences

- Successor `Supervisor`, `Lead`, and `Peer` sessions receive lean, project-pure continuity documents topped by active blockers, `Open Questions`, `Dead Ends & Do-Not-Retry`, and repo-relative `Read-First Files`, cleanly separated from fresh plugin-injected Control Plane tools and machine-verified Kickoff / `worktreeDigest` state.
- Mid-run plugin updates on active Projects (e.g. `goal-partner`) require only pausing `Gate queue`, updating the plugin, and triggering `Lead Handoff` (and `Supervisor Handoff` when Supervisor prompts changed) — no stale tool schemas, phantom CLI names, or old wiring bugs survive across updates.
- `Substitute handover` files become concise, readable, free of legacy root `git_blocked` floods and raw JSON dumps, and enforce Lead-only `Project notebook` isolation for Peers.
- `CONTEXT.md` reflects the updated `Project notebook`, `Handoff`, and `Seat kickoff packet` contracts.
